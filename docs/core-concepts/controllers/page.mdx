# Controllers

Controllers in NestJS CRUD Automator are automatically generated based on your configuration. The `@ApiController` decorator transforms a simple controller class into a fully functional CRUD API with all necessary endpoints, DTOs, and Swagger documentation.

## Basic Controller Setup

The minimal controller configuration requires an entity, a route map, and a service property. `@ApiController` applies the Nest controller metadata itself, so use `path` for the controller path:

```typescript filename="user.controller.ts" copy
import { ApiController, EApiRouteType } from "@elsikora/nestjs-crud-automator";
import { UserEntity } from "./user.entity";
import { UserService } from "./user.service";

@ApiController<UserEntity>({
	entity: UserEntity,
	name: "Users",
	path: "users",
	routes: {
		[EApiRouteType.CREATE]: {},
		[EApiRouteType.GET]: {},
		[EApiRouteType.GET_LIST]: {},
		[EApiRouteType.PARTIAL_UPDATE]: {},
		[EApiRouteType.UPDATE]: {},
		[EApiRouteType.DELETE]: {},
	},
})
export class UserController {
	constructor(public service: UserService) {}
}
```

This generates the following endpoints:

- `POST /users` - Create a new user
- `GET /users/:id` - Get a user by ID
- `GET /users` - Get a page- or cursor-paginated list of users
- `PATCH /users/:id` - Partially update a user
- `PUT /users/:id` - Replace/update a user
- `DELETE /users/:id` - Delete a user

## Route Configuration

### Enabling and Disabling Routes

Control which routes are available:

```typescript
@ApiController<UserEntity>({
  entity: UserEntity,
  name: "Users",
  routes: {
    [EApiRouteType.CREATE]: {},
    [EApiRouteType.GET]: {},
    [EApiRouteType.GET_LIST]: {},
    // Omitted route keys are still generated with default configuration.
    // Disable routes explicitly with generation.isEnabled = false.
  },
})
```

Or explicitly disable a route:

```typescript
routes: {
  [EApiRouteType.DELETE]: {
    generation: {
      isEnabled: false,
    },
  },
}
```

Automator has no custom-only/default-disabled controller mode. To expose only custom routes, explicitly set `generation.isEnabled: false` for CREATE, GET, GET_LIST, UPDATE, PARTIAL_UPDATE, and DELETE. An omitted route key is still generated with default configuration.

### Swagger Documentation

Generated CRUD routes automatically receive Swagger summaries and descriptions based on the controller `name` option, or the entity name when `name` is omitted. Item routes use a singular resource name, while list routes use a plural one. For example, `name: "User"` produces text such as `Create \`User\``and`List \`Users\``.

Override the generated text per route when your public API needs domain-specific wording:

```typescript
routes: {
  [EApiRouteType.GET_LIST]: {
    documentation: {
      summary: "List public users",
      description: "Returns users visible to the current caller",
      operationId: "listPublicUsers",
    },
  },
}
```

Omitted `summary` and `description` fields fall back to the generated defaults. Omitted `operationId` uses Nest Swagger's default operation ID.

Each generated route also declares exactly the error statuses it can return with its configuration, such as `401` only with a guard and `403` only with a guard or a securable controller with `authorization`. Declare application-owned statuses, such as a global `ThrottlerGuard` `429`, with `documentation.response.statuses`. See [Error Responses in OpenAPI](/docs/nestjs-crud-automator/guides/error-handling#error-responses-in-openapi).

### Custom Path

Override the default controller path:

```typescript
@ApiController<UserEntity>({
  entity: UserEntity,
  path: "api/v1/users", // Custom path
  name: "Users",
  routes: { /* ... */ },
})
```

### Row Paths And Composite Keys

A generated GET, PATCH, PUT and DELETE takes every primary key column as a path parameter, in declaration order. A single-column key stays `/:id`. An entity with the key `tenantId, id` generates `GET /orders/:tenantId/:id`, and a request with part of the key does not match the route.

Use `rowPath` on the controller to choose the columns and their order:

```typescript filename="order.controller.ts" copy
@ApiController<OrderEntity>({
	entity: OrderEntity,
	path: "orders",
	rowPath: { fields: ["id", "tenantId"] },
	routes: {},
})
export class OrderController {
	constructor(public service: OrderService) {}
}
```

This generates `GET /orders/:id/:tenantId`. An empty list, an unknown column, a column outside the key, a repeated column, or a column `pathScope` already binds fails at startup.

A date and time key column in the path of a composite key must be a `timestamptz` with precision 0 to 3, or a `datetime` with no precision or precision 0 to 3 (SQLite, MySQL, MariaDB), because a JavaScript `Date` cannot reproduce a finer value. A MySQL or MariaDB `datetime(6)` therefore fails at startup. Any other column fails at startup, and the value in the path must be the canonical UTC form such as `2026-01-15T05:06:07.123Z`; any other form answers `400`.

`rowPath` may leave key columns out, for example `rowPath: { fields: ["id"] }` on a partitioned ledger keyed by `id, createdAt`, where `createdAt` holds microseconds. The path is then a promise that it names one row:

- The route first reads the key of the matching rows with `take: 2`, under the current HOOKS or IAM scope, through the transaction of the route. It adds this one `SELECT` only on a route with a reduced key.
- More than one match answers `500` before any change. The value of a reduced column is not checked by the path, so a key that repeats is a deployment fault, not a client error. Rows are counted as the database stores them, so two rows whose left-out instants differ only below a millisecond count as two.
- A write answers `500` before any change when a left-out date and time key column holds a finer value than a millisecond: the write could not address that row. GET still reads it.
- After CREATE, the route reloads the row it inserted by its full key. A key column whose stored value a `Date` cannot reproduce is left out of that reload, and the other key columns must then name one row: a sibling row answers `500`, after the new row is stored.

Limits of a reduced key:

- Without a transaction (`SUPPORTS` outside one, or `NONE`), the check and the write are two statements, so a concurrent writer can act between them. Use `REQUIRED` when that matters.
- The lookup filters only on the columns in the path, so on a partitioned table it visits every partition unless an index on those columns serves it.
- A function subscriber that sets `withDeleted` does not reach the lookup, so a soft-deleted row answers `404` on a route with a reduced key.
- An IAM `resourcePath` placeholder such as `{createdAt}` renders `*` on a route whose path leaves that column out.

A custom route with two path segments on a controller with a two-column default row path can be captured by the generated route, for example `orders/export/daily` by `orders/:tenantId/:id`. Declare a longer or different custom path, or set `rowPath`.

### Binding Controller Path Parameters

Use `pathScope` when the controller path contains an owner or parent identity. It binds each path parameter to an entity field on **every** generated route:

```typescript filename="provider-game.controller.ts" copy
import { ApiController, EApiControllerGetListQueryUnlistedFields, EApiControllerRequestTarget, EApiRouteType, EFilterOrderDirection } from "@elsikora/nestjs-crud-automator";

@ApiController<GameEntity>({
	entity: GameEntity,
	name: "ProviderGames",
	path: "providers/:providerKey/games",
	pathScope: { parameters: [{ parameter: "providerKey", field: "providerId" }] },
	routes: {
		[EApiRouteType.GET]: {
			identity: { parameter: "gameId" },
		},
		[EApiRouteType.GET_LIST]: {
			request: {
				[EApiControllerRequestTarget.QUERY]: {
					order: {
						defaultOrder: [
							{ direction: EFilterOrderDirection.DESC, field: "priority" },
							{ direction: EFilterOrderDirection.ASC, field: "id" },
						],
						fields: { priority: { isEnabled: true } },
						tieBreakers: [{ direction: EFilterOrderDirection.ASC, field: "id" }],
						unlistedFields: EApiControllerGetListQueryUnlistedFields.REJECT,
					},
				},
			},
		},
	},
})
export class ProviderGameController {
	constructor(public service: GameService) {}
}
```

`providerKey` is the external path name; `providerId` is the described direct scalar entity field used in the database predicate.

| Route              | Effect of `pathScope`                                                                                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET, GET_LIST      | The row or list is limited to the bound value.                                                                                                                               |
| PATCH, PUT, DELETE | Only a row with the bound value is written. A row of another parent answers `404` and stays unchanged. A body naming another bound value or another key value answers `400`. |
| CREATE             | The bound value comes from the path. A body naming another value answers `400` without echoing it, including through a relation key such as `owner` over a bound `ownerId`.  |

Bound fields leave the generated BODY DTO, so a `ValidationPipe` with `forbidNonWhitelisted` refuses them in a body. A bound key column also leaves the row path: with the key `tenantId, id` and `tenantId` bound, the row path is `/:id`.

The route compares the body with the path itself, whatever pipe runs. It reads the body both as the client sent it and as the route will write it, so a pipe that strips or transforms a property changes nothing:

- A bound field in the body, directly or through the relation it joins, must equal the path value on CREATE, PATCH and PUT.
- A key column in a PATCH or PUT body must equal its row parameter. A key column the path leaves out, through `rowPath`, cannot appear in the body at all.
- Only the string the path would carry names a value: a date and time in its canonical UTC millisecond form, such as `2026-01-01T00:00:00.002Z`, and anything else as the path spells it. A number, an epoch, another offset or extra fraction digits, an array, an object or `null` answers `400`.
- A date and time key column in a CREATE body takes the same canonical UTC millisecond string, with or without a host pipe. A number or any other form answers `400` before the insert.

A refusal answers `400` with message `PARAMETERS_NOT_VALID` and `details: { propertyName, reason }` before any change. It names the property and the rule, not the value.

The route writes a copy of the body. A field the path addresses leaves the copy, because the path already names it and a key the save read from the body would insert another row. The request body, and the `body` route subscribers see, stay as the client sent them.

A relation that joins a bound field leaves the copy too. When it joins other columns as well, such as a `parent` over `(tenantId, parentId)` with `tenantId` bound, the route checks the bound column inside the relation object and writes the relation's other columns, here `parentId`, as the entity's own. `{ "parent": { "id": "P2", "tenantId": "T1" } }` under `/tenant/T1/child` stores `parentId` `P2`. The other columns must be declared on the entity and named in the relation object, and a body that also names one of them must name the same value; otherwise the route answers `400`, because the bound column cannot be told apart from the rest.

The response of CREATE reloads the row by every key column. A date and time key that the inserted row carries as a string, as the body spelled it, is converted to a `Date` first, so the reload compares an instant with the stored value.

A `request[PARAMETERS]` transformer runs before the binding is read, so a transformer on a bound field overrides the value of the path for every query and write of that request.

Every path parameter must be bound as soon as one generated route is enabled, and required: an unbound, wildcard or optional parameter fails at startup. Bind it or disable the route. A controller with all six generated routes disabled, which serves only custom routes, starts with any path it declares. A declared `pathScope` or `rowPath` is still validated. Duplicate parameters, duplicate fields, unknown path names, relations and objects fail at startup, as does a path parameter named like a row parameter, and binding every key column on a controller with a row route enabled.

`identity` renames the one row parameter that is left and stays GET-only: `gameId` is only the external name, and Automator still queries the actual primary column. With more than one row parameter it fails at startup. GET_LIST rejects identity because it has no item segment. Identity aliases must be safe simple identifiers such as `gameId`.

The framework generates a route-local PARAMETERS DTO, named `<Prefix><Route>ParametersDTO`, from the metadata of the bound and row fields under their external parameter names, and emits matching Swagger metadata. Do not combine `pathScope`, `rowPath` or `identity` with a manual `dto[EApiDtoType.PARAMETERS]`; use `autoDto[PARAMETERS]` only for validators on the generated DTO. `request[PARAMETERS]` on CREATE and GET_LIST requires `pathScope`, because those routes otherwise take no path parameters.

A manual PARAMETERS DTO on a default composite key is yours to keep complete: a value it does not deliver answers `400` with `<parameter> should not be null or undefined`.

Row parameters, the path binding, and HOOKS/IAM scope combine as a logical AND, and so do GET_LIST query predicates. A later layer cannot overwrite an earlier condition: a conflict matches nothing.

Service methods called directly take whatever criteria you pass. `service.update`, `service.delete` and `service.get` do not apply `rowPath` or `pathScope`, so pass the complete key.

The list example also provides deterministic page/limit ordering. Server-only `defaultOrder` is used when the client sends no order pair, while `tieBreakers` are appended after either the defaults or the client's selected order. Direct scalar UUID fields such as `id` may be used here without being listed in the client order allowlist.

GET_LIST defaults to PAGE mode. Add `pagination: { mode: EApiControllerGetListQueryPaginationMode.CURSOR }` beside `filter` and `order` to generate required `limit`, optional mutually exclusive `after`/`before`, and the flat `{ items, nextCursor, previousCursor }` response. CURSOR requires the complete primary key, single or composite, as the final explicit tie-breakers and non-null direct-scalar metadata for every possible order field. See [Pagination](/docs/nestjs-crud-automator/guides/pagination) for the full contract.

## Authentication and Authorization

Add authentication guards to specific routes:

```typescript filename="user.controller.ts" copy
import { JwtAuthGuard } from "../auth/guards/jwt-auth.guard";
import { EApiAuthenticationType } from "@elsikora/nestjs-crud-automator";

@ApiController<UserEntity>({
  entity: UserEntity,
  name: "Users",
  routes: {
    [EApiRouteType.CREATE]: {
      security: {
        authentication: {
          type: EApiAuthenticationType.USER,
          guard: JwtAuthGuard,
          securityRequirements: [
            {
              bearerStrategies: ["jwt"],
            },
          ],
        },
      },
    },
    [EApiRouteType.UPDATE]: {
      security: {
        authentication: {
          type: EApiAuthenticationType.USER,
          guard: JwtAuthGuard,
          securityRequirements: [
            {
              bearerStrategies: ["jwt"],
            },
          ],
        },
      },
    },
    [EApiRouteType.DELETE]: {
      security: {
        authentication: {
          type: EApiAuthenticationType.USER,
          guard: JwtAuthGuard,
          securityRequirements: [
            {
              bearerStrategies: ["jwt"],
            },
          ],
        },
      },
    },
    [EApiRouteType.GET]: {}, // Public
    [EApiRouteType.GET_LIST]: {}, // Public
  },
})
```

Route `execution.guards` runs before `authentication.guard` by default. Use a staged guard when it needs the authenticated principal:

```typescript
[EApiRouteType.CREATE]: {
  execution: {
    guards: [{ guard: UserThrottlerGuard, stage: EApiRouteGuardStage.AFTER_AUTHENTICATION }],
  },
  security: {
    authentication: {
      type: EApiAuthenticationType.USER,
      guard: JwtAuthGuard,
    },
  },
},
```

`UserThrottlerGuard` is a `ThrottlerGuard` subclass whose `getTracker` returns `request.user.id`; the stock tracker uses `request.ip`. The chain is `BEFORE_AUTHENTICATION` guards → `authentication.guard` → `AFTER_AUTHENTICATION` guards → `ApiAuthorizationGuard` → `AFTER_AUTHORIZATION` guards. Global `APP_GUARD` guards run before it. See [Guard stages](/docs/nestjs-crud-automator/api-reference/decorators/api-method/api-method#guard-stages).

## Request Transformers

Automatically transform request data before processing:

```typescript
import {
  EApiControllerRequestTarget,
  EApiControllerRequestTransformerType,
  EApiControllerResponseTarget,
  TRANSFORMER_VALUE_DTO_CONSTANT
} from "@elsikora/nestjs-crud-automator";

@ApiController<PostEntity>({
  entity: PostEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      request: {
        [EApiControllerRequestTarget.BODY]: {
          transformers: [
            {
              key: "author",
              type: EApiControllerRequestTransformerType.DYNAMIC,
              value: TRANSFORMER_VALUE_DTO_CONSTANT.AUTHORIZED_ENTITY,
              shouldSetValueEvenIfMissing: true,
            },
            {
              key: "createdAt",
              type: EApiControllerRequestTransformerType.DYNAMIC,
              value: TRANSFORMER_VALUE_DTO_CONSTANT.REQUEST_TIMESTAMP,
            },
          ],
        },
      },
    },
  },
})
```

Transformer types:

- `STATIC` - Set a constant value
- `DYNAMIC` - Extract value from request context (authenticated user, headers, IP)

## Response Transformers

Transform response data before returning to client:

```typescript
routes: {
  [EApiRouteType.GET]: {
    response: {
      [EApiControllerResponseTarget.RESPONSE]: {
        transformers: [
          {
            key: "responseSource",
            type: EApiControllerRequestTransformerType.STATIC,
            value: "api",
            shouldSetValueEvenIfMissing: true,
          },
        ],
      },
    },
  },
}
```

## Loading Relations

Configure relation loading:

```typescript
import { EApiControllerRelationReferenceShape } from "@elsikora/nestjs-crud-automator";

@ApiController<PostEntity>({
	entity: PostEntity,
	routes: {
		[EApiRouteType.CREATE]: {
			relations: {
				request: {
					reference: { shape: EApiControllerRelationReferenceShape.SCALAR },
					load: {
						include: { author: true },
					},
				},
				response: {
					reference: { shape: EApiControllerRelationReferenceShape.OBJECT, key: "id" },
					load: {
						include: { author: true, comments: true },
						relationLoadStrategy: "query",
					},
				},
			},
		},
	},
})
export class PostController {
	constructor(
		public service: PostService,
		// Inject related services for loading
		public authorService: UserService,
	) {}
}
```

Relation loading uses:

- `load.include` - Select direct relations and nested TypeORM relation preloads.
- `load.relationLoadStrategy` - Optional TypeORM `"join"` or `"query"` strategy.
- `relations.request.load.services` - Optional override for direct relation service property names; omitted keys use `${relationName}Service`.
- Request relation `load` hydrates only direct included relation keys present in the request body. Omitted, `undefined`, and `null` body relation values are left unchanged.
- Nested request include objects are passed to the direct relation service as TypeORM `relations`; they do not recursively hydrate nested request references.
- Custom route request relation loading uses the same relation config, but it only hydrates the method `@Body()` argument.

## Custom DTOs

Replace auto-generated DTOs with custom ones:

```typescript
import { ApiController, EApiDtoType, EApiRouteType } from "@elsikora/nestjs-crud-automator";
import { CreateUserDto } from "./dto/create-user.dto";
import { UpdateUserDto } from "./dto/update-user.dto";
import { UserResponseDto } from "./dto/user-response.dto";

@ApiController<UserEntity>({
  entity: UserEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      dto: {
        [EApiDtoType.BODY]: CreateUserDto,
        [EApiDtoType.RESPONSE]: UserResponseDto,
      },
    },
    [EApiRouteType.UPDATE]: {
      dto: {
        [EApiDtoType.BODY]: UpdateUserDto,
        [EApiDtoType.RESPONSE]: UserResponseDto,
      },
    },
  },
})
```

## Auto DTO Configuration

Customize auto-generated DTOs:

```typescript
import {
  AllOrNoneOfListedPropertiesValidator
} from "@elsikora/nestjs-crud-automator";

@ApiController<UserEntity>({
  entity: UserEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      autoDto: {
        [EApiDtoType.BODY]: {
          validators: [
            {
              constraintClass: AllOrNoneOfListedPropertiesValidator,
              options: ["firstName", "lastName"],
            },
          ],
        },
      },
    },
  },
})
```

## Request Validation

Add custom request validators:

```typescript
import { BadRequestException } from "@nestjs/common";
import { EApiControllerRequestTarget, EErrorStringAction, type IApiRequestValidator } from "@elsikora/nestjs-crud-automator";

const createValidators: Array<IApiRequestValidator<UserEntity>> = [
  {
    errorType: EErrorStringAction.BAD_REQUEST,
    exception: BadRequestException,
    validationFunction: (payload: Partial<UserEntity>) => Boolean(payload.email),
  },
];

routes: {
  [EApiRouteType.CREATE]: {
    request: {
      [EApiControllerRequestTarget.BODY]: {
        validators: createValidators,
      },
    },
  },
}
```

## Route Documentation

Generated CRUD routes use the package defaults unless you set `documentation` on the route. Use `documentation` for operation text and `operationId`; reserve `generation.decorators` for additive decorators such as interceptors, guards, or non-operation Swagger metadata:

```typescript
routes: {
  [EApiRouteType.CREATE]: {
    documentation: {
      description: "Creates a new user with the provided data",
      operationId: "createUser",
      summary: "Create a new user",
    },
  },
}
```

## Custom Decorators

Add additional decorators to routes:

```typescript
import { UseInterceptors } from "@nestjs/common";
import { FileInterceptor } from "@nestjs/platform-express";

routes: {
  [EApiRouteType.CREATE]: {
    generation: {
      decorators: [
        UseInterceptors(FileInterceptor('avatar')),
      ],
    },
  },
}
```

## Observable Controllers

Enable subscriber hooks by marking the controller as observable:

```typescript
import { ApiController, ApiControllerObservable } from "@elsikora/nestjs-crud-automator";

@ApiController({
	entity: PostEntity,
	path: "posts",
	routes: {},
})
@ApiControllerObservable()
export class PostController {
	constructor(public service: PostService) {}
}
```

## Generated Method Names

Each generated route is a method on the controller class, named after its `EApiRouteType` value: `create`, `delete`, `get`, `getList`, `partialUpdate` and `update`. `TApiControllerMethodName`, `TApiControllerMethodNameMap` and `TApiControllerTargetMethod` give exactly these names, and `ApiControllerGetMethodName` returns them at runtime.

A decorator cannot change a class's type, so these methods are not on the type of a class decorated with `@ApiController`: `new UserController(service).create` does not compile. Type such a value with a type assertion to `InstanceType<TApiControllerTargetMethod<UserEntity>>`, or merge the methods into the class with an `interface UserController extends TApiControllerMethodMap<UserEntity>` declaration.

`TApiControllerTargetMethod` and `TApiControllerMethodMap` always list all six methods, because a type cannot see the `routes` of a controller. So with `[EApiRouteType.DELETE]: { generation: { isEnabled: false } }`, `controller.delete(...)` compiles and throws `TypeError: controller.delete is not a function`. Remove a disabled route from the type:

```typescript copy
type TUserController = Omit<InstanceType<TApiControllerTargetMethod<UserEntity>>, "delete">;
```

These types also give `getList` the arguments `(query, headers, ip)`. On a controller with `pathScope`, the generated method takes `(parameters, query, headers, ip)`, and `create` takes `(parameters, body, headers, ip)`, so a direct call with the typed arguments answers `400` with `<parameter> should not be null or undefined`. HTTP requests to the route are not affected. Whether a controller has a `pathScope` is not visible to the types either, so call these methods through a type of your own.

## Migration Notes

- **5.0:** The route `read` key is removed. Replace `read: { scope: { parameters } }` on GET and GET_LIST with `pathScope: { parameters }` on the controller, which binds the parameters on every generated route. Every controller path parameter must now be bound, or the routes under it disabled. Generated row routes address every primary key column. See [Migrating To 5.0](/docs/nestjs-crud-automator/guides/migrating-to-5-0#generated-row-routes-and-path-parameters).
- **5.0:** `TApiControllerMethodName`, `TApiControllerMethodNameMap` and `TApiControllerTargetMethod` give the runtime names. Before 5.0.0 they gave `${string}Create` and the like, so `controller.create` did not compile while `controller.xCreate` did, although no such method exists. Call the methods by their runtime names. A cast on a value already typed with these types can go, but a decorated class still needs a type assertion or declaration merging.
- **5.0:** An instance of `TApiControllerTargetMethod` now has all six methods as required properties, including the methods of disabled routes, so a test stub of that type has to implement them. `ApiControllerFactory` takes the undecorated class as a `TApiControllerConstructor`, and its protected `target` has that type too.
