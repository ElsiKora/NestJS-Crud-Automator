# Controllers

Controllers in NestJS CRUD Automator are automatically generated based on your configuration. The `@ApiController` decorator transforms a simple controller class into a fully functional CRUD API with all necessary endpoints, DTOs, and Swagger documentation.

## Basic Controller Setup

The minimal controller configuration requires an entity, a route map, and a service property. `@ApiController` applies the Nest controller metadata itself, so use `path` for the controller path:

```typescript filename="user.controller.ts" copy
import { ApiController, EApiRouteType } from "@elsikora/nestjs-crud-automator";
import { UserEntity } from "./user.entity";
import { UserService } from "./user.service";

@ApiController<UserEntity>({
	entity: UserEntity,
	name: "Users",
	path: "users",
	routes: {
		[EApiRouteType.CREATE]: {},
		[EApiRouteType.GET]: {},
		[EApiRouteType.GET_LIST]: {},
		[EApiRouteType.PARTIAL_UPDATE]: {},
		[EApiRouteType.UPDATE]: {},
		[EApiRouteType.DELETE]: {},
	},
})
export class UserController {
	constructor(public service: UserService) {}
}
```

This generates the following endpoints:

- `POST /users` - Create a new user
- `GET /users/:id` - Get a user by ID
- `GET /users` - Get a page- or cursor-paginated list of users
- `PATCH /users/:id` - Partially update a user
- `PUT /users/:id` - Replace/update a user
- `DELETE /users/:id` - Delete a user

## Route Configuration

### Enabling and Disabling Routes

Control which routes are available:

```typescript
@ApiController<UserEntity>({
  entity: UserEntity,
  name: "Users",
  routes: {
    [EApiRouteType.CREATE]: {},
    [EApiRouteType.GET]: {},
    [EApiRouteType.GET_LIST]: {},
    // Omitted route keys are still generated with default configuration.
    // Disable routes explicitly with generation.isEnabled = false.
  },
})
```

Or explicitly disable a route:

```typescript
routes: {
  [EApiRouteType.DELETE]: {
    generation: {
      isEnabled: false,
    },
  },
}
```

Automator has no custom-only/default-disabled controller mode. To expose only custom routes, explicitly set `generation.isEnabled: false` for CREATE, GET, GET_LIST, UPDATE, PARTIAL_UPDATE, and DELETE. An omitted route key is still generated with default configuration.

### Swagger Documentation

Generated CRUD routes automatically receive Swagger summaries and descriptions based on the controller `name` option, or the entity name when `name` is omitted. Item routes use a singular resource name, while list routes use a plural one. For example, `name: "User"` produces text such as `Create \`User\``and`List \`Users\``.

Override the generated text per route when your public API needs domain-specific wording:

```typescript
routes: {
  [EApiRouteType.GET_LIST]: {
    documentation: {
      summary: "List public users",
      description: "Returns users visible to the current caller",
      operationId: "listPublicUsers",
    },
  },
}
```

Omitted `summary` and `description` fields fall back to the generated defaults. Omitted `operationId` uses Nest Swagger's default operation ID.

### Custom Path

Override the default controller path:

```typescript
@ApiController<UserEntity>({
  entity: UserEntity,
  path: "api/v1/users", // Custom path
  name: "Users",
  routes: { /* ... */ },
})
```

### Nested Generated Read Scope

Use `read.scope.parameters` when the controller path contains an owner or parent identity and generated GET/GET_LIST rows must belong to it:

```typescript filename="provider-game.controller.ts" copy
import { ApiController, EApiControllerGetListQueryUnlistedFields, EApiControllerRequestTarget, EApiRouteType, EFilterOrderDirection } from "@elsikora/nestjs-crud-automator";

@ApiController<GameEntity>({
	entity: GameEntity,
	name: "ProviderGames",
	path: "providers/:providerKey/games",
	routes: {
		[EApiRouteType.GET]: {
			identity: { parameter: "gameId" },
			read: {
				scope: {
					parameters: [{ parameter: "providerKey", field: "providerId" }],
				},
			},
		},
		[EApiRouteType.GET_LIST]: {
			read: {
				scope: {
					parameters: [{ parameter: "providerKey", field: "providerId" }],
				},
			},
			request: {
				[EApiControllerRequestTarget.QUERY]: {
					order: {
						defaultOrder: [
							{ direction: EFilterOrderDirection.DESC, field: "priority" },
							{ direction: EFilterOrderDirection.ASC, field: "id" },
						],
						fields: { priority: { isEnabled: true } },
						tieBreakers: [{ direction: EFilterOrderDirection.ASC, field: "id" }],
						unlistedFields: EApiControllerGetListQueryUnlistedFields.REJECT,
					},
				},
			},
		},
	},
})
export class ProviderGameController {
	constructor(public service: GameService) {}
}
```

This generates `GET /providers/:providerKey/games/:gameId` and `GET /providers/:providerKey/games`. `providerKey` is the external owner-path name; `providerId` is the described direct scalar entity field used in the database predicate. `gameId` is only the external GET identity name: Automator still queries the entity's actual primary column. Omit `identity` to retain the ordinary primary-column parameter name, or use identity without scope when the controller path has no inherited parameters. GET_LIST rejects identity because it has no primary-identity path segment. Identity aliases must be safe simple identifiers such as `gameId`; whitespace, slashes, punctuation, control characters, unsafe object-property names, and inherited-path collisions fail at bootstrap.

Every required scalar path parameter inherited from `path` must be mapped exactly once; wildcard and optional/grouped dynamic parameters fail at bootstrap. Duplicate/missing parameters, duplicate fields, unknown path names, relations, and objects also fail at bootstrap. On GET, the inherited path must not reuse the effective generated identity parameter name.

The framework generates a route-local PARAMETERS DTO from primary and mapped field metadata under their external parameter names and emits matching Swagger metadata. Do not combine configured read identity or scope with a manual `dto[EApiDtoType.PARAMETERS]`; use `autoDto[PARAMETERS]` only for validators on the generated DTO.

GET combines primary identity, path scope, and then HOOKS/IAM scope. GET_LIST combines query predicates, path scope, and then HOOKS/IAM scope. Every layer is a logical AND, including when the same field appears more than once; a later layer cannot overwrite an earlier condition.

The list example also provides deterministic page/limit ordering. Server-only `defaultOrder` is used when the client sends no order pair, while `tieBreakers` are appended after either the defaults or the client's selected order. Direct scalar UUID fields such as `id` may be used here even when they are absent from the client order allowlist.

GET_LIST defaults to PAGE mode. Add `pagination: { mode: EApiControllerGetListQueryPaginationMode.CURSOR }` beside `filter` and `order` to generate required `limit`, optional mutually exclusive `after`/`before`, and the flat `{ items, nextCursor, previousCursor }` response. CURSOR requires one primary column as the only final explicit tie-breaker and non-null direct-scalar metadata for every possible order field. See [Pagination](/docs/nestjs-crud-automator/guides/pagination) for the full contract.

## Authentication and Authorization

Add authentication guards to specific routes:

```typescript filename="user.controller.ts" copy
import { JwtAuthGuard } from "../auth/guards/jwt-auth.guard";
import { EApiAuthenticationType } from "@elsikora/nestjs-crud-automator";

@ApiController<UserEntity>({
  entity: UserEntity,
  name: "Users",
  routes: {
    [EApiRouteType.CREATE]: {
      security: {
        authentication: {
          type: EApiAuthenticationType.USER,
          guard: JwtAuthGuard,
          securityRequirements: [
            {
              bearerStrategies: ["jwt"],
            },
          ],
        },
      },
    },
    [EApiRouteType.UPDATE]: {
      security: {
        authentication: {
          type: EApiAuthenticationType.USER,
          guard: JwtAuthGuard,
          securityRequirements: [
            {
              bearerStrategies: ["jwt"],
            },
          ],
        },
      },
    },
    [EApiRouteType.DELETE]: {
      security: {
        authentication: {
          type: EApiAuthenticationType.USER,
          guard: JwtAuthGuard,
          securityRequirements: [
            {
              bearerStrategies: ["jwt"],
            },
          ],
        },
      },
    },
    [EApiRouteType.GET]: {}, // Public
    [EApiRouteType.GET_LIST]: {}, // Public
  },
})
```

## Request Transformers

Automatically transform request data before processing:

```typescript
import {
  EApiControllerRequestTarget,
  EApiControllerRequestTransformerType,
  EApiControllerResponseTarget,
  TRANSFORMER_VALUE_DTO_CONSTANT
} from "@elsikora/nestjs-crud-automator";

@ApiController<PostEntity>({
  entity: PostEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      request: {
        [EApiControllerRequestTarget.BODY]: {
          transformers: [
            {
              key: "author",
              type: EApiControllerRequestTransformerType.DYNAMIC,
              value: TRANSFORMER_VALUE_DTO_CONSTANT.AUTHORIZED_ENTITY,
              shouldSetValueEvenIfMissing: true,
            },
            {
              key: "createdAt",
              type: EApiControllerRequestTransformerType.DYNAMIC,
              value: TRANSFORMER_VALUE_DTO_CONSTANT.REQUEST_TIMESTAMP,
            },
          ],
        },
      },
    },
  },
})
```

Transformer types:

- `STATIC` - Set a constant value
- `DYNAMIC` - Extract value from request context (authenticated user, headers, IP)

## Response Transformers

Transform response data before returning to client:

```typescript
routes: {
  [EApiRouteType.GET]: {
    response: {
      [EApiControllerResponseTarget.RESPONSE]: {
        transformers: [
          {
            key: "responseSource",
            type: EApiControllerRequestTransformerType.STATIC,
            value: "api",
            shouldSetValueEvenIfMissing: true,
          },
        ],
      },
    },
  },
}
```

## Loading Relations

Configure relation loading:

```typescript
import { EApiControllerRelationReferenceShape } from "@elsikora/nestjs-crud-automator";

@ApiController<PostEntity>({
	entity: PostEntity,
	routes: {
		[EApiRouteType.CREATE]: {
			relations: {
				request: {
					reference: { shape: EApiControllerRelationReferenceShape.SCALAR },
					load: {
						include: { author: true },
					},
				},
				response: {
					reference: { shape: EApiControllerRelationReferenceShape.OBJECT, key: "id" },
					load: {
						include: { author: true, comments: true },
						relationLoadStrategy: "query",
					},
				},
			},
		},
	},
})
export class PostController {
	constructor(
		public service: PostService,
		// Inject related services for loading
		public authorService: UserService,
	) {}
}
```

Relation loading uses:

- `load.include` - Select direct relations and nested TypeORM relation preloads.
- `load.relationLoadStrategy` - Optional TypeORM `"join"` or `"query"` strategy.
- `relations.request.load.services` - Optional override for direct relation service property names; omitted keys use `${relationName}Service`.
- Request relation `load` hydrates only direct included relation keys present in the request body. Omitted, `undefined`, and `null` body relation values are left unchanged.
- Nested request include objects are passed to the direct relation service as TypeORM `relations`; they do not recursively hydrate nested request references.
- Custom route request relation loading uses the same relation config, but it only hydrates the method `@Body()` argument.

## Custom DTOs

Replace auto-generated DTOs with custom ones:

```typescript
import { ApiController, EApiDtoType, EApiRouteType } from "@elsikora/nestjs-crud-automator";
import { CreateUserDto } from "./dto/create-user.dto";
import { UpdateUserDto } from "./dto/update-user.dto";
import { UserResponseDto } from "./dto/user-response.dto";

@ApiController<UserEntity>({
  entity: UserEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      dto: {
        [EApiDtoType.BODY]: CreateUserDto,
        [EApiDtoType.RESPONSE]: UserResponseDto,
      },
    },
    [EApiRouteType.UPDATE]: {
      dto: {
        [EApiDtoType.BODY]: UpdateUserDto,
        [EApiDtoType.RESPONSE]: UserResponseDto,
      },
    },
  },
})
```

## Auto DTO Configuration

Customize auto-generated DTOs:

```typescript
import {
  AllOrNoneOfListedPropertiesValidator
} from "@elsikora/nestjs-crud-automator";

@ApiController<UserEntity>({
  entity: UserEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      autoDto: {
        [EApiDtoType.BODY]: {
          validators: [
            {
              constraintClass: AllOrNoneOfListedPropertiesValidator,
              options: ["firstName", "lastName"],
            },
          ],
        },
      },
    },
  },
})
```

## Request Validation

Add custom request validators:

```typescript
import { BadRequestException } from "@nestjs/common";
import { EApiControllerRequestTarget, EErrorStringAction, type IApiRequestValidator } from "@elsikora/nestjs-crud-automator";

const createValidators: Array<IApiRequestValidator<UserEntity>> = [
  {
    errorType: EErrorStringAction.BAD_REQUEST,
    exception: BadRequestException,
    validationFunction: (payload: Partial<UserEntity>) => Boolean(payload.email),
  },
];

routes: {
  [EApiRouteType.CREATE]: {
    request: {
      [EApiControllerRequestTarget.BODY]: {
        validators: createValidators,
      },
    },
  },
}
```

## Route Documentation

Generated CRUD routes use the package defaults unless you set `documentation` on the route. Use `documentation` for operation text and `operationId`; reserve `generation.decorators` for additive decorators such as interceptors, guards, or non-operation Swagger metadata:

```typescript
routes: {
  [EApiRouteType.CREATE]: {
    documentation: {
      description: "Creates a new user with the provided data",
      operationId: "createUser",
      summary: "Create a new user",
    },
  },
}
```

## Custom Decorators

Add additional decorators to routes:

```typescript
import { UseInterceptors } from "@nestjs/common";
import { FileInterceptor } from "@nestjs/platform-express";

routes: {
  [EApiRouteType.CREATE]: {
    generation: {
      decorators: [
        UseInterceptors(FileInterceptor('avatar')),
      ],
    },
  },
}
```

## Observable Controllers

Enable subscriber hooks by marking the controller as observable:

```typescript
import { ApiController, ApiControllerObservable } from "@elsikora/nestjs-crud-automator";

@ApiController({
	entity: PostEntity,
	path: "posts",
	routes: {},
})
@ApiControllerObservable()
export class PostController {
	constructor(public service: PostService) {}
}
```
