# Entities

Entities are the foundation of your CRUD operations. By properly configuring entity properties with `@ApiPropertyDescribe`, you enable automatic DTO generation, validation, and Swagger documentation.

## Basic Entity Configuration

Every entity property that should participate in CRUD operations must be decorated with `@ApiPropertyDescribe`:

```typescript filename="product.entity.ts" copy
import { Entity, PrimaryGeneratedColumn, Column } from "typeorm";
import { ApiPropertyDescribe, EApiPropertyDescribeType, EApiPropertyStringType, EApiPropertyNumberType } from "@elsikora/nestjs-crud-automator";

@Entity("products")
export class ProductEntity {
	@PrimaryGeneratedColumn("uuid")
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.UUID,
		description: "Product unique identifier",
	})
	id: string;

	@Column()
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.STRING,
		description: "Product name",
		format: EApiPropertyStringType.STRING,
		minLength: 3,
		maxLength: 100,
		pattern: "/^.{3,100}$/",
		exampleValue: "Laptop",
	})
	name: string;

	@Column({ type: "decimal", precision: 10, scale: 2 })
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.NUMBER,
		description: "Product price",
		format: EApiPropertyNumberType.DOUBLE,
		minimum: 0,
		maximum: 999999,
		multipleOf: 0.01,
		exampleValue: 999.99,
	})
	price: number;
}
```

## Property Types

### UUID Properties

Used for unique identifiers, typically primary keys:

```typescript
@PrimaryGeneratedColumn("uuid")
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.UUID,
  description: "Unique identifier",
})
id: string;
```

### String Properties

Text fields with various validation options:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "User email",
  format: EApiPropertyStringType.EMAIL,
  minLength: 5,
  maxLength: 255,
  pattern: "/^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$/",
  exampleValue: "user@example.com",
})
email: string;
```

Available string formats:

- `STRING` - Plain text
- `EMAIL` - Email addresses
- `URL` - URLs
- `PASSWORD` - Password fields (hidden in responses)

### Number Properties

Numeric fields with range validation:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.NUMBER,
  description: "User age",
  format: EApiPropertyNumberType.INTEGER,
  minimum: 18,
  maximum: 120,
  multipleOf: 1,
  exampleValue: 25,
})
age: number;
```

Available number formats:

- `INTEGER` - Whole numbers
- `DOUBLE` - Decimal numbers

### Boolean Properties

Boolean flags:

```typescript
@Column({ default: false })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.BOOLEAN,
  description: "Is user active",
})
isActive: boolean;
```

### Date Properties

Date and timestamp fields with automatic identifiers:

```typescript
@Column({ type: "timestamp", default: () => "CURRENT_TIMESTAMP" })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.DATE,
  identifier: EApiPropertyDateIdentifier.CREATED_AT,
  format: EApiPropertyDateType.DATE_TIME,
})
createdAt: Date;

@Column({
  type: "timestamp",
  default: () => "CURRENT_TIMESTAMP",
  onUpdate: "CURRENT_TIMESTAMP"
})
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.DATE,
  identifier: EApiPropertyDateIdentifier.UPDATED_AT,
  format: EApiPropertyDateType.DATE_TIME,
})
updatedAt: Date;
```

Date identifiers express semantics rather than property names:

- Infrastructure timestamps: `CREATED_AT`, `RECEIVED_AT`, and `UPDATED_AT`.
- Writable business dates: `DATE`, `EXPIRES_IN`, and `REFRESH_IN`.
- Range/query identifiers: `CREATED_AT_FROM`, `CREATED_AT_TO`, `RECEIVED_AT_FROM`, `RECEIVED_AT_TO`, `UPDATED_AT_FROM`, and `UPDATED_AT_TO`.

Generated CREATE, UPDATE, and PARTIAL_UPDATE body DTOs omit the three infrastructure identifiers while response DTOs retain them. A property named `createdAt` remains writable when its identifier is `DATE`, and a nonstandard property name such as `insertedOn` is excluded when its identifier is `CREATED_AT`.

### Enum Properties

Enumeration types with predefined values:

```typescript
export enum UserRole {
  USER = "user",
  ADMIN = "admin",
  MODERATOR = "moderator",
}

@Column({
  type: "enum",
  enum: UserRole,
  default: UserRole.USER
})
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.ENUM,
  description: "User role",
  enum: UserRole,
  enumName: "UserRole",
})
role: UserRole;
```

### Object Properties

Complex nested objects with optional discriminator support:

```typescript
@Column({ type: "jsonb" })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.OBJECT,
  description: "User metadata",
  dataType: UserMetadataDto,
  shouldValidateNested: true,
})
metadata: Record<string, unknown>;
```

For polymorphic objects with discriminator:

```typescript
@Column({ type: "jsonb" })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.OBJECT,
  description: "Payment method",
  discriminator: {
    propertyName: "type",
    mapping: {
      card: CardPaymentDto,
      paypal: PayPalPaymentDto,
    },
  },
  dataType: [CardPaymentDto, PayPalPaymentDto],
})
paymentMethod: CardPayment | PayPalPayment;
```

## Inherited Entity Metadata

Entities may extend a shared base class that owns common TypeORM columns or `@ApiPropertyDescribe` metadata. DTO generation walks the entity inheritance chain, so inherited columns, primary keys, relations, and property metadata participate in validation and Swagger generation for the concrete entity.

```typescript
abstract class BaseContentEntity {
	@PrimaryGeneratedColumn("uuid")
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.UUID,
		description: "Unique identifier",
	})
	id: string;

	@Column()
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.STRING,
		description: "Shared slug",
		format: EApiPropertyStringType.STRING,
		minLength: 1,
		maxLength: 64,
		pattern: "/^[a-z0-9-]+$/",
		exampleValue: "intro-to-crud",
	})
	slug: string;
}

@Entity("articles")
export class ArticleEntity extends BaseContentEntity {
	@Column()
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.STRING,
		description: "Article title",
		format: EApiPropertyStringType.STRING,
		minLength: 1,
		maxLength: 255,
		pattern: "/^.{1,255}$/",
		exampleValue: "Getting started",
	})
	title: string;
}
```

In this example, generated `ArticleEntity` DTOs include `id`, `slug`, and `title`. Inherited relation metadata is also registered as Swagger extra models when relation DTOs are generated.

### Relation Properties

Entity relationship metadata for route-configured loading:

```typescript
@ManyToOne(() => UserEntity, user => user.posts)
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.RELATION,
  description: "Post author",
})
author: UserEntity;

@OneToMany(() => CommentEntity, comment => comment.post)
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.RELATION,
  description: "Post comments",
})
comments: CommentEntity[];
```

## Table Inheritance

A generated controller over a TypeORM single-table-inheritance root serves polymorphic GET and GET_LIST responses without any DTO or option. Each row is serialized through the DTO of its own variant, so child columns reach the response and the fields of other variants do not.

```typescript filename="deposit-detail.entity.ts" copy
export enum EDepositDetailType {
	CARD_TRANSFER = "CARD_TRANSFER",
	FORM_POST = "FORM_POST",
	QR = "QR",
}

@Entity("deposit_detail")
@TableInheritance({ column: { enum: EDepositDetailType, name: "type", type: "enum" } })
export class DepositDetailEntity {
	@PrimaryGeneratedColumn("uuid")
	@ApiPropertyDescribe({ type: EApiPropertyDescribeType.UUID, description: "Detail identifier" })
	id: string;

	@Column({ enum: EDepositDetailType, type: "enum" })
	@ApiPropertyDescribe({ type: EApiPropertyDescribeType.ENUM, enum: EDepositDetailType, enumName: "EDepositDetailType", description: "Detail type" })
	type: EDepositDetailType;
}

@ChildEntity(EDepositDetailType.CARD_TRANSFER)
export class DepositDetailCardTransferEntity extends DepositDetailEntity {
	@Column({ nullable: true, type: "varchar" })
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.STRING,
		description: "Card number",
		format: EApiPropertyStringType.STRING,
		minLength: 1,
		maxLength: 19,
		pattern: "/^[0-9]+$/",
		exampleValue: "4111111111111111",
	})
	cardNumber: string;
}
```

```typescript filename="deposit-detail.controller.ts" copy
import "./deposit-detail-card-transfer.entity";

import { DepositDetailEntity } from "./deposit-detail.entity";

@ApiController<DepositDetailEntity>({
	entity: DepositDetailEntity,
	name: "DepositDetails",
	path: "deposit-details",
	routes: {
		[EApiRouteType.GET]: {},
		[EApiRouteType.GET_LIST]: {},
	},
})
export class DepositDetailController {
	constructor(public readonly service: DepositDetailService) {}
}
```

GET answers with `DepositDetailGetResponseCardTransferDTO` and its siblings, described in Swagger as `oneOf` with a discriminator mapping. GET_LIST keeps its usual wrapper (`DepositDetailGetListPageDTO`, or `DepositDetailGetListCursorPageDTO` in CURSOR mode), and its `items` are `oneOf` over `DepositDetailGetListResponseCardTransferDTO` and its siblings. The suffix is the discriminator value in camel case. The discriminator property stays in every response. A child entity declared as `@ChildEntity()` without a value gets its class name as the value, which is the TypeORM default, so the suffix is the class name, as in `DepositDetailGetResponseCardTransferDepositDetailEntityDTO`. Set an explicit value, such as `@ChildEntity("CARD_TRANSFER")`, for a shorter name.

The root must declare the discriminator column as a property with `@Column` and `@ApiPropertyDescribe`, keep it selected, store it as a string, and leave it in GET and GET_LIST responses. A manual RESPONSE DTO on a route keeps that route as it is.

### Which Classes Become Variants

Variants are read from TypeORM metadata:

- A leaf child entity is always a variant. Its value is the `@ChildEntity(...)` argument or, without one, the class name.
- The root and any intermediate child entity are variants only when the discriminator column can store their value, meaning the column has no `enum` or the enum contains the value. With an enum column they usually are not. On a `varchar` column the root is a variant, because `save()` through the root repository writes its class name as the value.

The column options come from the property column on the root, as in TypeORM: once the root declares the property, the options in `@TableInheritance({ column })` are ignored, including its `enum`.

These cases fail at startup:

- The discriminator column is missing or undescribed on the root, has `select: false`, or uses a numeric column type.
- The discriminator column is hidden from the generated GET or GET_LIST response, for example with `isEnabled: false` on the RESPONSE DTO of a route.
- No child entity is loaded when the controller is decorated.
- A leaf value is outside the column enum, or a discriminator value is not a non-empty string.
- A discriminator value contains a character other than letters, digits, `_` and `-`, such as `"my type"` or `"card.transfer"`, because the value becomes part of generated DTO names. A trailing `DTO` in any case is not repeated in the name, so `VIP_DTO` gives the suffix `Vip`, which fails next to a value `VIP`. The value `DTO` is only the suffix and keeps it: `Dto`.
- Two values produce the same DTO name suffix, or a value produces the name of another DTO generated for the entity, a relation DTO of another variant (`CARD_TRANSFER_ISSUER` next to a `CARD_TRANSFER` variant with an `issuer` relation). Values are never normalized, so change the value or the property name that produces the clash.

A manual RESPONSE DTO on both read routes takes the entity out of this contract.

A row whose discriminator value has no variant fails the request with `500`. The response does not echo the value, and nothing is serialized through a guessed DTO. The same happens when a subscriber or response transform removes the discriminator from a loaded row: the row cannot be matched to a variant, so the request fails closed instead of answering with a guessed shape.

### Loading Child Entities

Variants are compiled once when `@ApiController` decorates the class, so every child entity file must be imported before the controller file. Import them for their side effects, as above, or through a barrel. A glob in the data source `entities` option runs later and does not count.

A root with no child entity loaded at that moment fails startup. The controller constructor compares the variants with the child entities loaded by then and fails startup with a message naming the missing classes, before Swagger is generated. This also fires for a child class that is imported late and never registered in the data source. A REQUEST-scoped controller, including one that becomes request-scoped through its service, is constructed for every request, so every request answers with the generic `500` body until the import order is fixed; the message naming the classes appears only in the server log.

### Shared Columns Between Variants

Put columns shared by some variants on an abstract child entity:

```typescript
@ChildEntity()
export abstract class DepositDetailTransferEntity extends DepositDetailEntity {
	@Column({ nullable: true, type: "varchar" })
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.STRING,
		description: "Bank name",
		format: EApiPropertyStringType.STRING,
		minLength: 1,
		maxLength: 64,
		pattern: "/^.+$/",
		exampleValue: "Bank",
	})
	bankName: string;
}
```

A plain class with `@Column` between the root and a child makes `DataSource.initialize()` throw, without Automator being involved: a child takes its columns from its parent by property name, and the parent tree of TypeORM leaves such classes out. A plain class without columns is fine.

### What Stays On The Root

Filters, order, pagination, HOOKS and IAM scope, and `read.scope.parameters` work on root columns only. CURSOR order fields must be root columns, and each variant must keep the proof CURSOR requires for them; see [Pagination](/docs/nestjs-crud-automator/guides/pagination#table-inheritance-roots).

Generated CREATE, UPDATE, PARTIAL_UPDATE, and DELETE keep working on the root columns. Their bodies and responses are the plain DTOs of the root, without child columns.

Relations declared on a child entity are covered in [Relations](/docs/nestjs-crud-automator/guides/relations#relations-on-child-entities).

### Migration Notes

From 5.0.0, an existing generated controller over a table inheritance root changes in these ways:

- GET and GET_LIST return the full polymorphic shape instead of silently stripped variant columns, and their Swagger schemas are `oneOf`. Clients that depend on the reduced shape need a manual RESPONSE DTO on the route.
- The 4.x Swagger components `<Root>GetResponseDTO` and `<Root>GetListResponseDTO` are no longer generated. GET refers to the variant DTOs such as `<Prefix>GetResponseCardTransferDTO`, and the GET_LIST wrapper is `<Prefix>GetListPageDTO` with `oneOf` items. `<Prefix>` is the controller's schema prefix, see [Generated Schema Names](/docs/nestjs-crud-automator/core-concepts/dtos#generated-schema-names). Regenerate OpenAPI clients, or keep a manual RESPONSE DTO on the route to keep the old components.
- A discriminator column that exists only in `@TableInheritance({ column })` fails startup. Declare it on the root as a property with `@Column` and `@ApiPropertyDescribe`.
- A discriminator property without `@ApiPropertyDescribe` fails startup. Describe it, usually as `ENUM` or `STRING`.
- A discriminator hidden from GET or GET_LIST responses fails startup with `Table inheritance root <Root> must expose its discriminator column "type" in GET and GET_LIST responses`. Remove the hiding, or put a manual RESPONSE DTO on both read routes.
- A discriminator with `select: false` fails startup. Remove `select: false`.
- A numeric discriminator column, or a numeric value such as `@ChildEntity(1)`, fails startup. Keep a manual RESPONSE DTO on the read routes of such an entity.
- A leaf child whose value is outside the column enum fails startup. Add the value to the enum or change the `@ChildEntity(...)` argument.
- A discriminator value that clashes with another generated DTO name, or contains a character other than letters, digits, `_` and `-`, fails startup. Change the value or the property name that produces the clash.
- A controller whose child entity files load after it, or before any of them, fails startup. Import those files before the controller. A REQUEST-scoped controller answers every request with a generic `500` until then, and the server log names the classes.
- An enum in `@TableInheritance({ column })` that differs from the property column no longer counts; the property column decides, as it does in TypeORM.
- `GenerateEntityInformation(Child).tableName` returns the table of the root, where the child rows are stored, instead of a name derived from the discriminator value. A child entity without a `@ChildEntity(...)` value no longer throws there. Code that used the old value as a table name must use the root table.

## DTO Generation Control

Use `isAutoDtoEnabled: false` when a described property must remain outside all automatically generated DTOs:

```typescript
@Column({ default: false, type: "boolean" })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.BOOLEAN,
  description: "Internal eligibility flag",
  isAutoDtoEnabled: false,
})
internalEligibility: boolean;
```

Omitted or `true` keeps normal generation. `false` retains entity metadata, TypeORM persistence, and manual DTO support, while excluding the property from every generated BODY, PARAMETERS, QUERY, and RESPONSE DTO, generated Swagger relation components, and client filter/order surfaces. Route/DTO `isEnabled: true`, generated identity or read scope, and a typed query plan cannot re-enable it. Explicit `@ApiPropertyCopy` may deliberately copy it into a manual DTO and still applies all other source metadata rules. PAGE server-only ordering may use the described scalar; CURSOR ordering cannot because it requires generated response exposure.

Use route- and DTO-specific metadata when only selected generated DTOs should exclude a property:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Internal admin notes",
  format: EApiPropertyStringType.STRING,
  minLength: 0,
  maxLength: 500,
  pattern: "/^[\\s\\S]{0,500}$/",
  exampleValue: "Visible to admins only",
  properties: {
    [EApiRouteType.CREATE]: {
      [EApiDtoType.BODY]: { isEnabled: false },
    },
    [EApiRouteType.UPDATE]: {
      [EApiDtoType.BODY]: { isEnabled: true },
      [EApiDtoType.RESPONSE]: { isEnabled: false, isResponse: true },
    },
  },
})
internalNotes: string;
```

## Validation Rules

Add custom validation behavior:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Username",
  format: EApiPropertyStringType.STRING,
  minLength: 3,
  maxLength: 20,
  pattern: "/^[a-zA-Z0-9_-]+$/",
  properties: {
    [EApiRouteType.CREATE]: {
      [EApiDtoType.BODY]: { isRequired: true },
    },
  },
  exampleValue: "john_doe",
})
username: string;
```

## Guard-Based Visibility

Generate route/guard-specific response DTO metadata:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Sensitive data",
  format: EApiPropertyStringType.STRING,
  minLength: 1,
  maxLength: 255,
  pattern: "/^[\\s\\S]{1,255}$/",
  exampleValue: "restricted",
  properties: {
    [EApiRouteType.GET]: {
      [EApiDtoType.RESPONSE]: {
        isExpose: true,
        isResponse: true,
        guard: { guards: [AdminGuard] },
      },
    },
  },
})
sensitiveData: string;
```

The `guard` metadata selects a generated DTO variant for routes protected by that guard. It does not inspect the current user's role at serialization time; runtime allow/deny decisions belong in Nest guards or authorization policies.
