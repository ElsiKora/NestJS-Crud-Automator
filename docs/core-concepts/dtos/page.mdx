# DTOs

Data Transfer Objects (DTOs) in NestJS CRUD Automator are automatically generated based on entity metadata. The library creates appropriate DTOs for request bodies, query parameters, and responses with built-in validation and transformation.

## Automatic DTO Generation

DTOs are generated automatically from entity properties decorated with `@ApiPropertyDescribe`:

```typescript filename="user.entity.ts" copy
@Entity("users")
export class UserEntity {
	@PrimaryGeneratedColumn("uuid")
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.UUID,
		description: "User ID",
	})
	id: string;

	@Column()
	@ApiPropertyDescribe({
		type: EApiPropertyDescribeType.STRING,
		description: "Username",
		format: EApiPropertyStringType.STRING,
		minLength: 3,
		maxLength: 20,
		pattern: "/^[a-zA-Z0-9_-]+$/",
		exampleValue: "john_doe",
	})
	username: string;
}
```

This automatically generates:

- **CreateUserDto** - For POST requests
- **UpdateUserDto** - For PUT update/replace requests where enabled fields keep their requiredness
- **PartialUpdateUserDto** - For PATCH partial-update requests where enabled body fields are optional-friendly
- **UserResponseDto** - For responses
- **GetListQueryDto** - For GET /users query parameters

## DTO Types

### Body DTOs

Used for request bodies in CREATE and UPDATE operations.

**Create DTO** includes:

- Properties enabled for `[EApiRouteType.CREATE][EApiDtoType.BODY]`
- Validation rules from property configuration
- Required fields based on `isRequired`

**Update DTO** includes:

- Properties enabled for `[EApiRouteType.UPDATE][EApiDtoType.BODY]` or `[EApiRouteType.PARTIAL_UPDATE][EApiDtoType.BODY]`
- `UPDATE` bodies keep required fields required; `PARTIAL_UPDATE` bodies are optional-friendly
- Validation rules still apply when provided

### Query DTOs

Used for filtering and pagination in GET_LIST operations:

```typescript
// Generated GetListQueryDto structure
interface GetListQueryDto {
	limit?: number;
	page?: number;
	orderBy?: string;
	orderDirection?: "asc" | "desc";
	"username[operator]"?: EFilterOperation;
	"username[value]"?: string;
	"username[values]"?: string[];
}
```

Example usage:

```
GET /users?limit=10&page=1&username[operator]=cont&username[value]=john&orderBy=createdAt&orderDirection=desc
```

GET_LIST query DTOs remain dynamically generated from entity metadata. Optional route `request[EApiControllerRequestTarget.QUERY].filter` and `order` configuration narrows or overlays that metadata; it does not replace generation with a hand-written DTO. Automator compiles a normalized immutable plan and uses it for:

- The runtime query DTO and strict query parser.
- Controller- and plan-scoped DTO cache identity.
- OpenAPI deep-object `oneOf` filter branches.
- Typed TypeORM filter values and the direct-scalar order allowlist.

Omitting either section preserves its legacy metadata-driven behavior. A route plan cannot re-enable a field disabled by entity query metadata, and response visibility does not grant query exposure.

### Response DTOs

Control which properties are included in responses:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Password hash",
  format: EApiPropertyStringType.PASSWORD,
  minLength: 1,
  maxLength: 128,
  pattern: "/^[\\s\\S]{1,128}$/",
  exampleValue: "hashed-password",
  properties: {
    [EApiRouteType.GET]: {
      [EApiDtoType.RESPONSE]: { isEnabled: false, isResponse: true },
    },
    [EApiRouteType.GET_LIST]: {
      [EApiDtoType.RESPONSE]: { isEnabled: false, isResponse: true },
    },
  },
})
password: string;
```

## Controlling DTO Generation

### Exclude from DTOs

Prevent a property from appearing in specific DTOs:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Internal notes",
  format: EApiPropertyStringType.STRING,
  minLength: 0,
  maxLength: 500,
  pattern: "/^[\\s\\S]{0,500}$/",
  exampleValue: "Visible to staff only",
  properties: {
    [EApiRouteType.CREATE]: {
      [EApiDtoType.BODY]: { isEnabled: false },
    },
    [EApiRouteType.UPDATE]: {
      [EApiDtoType.BODY]: { isEnabled: false },
      [EApiDtoType.RESPONSE]: { isExpose: true, isResponse: true },
    },
  },
})
internalNotes: string;
```

### Required vs Optional

Control field requirements:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Email",
  format: EApiPropertyStringType.EMAIL,
  minLength: 5,
  maxLength: 255,
  pattern: "/^[\\w.-]+@([\\w-]+\\.)+[\\w-]{2,}$/",
  exampleValue: "user@example.com",
  properties: {
    [EApiRouteType.CREATE]: {
      [EApiDtoType.BODY]: { isRequired: true },
    },
    [EApiRouteType.PARTIAL_UPDATE]: {
      [EApiDtoType.BODY]: { isRequired: false },
    },
  },
})
email: string;
```

### Default Values

Specify default values for DTO properties:

```typescript
@Column({ default: false })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.BOOLEAN,
  description: "Is active",
})
isActive: boolean;
```

## Custom DTOs

Replace auto-generated DTOs with custom ones:

```typescript filename="dto/create-user.dto.ts" copy
import { IsString, IsEmail, MinLength, MaxLength } from "class-validator";
import { ApiProperty } from "@nestjs/swagger";

export class CreateUserDto {
	@ApiProperty()
	@IsString()
	@MinLength(3)
	@MaxLength(20)
	username: string;

	@ApiProperty()
	@IsEmail()
	email: string;

	@ApiProperty()
	@IsString()
	@MinLength(8)
	password: string;
}
```

Use in controller:

```typescript
@ApiController<UserEntity>({
  entity: UserEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      dto: {
        [EApiDtoType.BODY]: CreateUserDto,
        [EApiDtoType.RESPONSE]: UserResponseDto,
      },
    },
  },
})
```

Manual DTOs can also be nested inside auto-generated DTOs through `@ApiPropertyObject`. When this happens, NestJS CRUD Automator creates context-specific wrapper schemas for each generated path, so the same manual DTO can be reused safely in create body DTOs, update body DTOs, and response DTOs without sharing conflicting Swagger or serialization metadata.

For GET_LIST, a manual `dto[EApiDtoType.QUERY]` and generated `request[QUERY].filter` or `order` configuration are mutually exclusive. Manual response DTOs remain compatible with the generated query plan.

### Custom GET_LIST item DTOs

`GET_LIST` response DTOs support two explicit modes:

- Full wrapper mode: `dto[EApiDtoType.RESPONSE]` is a class that describes the whole list response.
- Item DTO mode: `dto[EApiDtoType.RESPONSE]` is `{ itemType }`, and the framework generates the list wrapper.

Use item DTO mode when a route only needs custom serialization for each item:

```typescript
class PublicUserResponseDto {
	@Expose()
	id!: string;

	@Expose()
	username!: string;
}

@ApiController<UserEntity>({
	entity: UserEntity,
	routes: {
		[EApiRouteType.GET_LIST]: {
			dto: {
				[EApiDtoType.RESPONSE]: {
					itemType: PublicUserResponseDto,
					name: "PublicUserListResponseDto",
				},
			},
		},
	},
})
export class UserController {}
```

Both modes use the same runtime list result shape: `count`, `currentPage`, `items`, `totalCount`, and `totalPages`.

## DTO Validation

### Built-in Validators

Validation rules are automatically applied based on property configuration:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Username",
  format: EApiPropertyStringType.STRING,
  minLength: 3, // Adds @MinLength(3)
  maxLength: 20, // Adds @MaxLength(20)
  pattern: "/^[a-zA-Z0-9_-]+$/", // Adds @Matches(/^[a-zA-Z0-9_-]+$/)
})
username: string;
```

### Custom Validators

Add custom validators to auto-generated DTOs:

```typescript
import {
  AllOrNoneOfListedPropertiesValidator
} from "@elsikora/nestjs-crud-automator";

@ApiController<UserEntity>({
  entity: UserEntity,
  routes: {
    [EApiRouteType.CREATE]: {
      autoDto: {
        [EApiDtoType.BODY]: {
          validators: [
            {
              constraintClass: AllOrNoneOfListedPropertiesValidator,
              options: ["firstName", "lastName"],
            },
          ],
        },
      },
    },
  },
})
```

Available built-in validators:

- `AllOrNoneOfListedPropertiesValidator` - All or none must be provided
- `OnlyOneOfListedPropertiesValidator` - Exactly one must be provided
- `HasAtLeastOneOfListedPropertiesValidator` - At least one required
- `HasAtLeastOneAndOnlyOneOfListedPropertiesValidator` - Only one required
- `MustMatchOneOfSchemasValidator` - Must match a schema
- `HasPairedCustomSuffixesFieldsValidator` - Paired fields validation

## Polymorphic DTOs

Support for discriminated unions:

```typescript
// Base interface
interface Payment {
  type: string;
}

// Specific implementations
interface CardPayment extends Payment {
  type: "card";
  cardNumber: string;
  cvv: string;
}

interface PayPalPayment extends Payment {
  type: "paypal";
  email: string;
}

@Column({ type: "jsonb" })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.OBJECT,
  description: "Payment method",
  discriminator: {
    propertyName: "type",
    mapping: {
      card: CardPaymentDto,
      paypal: PayPalPaymentDto,
    },
  },
  dataType: [CardPaymentDto, PayPalPaymentDto],
  shouldValidateNested: true,
})
paymentMethod: CardPayment | PayPalPayment;
```

## DTO Transformation

Transform DTO values during processing:

```typescript
import { Transform } from "class-transformer";

@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Email",
  format: EApiPropertyStringType.EMAIL,
  minLength: 5,
  maxLength: 255,
  pattern: "/^[\\w.-]+@([\\w-]+\\.)+[\\w-]{2,}$/",
  exampleValue: "user@example.com",
})
@Transform(({ value }) => value.toLowerCase())
email: string;
```

## Guard-Based DTO Properties

Generate separate DTO property variants for a guard class:

```typescript
@Column()
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.STRING,
  description: "Admin notes",
  format: EApiPropertyStringType.STRING,
  minLength: 0,
  maxLength: 500,
  pattern: "/^[\\s\\S]{0,500}$/",
  exampleValue: "Admin-only note",
  properties: {
    [EApiRouteType.GET]: {
      [EApiDtoType.RESPONSE]: {
        isExpose: true,
        isResponse: true,
        guard: { guards: [AdminGuard] },
      },
    },
  },
})
adminNotes: string;
```

This metadata tags the generated response DTO variant for routes protected by `AdminGuard`. It is not a per-request authorization check; use authentication guards or authorization policies to decide whether a request may use that route.

## Relation DTOs

Control how relations appear in DTOs:

```typescript
@ManyToOne(() => UserEntity)
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.RELATION,
  description: "Post author",
  properties: {
    [EApiRouteType.GET]: {
      [EApiDtoType.RESPONSE]: { isExpose: true, isResponse: true },
    },
  },
})
author: UserEntity;
```

Load relation data from the route config with `relations.response.load.include`, not from the property metadata.

## Nested DTOs

For complex nested objects:

```typescript
@Column({ type: "jsonb" })
@ApiPropertyDescribe({
  type: EApiPropertyDescribeType.OBJECT,
  description: "User profile",
  dataType: UserProfileDto,
  shouldValidateNested: true,
})
profile: UserProfile;
```
