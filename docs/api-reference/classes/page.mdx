# Classes

Reference for the main public classes provided by NestJS CRUD Automator. Low-level DTO factories, strategies, and internal runtime helpers are advanced extension points and should normally be reached through decorators and route config instead.

## Base Classes

### ApiServiceBase

Base class for services providing CRUD operations.

**Location:** `src/class/api/service-base.class.ts`

**Methods:**

#### `create(properties): Promise<E>`

Creates a new entity.

```typescript
create(
  properties: TApiFunctionCreateProperties<E>
): Promise<E>
```

#### `get(properties): Promise<E>`

Retrieves a single entity.

```typescript
get(
  properties: TApiFunctionGetProperties<E>
): Promise<E>
```

#### `getList(properties): Promise<IApiGetListResponseResult<E>>`

Retrieves a paginated list of entities.

```typescript
getList(
  properties: TApiFunctionGetListProperties<E>
): Promise<IApiGetListResponseResult<E>>
```

#### `getMany(properties): Promise<E[]>`

Retrieves multiple entities.

```typescript
getMany(
  properties: TApiFunctionGetManyProperties<E>
): Promise<E[]>
```

#### `update(criteria, properties): Promise<E>`

Updates an entity.

```typescript
update(
  criteria: Array<TApiFunctionUpdateCriteria<E>> | TApiFunctionUpdateCriteria<E>,
  properties: TApiFunctionUpdateProperties<E>
): Promise<E>
```

#### `delete(criteria): Promise<void>`

Deletes an entity.

```typescript
delete(
  criteria: Array<TApiFunctionDeleteCriteria<E>> | TApiFunctionDeleteCriteria<E>
): Promise<void>
```

#### `protected getApiFunctionContext(): IApiFunctionContext<T>`

Returns the active function context inside a decorated `@ApiFunctionCustom` or built-in `@ApiFunction` execution. Use it from service subclasses to access transaction-aware `operations`, `repository`, and `eventManager`.

```typescript
const context = this.getApiFunctionContext<PostEntity>();
await context.operations.update({ id }, { status: "published" });
```

#### `protected getApiFunctionStepContext(): IApiFunctionStepContext<T>`

Returns the active transaction-aware step context inside an `@ApiFunctionStep` method. Use it for internal helpers that need `eventManager`, the entity `repository`, or `getRepository()` without exposing `EntityManager` in the method signature.

```typescript
const context = this.getApiFunctionStepContext<PostEntity>();
await context.repository.save(post);
```

`getApiFunctionStepContext()` intentionally omits `operations`. Use `@ApiFunctionCustom` and `getApiFunctionContext()` for standalone custom service actions that need function lifecycle helpers and subscribers.

- [Core Concepts - Services](/docs/nestjs-crud-automator/core-concepts/services)

## Subscriber Base Classes

### ApiRouteSubscriberBase

Abstract base class for route-level subscribers.

**Location:** `src/class/api/subscriber/route-base.class.ts`

```typescript
abstract class ApiRouteSubscriberBase<E extends IApiBaseEntity, TAuthorizationExpectation extends EApiRouteSubscriberAuthorizationExpectation = EApiRouteSubscriberAuthorizationExpectation.OPTIONAL, M extends EApiControllerGetListQueryPaginationMode = EApiControllerGetListQueryPaginationMode.PAGE>
```

The second generic is optional and type-only. Use `EApiRouteSubscriberAuthorizationExpectation.REQUIRED` when the subscriber only observes routes that guarantee authentication and authorization. The third generic defaults to PAGE for source compatibility; select CURSOR when GET_LIST hooks consume cursor queries and the flat response.

**Hook Methods:**

- `onBeforeCreate`, `onAfterCreate`, `onBeforeErrorCreate`, `onAfterErrorCreate`
- `onBeforeUpdate`, `onAfterUpdate`, `onBeforeErrorUpdate`, `onAfterErrorUpdate`
- `onBeforePartialUpdate`, `onAfterPartialUpdate`, `onBeforeErrorPartialUpdate`, `onAfterErrorPartialUpdate`
- `onBeforeGet`, `onAfterGet`, `onBeforeErrorGet`, `onAfterErrorGet`
- `onBeforeGetList`, `onAfterGetList`, `onBeforeErrorGetList`, `onAfterErrorGetList`
- `onBeforeDelete`, `onAfterDelete`, `onBeforeErrorDelete`, `onAfterErrorDelete`

### ApiFunctionSubscriberBase

Abstract base class for function-level subscribers.

**Location:** `src/class/api/subscriber/function-base.class.ts`

**Generic Parameters:**

```typescript
ApiFunctionSubscriberBase<
	E extends IApiBaseEntity,
	BeforeCreateResult extends TApiFunctionCreateProperties<E> = TApiFunctionCreateProperties<E>,
	BeforeDeleteResultOrTransactionExpectation extends TApiFunctionDeleteCriteria<E> | EApiFunctionSubscriberTransactionExpectation = TApiFunctionDeleteCriteria<E>,
	BeforeGetResult extends TApiFunctionGetProperties<E> = TApiFunctionGetProperties<E>,
	BeforeGetListResult extends TApiFunctionGetListProperties<E> = TApiFunctionGetListProperties<E>,
	BeforeGetManyResult extends TApiFunctionGetManyProperties<E> = TApiFunctionGetManyProperties<E>,
	BeforeUpdateResult extends TApiFunctionUpdateProperties<E> = TApiFunctionUpdateProperties<E>,
	TTransactionExpectation extends EApiFunctionSubscriberTransactionExpectation = TApiSubscriberFunctionBaseTransactionExpectation<BeforeDeleteResultOrTransactionExpectation>,
>
```

The before-result generics are optional and type-only. Keep the one-generic form for default CRUD payloads, or pass a stricter before-create payload as `ApiFunctionSubscriberBase<Entity, CreateInput>`.

The third generic remains the before-delete result when it is a delete criteria type. When it is an `EApiFunctionSubscriberTransactionExpectation`, it declares the subscriber's transaction expectation shorthand, for example `ApiFunctionSubscriberBase<Entity, CreateInput, EApiFunctionSubscriberTransactionExpectation.REQUIRED>`. If you also customize later before-result generics, use the final `TTransactionExpectation` generic. Pair either form with `@ApiFunctionSubscriber({ transaction: { expectation } })` and the same helper context generic to narrow `context.DATA.eventManager`.

**Hook Methods:**

- `onBeforeCreate`, `onAfterCreate`, `onBeforeErrorCreate`, `onAfterErrorCreate`
- `onBeforeUpdate`, `onAfterUpdate`, `onBeforeErrorUpdate`, `onAfterErrorUpdate`
- `onBeforeGet`, `onAfterGet`, `onBeforeErrorGet`, `onAfterErrorGet`
- `onBeforeGetList`, `onAfterGetList`, `onBeforeErrorGetList`, `onAfterErrorGetList`
- `onBeforeGetMany`, `onAfterGetMany`, `onBeforeErrorGetMany`, `onAfterErrorGetMany`
- `onBeforeDelete`, `onAfterDelete`, `onBeforeErrorDelete`, `onAfterErrorDelete`
- `onBeforeCustom`, `onAfterCustom`, `onBeforeErrorCustom`, `onAfterErrorCustom`
- `onAfterCommit`, `onAfterRollback`
- `onBeforeErrorCommit`, `onAfterErrorCommit`, `onBeforeErrorRollback`, `onAfterErrorRollback`

Post-transaction hooks run only after the outer owner confirms commit or rollback. They return `Promise<void>` and cannot replace operation results.

## Utility Classes

### MetadataStorage

Singleton class for storing and retrieving entity property metadata.

**Location:** `src/class/metadata-storage.class.ts`

**Methods:**

#### `getInstance(): MetadataStorage`

Returns the singleton instance.

```typescript
const storage = MetadataStorage.getInstance();
```

#### `setMetadata(entityName, propertyKey, key, value)`

Stores metadata for a property.

```typescript
storage.setMetadata("UserEntity", "username", "API_PROPERTY_DESCRIBE_METADATA_KEY", { ... });
```

#### `getMetadata(entityName, propertyKey?, key?)`

Retrieves all entity metadata, one property metadata entry, or one metadata key.

```typescript
const metadata = storage.getMetadata("UserEntity", "username", "API_PROPERTY_DESCRIBE_METADATA_KEY");
```

#### `getAllEntitiesMetadata()`

Retrieves metadata for every registered entity.

```typescript
const allMetadata = storage.getAllEntitiesMetadata();
```

### ApiControllerFactory

Factory class for generating controller endpoints.

**Location:** `src/factory/api-controller.factory.ts`

**Internal Use:** This class is used internally by the `@ApiController` decorator and is not typically used directly.

### ApiRouteRuntime

Runtime executor for generated and custom controller routes. It handles request target validation/transformation, relation hydration, authorization decision application, subscriber execution, service calls, and response serialization. Generated routes can also resolve `SUPPORTS`, `REQUIRED`, `MANDATORY`, and `NONE` transaction modes; a route-owned `REQUIRED` transaction encloses request relation hydration, the generated operation, and response relation reload.

**Location:** `src/class/api/route-runtime.class.ts`

**Internal Use:** Generated route methods and `@ApiRouteCustom` call this class through decorator/runtime wiring.

**Public static methods used by decorators:**

- `executeGenerated(options)` runs the generated CRUD route pipeline and opens a `ROUTE`-owned transaction when configured `REQUIRED` and no owner is active.
- `executeCustom(options)` runs the `@ApiRouteCustom` pipeline around a custom controller operation.
- `executeCustomRequestRelations(controller, metadata, runtimeProperties, body)` hydrates configured request relations for custom routes.
- `executeCustomResponseRelations(controller, runtimeProperties, response)` reloads configured response relations for custom routes.

## Function Runtime Classes

### ApiFunctionTransactionScope

Public helper for running code inside an external TypeORM transaction while making the transaction manager available through `ApiFunctionContextStorage`.

**Location:** `src/class/api/function/transaction/scope.class.ts`

**Static methods:**

- `runWithDataSource(dataSource, { name }, callback)` opens a named TypeORM transaction and passes its owning `EntityManager` to the callback.
- `runWithEntityManager(entityManager, callback)` joins only the manager already bound to an active Automator transaction.

Only service-bound decorated function execution, including generated `@ApiFunction` flows and `@ApiFunctionCustom`, has real CRUD `operations`; transaction scopes created without a decorated service expose `getRepository` and transaction metadata but reject CRUD operations because there is no owning service context.

### Transaction Outcome Exceptions

#### ApiFunctionTransactionPostCommitException

The database commit succeeded, but one or more `onAfterCommit` or commit-error lifecycle hooks failed. `outcome` is `COMMITTED`; the exception exposes `transactionId`, `owner`, `hookFailures`, and `errorLifecycleFailures`. Do not report or retry this as a rollback.

#### ApiFunctionTransactionCommitUnknownOutcomeException

The driver did not confirm the result of COMMIT. `outcome` is `UNKNOWN`; the exception exposes the commit failure, optional cleanup failure, error-lifecycle failures, transaction id, and owner. Automator invokes commit-error lifecycle but neither post-commit nor post-rollback hooks for this uncertain outcome.

#### ApiFunctionTransactionRollbackException

The operation failed and rollback handling also produced a database, post-rollback, or rollback-error lifecycle failure. The original `operationError` remains available. `outcome` is `ROLLED_BACK` when the database rollback was confirmed and `UNKNOWN` when the rollback itself failed.

## Authorization Classes

### ApiAuthorizationPolicyBase

Base class for hooks-mode authorization policies. Provides helper methods such as `allow`, `deny`, `allowForRoles`, `allowForPermissions`, `denyForPermissions`, and `scopeToOwner` for constructing rules executed by the hooks engine.

**Location:** `src/class/api/authorization/policy/base.class.ts`

### ApiAuthorizationModule

Global module that wires the authorization registry, discovery service, guard, hooks runtime, IAM runtime, bootstrap validation, and simulator services.

**Location:** `src/module/api/authorization.module.ts`

**Module providers/exports include:** `ApiAuthorizationGuard`, `ApiAuthorizationRuntime`, `ApiAuthorizationSimulator`, `ApiAuthorizationBootstrapValidationService`, `ApiAuthorizationPolicyDiscoveryService`, `ApiAuthorizationPolicyRegistry`, `ApiAuthorizationHookPermissionResolver`, IAM attachment/document resolvers, IAM document validator, IAM query planner, authorization cache stores, `ApiAuthorizationCacheInvalidationService`, and related authorization tokens.

**Static methods:**

- `forRoot(options?: IApiAuthorizationModuleOptions): DynamicModule` for value-based resolver and source registration
- `forRootAsync(options: IApiAuthorizationModuleAsyncOptions): DynamicModule` for DI-backed `principalResolver`, `hookPermissionSources`, `iam.attachmentSources`, and `iam.documentSources`

`forRootAsync(...)` supports the standard Nest async module patterns: `imports`, `inject`, `useFactory`, `useClass`, and `useExisting`. Use `IApiAuthorizationModuleOptionsFactory` when you want a dedicated Nest provider class that builds the authorization module options. Module options also select the resolver cache mode: source-first is the default, while bounded memory caching requires explicit TTL and entry-limit values.

### ApiAuthorizationRuntime

Shared runtime that resolves the principal, selects the controller or route authorization mode, and dispatches to either hooks or IAM evaluation.

**Location:** `src/class/api/authorization/runtime.class.ts`

### ApiAuthorizationSimulator

Service for evaluating authorization decisions outside HTTP requests by reusing the same runtime as the guard.

**Location:** `src/class/api/authorization/simulator.class.ts`

### ApiAuthorizationIamEngine

Evaluates IAM attachments and policy documents, applies explicit deny and boundary rules, resolves runtime condition paths such as `principal.*`, `resource.*`, and `request.*`, and produces IAM decision traces.

**Location:** `src/class/api/authorization/iam/engine.class.ts`

### ApiAuthorizationIamQueryPlanner

Compiles safe `resource.*` IAM conditions into database scopes for controller queries. The planner supports `StringEquals` and `StringEqualsIfExists` on filterable resource fields, including `resource.id`, `resource.operatorId`, and nested `queryPath` mappings such as `operator.id`.

**Location:** `src/class/api/authorization/iam/query-planner.class.ts`

### ApiAuthorizationHookPermissionResolver

Resolves permissions for hooks mode from configured `IApiHookPermissionSource` implementations. Source-first mode reads them on every evaluation; memory mode may reuse a bounded process-local entry.

**Location:** `src/class/api/authorization/hook/permission/resolver.class.ts`

### ApiAuthorizationHookPermissionCache

Stores hook-mode permissions by normalized principal only when the module explicitly selects `MEMORY`. It remains empty in default source-first mode and supports public invalidation through `ApiAuthorizationCacheInvalidationService`.

**Location:** `src/class/api/authorization/hook/permission/cache.class.ts`

### ApiAuthorizationIamAttachmentCache

Stores IAM policy attachments and boundaries by normalized principal only in explicit bounded memory mode. Source-first evaluations bypass it.

**Location:** `src/class/api/authorization/iam/attachment/cache.class.ts`

### ApiAuthorizationIamDocumentCache

Stores IAM policy document records by normalized document id set only in explicit bounded memory mode. Source-first evaluations bypass it.

**Location:** `src/class/api/authorization/iam/document/cache.class.ts`

### ApiAuthorizationBootstrapValidationService

Applies resolver cache configuration and validates cache bounds, securable controller configuration, authorization mode selection, hooks policy presence, and IAM prerequisites during application bootstrap.

**Location:** `src/class/api/authorization/bootstrap-validation.service.class.ts`

### ApiAuthorizationCacheInvalidationService

Public Nest injectable facade for clearing authorization policy, hook permission, and IAM resolver caches after policy or permission changes. Resolver-cache invalidation is required for immediate visibility in memory mode and is harmless in source-first mode.

**Location:** `src/class/api/authorization/cache-invalidation.service.class.ts`

```typescript
@Injectable()
export class PermissionAdminService {
	constructor(private readonly cacheInvalidation: ApiAuthorizationCacheInvalidationService) {}

	async grantPermission(userId: string, permission: string): Promise<void> {
		await this.permissionRepository.save({ userId, permission });
		this.cacheInvalidation.clearAll(UserEntity);
	}
}
```
