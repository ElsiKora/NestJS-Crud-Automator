# Utilities

Utility functions and helpers provided by NestJS CRUD Automator.

## Entity Utilities

### GenerateEntityInformation

Generates entity metadata from an entity class. The result includes TypeORM columns, relations, the primary key, and `@ApiPropertyDescribe` metadata discovered on the entity and its inherited base classes.

**Location:** `src/utility/generate-entity-information.utility.ts`

```typescript
function GenerateEntityInformation<E>(entity: TApiEntityReference): IApiEntity<E>;
```

**Usage:**

```typescript
const entityInfo = GenerateEntityInformation(UserEntity);
// Returns: { tableName: "users", primaryKey: { name: "id", ... }, columns: [...] }
```

Tables, columns, and relations are matched to the class and its ancestors, not by name, so a same-named class does not contribute to the result.

### ResolveMetadataTarget

Resolves an entity reference to the class that `MetadataStorage` keys its metadata by. A class is returned as is, an `EntitySchema` resolves to its `target` class, and a `{ name }` reference resolves to the one class registered with that name by TypeORM's `@Entity` decorator (`getMetadataArgsStorage().tables`). It reads decorator registrations, not the entity metadata of a `DataSource`, so a name known only through a `DataSource` fails, or resolves to an unrelated `@Entity` class that has the same name. An `EntitySchema` without a `target` class always fails. A name that matches no entity class or several entity classes throws an error that names the target.

**Location:** `src/utility/resolve/metadata-target.utility.ts`

```typescript
function ResolveMetadataTarget(entity: IApiBaseEntity): TMetadataStorageTarget;
```

**Usage:**

```typescript
const metadata = MetadataStorage.getInstance().getMetadata(ResolveMetadataTarget({ name: "UserEntity" }));
```

### GetDefaultStringFormatProperties

Returns the default description, example, length bounds, and regex pattern for supported string formats.

**Location:** `src/utility/api/get-default-string-format-properties/utility.ts`

```typescript
function GetDefaultStringFormatProperties<TFormat extends TApiPropertyDefaultStringFormat>(format: TFormat, ...parameters: TApiGetDefaultStringFormatPropertiesParameters<TFormat>): TApiPropertyDefaultStringFormatProperties;
```

**Usage:**

```typescript
const emailDefaults = GetDefaultStringFormatProperties(EApiPropertyStringType.EMAIL);

@ApiPropertyDescribe({
	type: EApiPropertyDescribeType.STRING,
	format: EApiPropertyStringType.EMAIL,
	...emailDefaults,
})
email!: string;
```

`BIGINT_STRING` accepts format-specific options:

```typescript
const unsignedBigintDefaults = GetDefaultStringFormatProperties(EApiPropertyStringType.BIGINT_STRING, {
	sign: EApiGetDefaultStringFormatPropertiesBigIntStringSign.UNSIGNED,
});
```

### DtoGenerate

Generates DTO classes from entity metadata.

**Location:** `src/utility/dto/generate/core.utility.ts`

```typescript
function DtoGenerate<E>(
	entity: ObjectLiteral,
	entityMetadata: IApiEntity<E>,
	method: EApiRouteType,
	dtoType: EApiDtoType,
	schemaPrefix: string,
	dtoConfig?: IApiControllerPropertiesRouteAutoDtoConfig,
	currentGuard?: Type<CanActivate>,
	queryPlan?: IApiControllerGetListQueryPlan,
	responseVariantName?: string,
	routeName?: string,
	listResponseDto?: ReadonlyArray<Type<unknown>> | Type<unknown>,
	responseRelations?: IApiControllerPropertiesRouteBaseRelationsResponse<E>,
): Type<unknown> | undefined;
```

`schemaPrefix` is the schema prefix of the controller that owns the route, from `ApiControllerGetSchemaPrefix`. It starts every generated DTO name, so two controllers on one entity never share an OpenAPI component. `routeName` is the PascalCase handler method name of a custom route; it takes the place of the route type in the generated names. See [Generated Schema Names](/docs/nestjs-crud-automator/core-concepts/dtos#generated-schema-names). `responseRelations` is the `relations.response` config of the route; it shapes the relation properties of a RESPONSE DTO and is ignored for any other DTO type.

**Internal Use:** Called automatically for DTO generation.

### CorrelationIDNormalizeException

Converts what an exception filter caught into the `HttpException` that carries the correlation contract: the same `correlationID` and `timestamp` rule as `CorrelationIDResponseBodyInterceptor`, with the received value in `cause`. It writes the `x-correlation-id` response header through the HTTP adapter, also on the native response a Nest middleware failure carries. A client `x-correlation-id` is kept only when it is 1 to 128 characters of `[A-Za-z0-9._:-]`, otherwise a UUID is generated, as described in [Client Correlation ID](/docs/nestjs-crud-automator/api-reference/interceptors#client-correlation-id). A failure that already passed through the interceptor is returned as is. Outside an HTTP context the ID is generated and only appears in the body.

**Location:** `src/utility/correlation-id/normalize-exception.utility.ts`

**Type Signature:**

```typescript
function CorrelationIDNormalizeException(exception: unknown, host: ArgumentsHost, httpAdapterHost: HttpAdapterHost): HttpException;
```

**Example:**

```typescript
const { httpAdapter } = this.httpAdapterHost;
const response = host.getArgByIndex(1);
const normalized = CorrelationIDNormalizeException(exception, host, this.httpAdapterHost);

// The adapter answers both a Fastify reply and the native response from Nest middleware,
// but only the native response reports headersSent itself
if (!(response.headersSent ?? httpAdapter.isHeadersSent(response))) {
	httpAdapter.reply(response, normalized.getResponse(), normalized.getStatus());
}
```

See [Custom Exception Filters](/docs/nestjs-crud-automator/guides/error-handling#custom-exception-filters).

### ApiRequestValidationGetErrors

Reads the validation failures of an `ApiRequestValidationException`, thrown as is or kept in the `cause` chain, as `CorrelationIDResponseBodyInterceptor` keeps what it caught. Any value can be thrown, so the walk stops after 16 steps, which also ends a cycle, and a value that throws on being read counts as holding no failures.

**Location:** `src/utility/api/request-validation-get-errors.utility.ts`

**Type Signature:**

```typescript
function ApiRequestValidationGetErrors(exception: unknown): Array<ValidationError> | undefined;
```

See [Translating Request Validation Failures](/docs/nestjs-crud-automator/guides/error-handling#translating-request-validation-failures).

### FormatErrorEvidenceForLog

Formats an unknown error as bounded evidence suitable for a log message.

**Location:** `src/utility/error/evidence-for-log.utility.ts`

```typescript
function FormatErrorEvidenceForLog(error: unknown): string;
```

The result contains only an ASCII error-type token of at most 64 characters and, when available, a validated five-character SQLSTATE. Inspection is bounded and uses own data descriptors, so getters are not invoked. The utility never reads or emits `message`, `stack`, query text, parameters, headers, URLs, IP addresses, or arbitrary driver fields.

```typescript
import { FormatErrorEvidenceForLog } from "@elsikora/nestjs-crud-automator";

logger.error(`Database operation failed: ${FormatErrorEvidenceForLog(error)}`);
```

`FormatUnknownForLog` remains a general formatter and is not a safe error-evidence boundary.

## Logging Utilities

### LoggerUtility

Logging utility for internal use.

**Location:** `src/utility/logger.utility.ts`

```typescript
class LoggerUtility {
	static getLogger(context?: string): LoggerUtility;
}
```

**Example:**

```typescript
const logger = LoggerUtility.getLogger("UserService");
logger.log("Operation completed");
logger.error(`Operation failed: ${FormatErrorEvidenceForLog(error)}`);
```

The `NCD_LOG_LEVEL` environment variable picks the enabled levels: `none`, `error`, `warn`, `log` (the default), `debug` or `verbose`. The logger reads it from `process.env` only, when a logger handles its first message rather than when the package is imported. Crud Automator does not load a `.env` file. Set the variable in the process environment, or load your `.env` during startup, for example with `ConfigModule.forRoot()` from `@nestjs/config`, before the application logs. A logger keeps the levels of its first message; `setLogLevels` replaces them.

### Generated GET identity ownership

Top-level GET `identity` configuration is owned by the `@ApiController` factory because one private compiled plan must drive the path, PARAMETERS DTO, runtime primary-key lookup, and authorization canonicalization. The legacy low-level `ApiControllerApplyDecorators`, `ApiControllerApplyMetadata`, `ApiControllerGetDto`, and `ApiControllerWriteDtoSwagger` signatures do not accept that plan and fail closed when passed a route containing `identity`. Use `@ApiController` for identity-aliased generated GET routes; the low-level helpers remain compatible with route configurations that do not contain `identity`.

## Authorization Utilities

- `AuthorizationDecisionApplyResult` applies an authorization decision's response transforms.
- `AuthorizationDecisionAttachResource` attaches resolved resources to a decision.
- `AuthorizationDecisionResolveFromRequest` reads an authorization decision from the authentication request.
- `AuthorizationPermissionMatches` and `AuthorizationPermissionSetMatches` compare permission strings and sets.
- `AuthorizationResolveDefaultPrincipal` resolves the default principal from an authentication request.
- `AuthorizationScopeMergeWhere` merges authorization scopes into TypeORM `where` options. Array-form OR scopes must contain at least one non-empty plain-object branch; empty arrays and empty branches fail closed instead of reaching TypeORM as an unconstrained query. When an additional scope is present, scalar leaves are normalized to explicit `Equal(...)` operators before TypeORM receives them. Wrap object-valued scalar columns such as JSON/JSONB or geometry in `Equal(value)` explicitly; raw objects remain relation or embedded criteria.

## Database Utilities

TypeORM helpers detect and explain common database errors:

- `DatabaseTypeOrmAssertEffectiveWhere` refuses a `where` that TypeORM would widen or reject: an `undefined` or `null` value (use `IsNull()`), an empty relation object, an empty OR array or an empty OR branch. A missing or empty top-level `where` still reads every row. `getList` and `getMany` run it before every query.
- `DatabaseTypeOrmAssertRequiredWhere` applies the same rules and also refuses a missing or empty `where`. `get`, `update`, `delete` and generated PATCH run it before every single-row query, so a lost criterion fails instead of matching the first row.
- `DatabaseTypeOrmIsUniqueViolation`
- `DatabaseTypeOrmIsForeignKeyViolation`
- `DatabaseTypeOrmGetUniqueViolationDetails`
- `DatabaseTypeOrmGetForeignKeyViolationDetails`
- `DatabaseTypeOrmIsEntityNotFound`
- `DatabaseTypeOrmIsEntityMetadataNotFound`

## DTO Utilities

Public DTO helpers include generation, decorator, auto-context, manual child DTO, date handling, property marking, and cache-key helpers. Most are intended for advanced integrations with the generated DTO pipeline rather than normal application code.

## Migration Notes

Before 5.0.0, importing Crud Automator ran `dotenv`'s `config()`: it loaded the application's `.env` file into `process.env` and printed a line such as `injected env (0) from .env` at startup. From 5.0.0 the package has no `dotenv` dependency and never reads `.env`.

If your application relied on that side effect, load the file yourself before anything reads it, for example with `node --env-file=.env`, `import "dotenv/config"` as the first import, or `@nestjs/config`. This also applies to `NCD_LOG_LEVEL`, which each logger reads at its first message, so a value that `ConfigModule.forRoot()` loads during bootstrap takes effect.
