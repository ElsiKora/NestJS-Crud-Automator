# Interfaces

Complete reference for key interfaces used in NestJS CRUD Automator.

## Core Interfaces

### IApiBaseEntity

Base interface for all entities.

```typescript
interface IApiBaseEntity {
	[key: string]: unknown;
}
```

All entities must implement this interface (implicitly through TypeScript's structural typing).

### IApiGetListResponseResult\<E\>

Response structure for PAGE list operations.

```typescript
interface IApiGetListResponseResult<E> {
	count: number;
	currentPage: number;
	items: Array<E>;
	totalCount: number;
	totalPages: number;
}
```

### IApiGetListCursorResponseResult\<E\>

Flat response structure for generated CURSOR list operations.

```typescript
interface IApiGetListCursorResponseResult<E> {
	items: Array<E>;
	nextCursor: null | string;
	previousCursor: null | string;
}
```

All three properties are always present. This response intentionally has no count, total, page-info, or boolean fields.

## Controller Interfaces

### IApiControllerProperties\<E\>

Configuration options for `@ApiController`.

```typescript
interface IApiControllerProperties<E extends IApiBaseEntity> {
	authorization?: IApiControllerAuthorizationProperties<E>;
	entity: IApiBaseEntity;
	name?: string;
	path?: string;
	routes: {
		[R in EApiRouteType]?: TApiControllerPropertiesRoute<E, R>;
	};
}
```

Generated route entries also accept `documentation?: IApiRouteDocumentationProperties` through their shared route base configuration. Use it to override the default pluralized Swagger summary, description, or operation ID for a specific CRUD route.

```typescript
interface IApiRouteDocumentationProperties {
	description?: string;
	operationId?: string;
	summary?: string;
}

interface IApiControllerPropertiesRouteBase<E, R extends EApiRouteType> {
	documentation?: IApiRouteDocumentationProperties;
	generation?: IApiControllerPropertiesRouteBaseGeneration;
	read?: Extract<R, EApiRouteType.GET | EApiRouteType.GET_LIST> extends never ? never : IApiControllerPropertiesRouteBaseRead<E>;
	relations?: IApiControllerPropertiesRouteBaseRelations<E>;
	request?: IApiControllerPropertiesRouteBaseRequest<E, R>;
	response?: IApiControllerPropertiesRouteBaseResponse<E, R>;
	security?: IApiControllerPropertiesRouteBaseSecurity;
	transaction?: IApiControllerPropertiesRouteBaseTransaction;
}
```

Generated GET routes additionally accept `identity` as a top-level route property. It is separate from `read`, because it names the primary item segment while `read.scope` maps controller-path owner segments.

### IApiControllerPropertiesRouteIdentity

```typescript
interface IApiControllerPropertiesRouteIdentity {
	parameter: string;
}

const getRoute: TApiControllerPropertiesRoute<GameEntity, EApiRouteType.GET> = {
	identity: { parameter: "gameId" },
};
```

`identity.parameter` changes the generated GET wire path from the entity primary field (for example `:id`) to a safe simple identifier such as `:gameId`. It does not select another entity field and does not rename the response: DTO generation, runtime lookup, authorization resource expansion, and service criteria still use the actual primary column. `identity` is rejected on GET_LIST and every write route, and it cannot be combined with a manual `dto[EApiDtoType.PARAMETERS]`.

An identity-only GET is valid when the controller `path` has no dynamic parameters. If the controller path contains any inherited `:parameter`, the same GET must also provide `read.scope.parameters`, with every inherited parameter mapped exactly once. The identity alias cannot collide with an inherited parameter or with the primary field name inherited from the controller path.

### IApiControllerPropertiesRouteBaseRead\<E\>

Generated GET and GET_LIST routes may scope reads through parameters inherited from the controller `path`:

```typescript
interface IApiControllerPropertiesRouteBaseRead<E> {
	scope: IApiControllerPropertiesRouteReadScope<E>;
}

interface IApiControllerPropertiesRouteReadScope<E> {
	parameters: ReadonlyArray<IApiControllerPropertiesRouteReadScopeParameter<E>>;
}

interface IApiControllerPropertiesRouteReadScopeParameter<E> {
	field: TApiControllerReadDirectScalarField<E>;
	parameter: string;
}
```

`parameters` is a non-empty array of `{ parameter, field }` mappings. Every required scalar `:parameter` declared by the inherited controller path must appear exactly once; wildcard and optional/grouped dynamic parameters are rejected at bootstrap. Each `field` must be a different described direct scalar entity column. Unknown or duplicate parameters, duplicate fields, missing mappings, relations, objects, and use on routes other than GET/GET_LIST are also rejected. A generated GET owns its primary identity parameter, so the inherited path cannot redeclare that name; this mapping does not rename or replace GET identity.

Automator creates a route-scoped PARAMETERS DTO and OpenAPI metadata using each field's `ApiPropertyDescribe` metadata under the external path-parameter name. `read.scope.parameters` is mutually exclusive with a manual `dto[EApiDtoType.PARAMETERS]`; `autoDto[PARAMETERS]` validators remain available on the generated DTO.

At runtime, GET identity or GET_LIST query predicates are merged first, the path-derived scope is AND-merged next, and HOOKS/IAM scope is AND-merged last. Equal conditions remain equal; conflicting conditions become match-nothing criteria rather than allowing a later layer to overwrite an earlier one. Scalar leaves are normalized to explicit TypeORM `Equal(...)` predicates during these merges so TypeORM cannot silently reinterpret or drop them on relation-shaped paths. Object-valued scalar columns must use an explicit `Equal(value)` operator because an unwrapped object denotes relation or embedded criteria.

### IApiControllerPropertiesRouteBaseTransaction

Optional transaction configuration for generated CRUD routes.

```typescript
interface IApiControllerPropertiesRouteBaseTransaction {
	mode: EApiFunctionTransactionMode;
}
```

Omitted configuration and `SUPPORTS` do not open a route transaction. `REQUIRED` opens one through the controller service repository when no Automator transaction is active, `MANDATORY` requires an active owner, and `NONE` rejects active execution. A route that opens the transaction owns the `ROUTE` transaction registry and encloses request relation hydration, the generated service operation, and response relation reload. Request transformation and validation run before the transaction; response transformation, route-after subscribers, authorization result handling, and serialization run after commit.

### IApiControllerPropertiesRouteGetListQueryRequestTarget\<E, M\>

The generated GET_LIST QUERY target extends ordinary request transformers/validators with optional typed filter, order, and pagination sections.

```typescript
interface IApiControllerPropertiesRouteBaseRequestTarget<E, M extends EApiControllerGetListQueryPaginationMode = EApiControllerGetListQueryPaginationMode.PAGE> {
	transformers?: Array<TApiRequestTransformer<E>>;
	validators?: Array<IApiRequestValidator<E, M>>;
}

interface IApiControllerPropertiesRouteGetListQueryRequestTarget<E, M extends EApiControllerGetListQueryPaginationMode = EApiControllerGetListQueryPaginationMode.PAGE> extends IApiControllerPropertiesRouteBaseRequestTarget<E, M> {
	filter?: IApiControllerPropertiesRouteGetListQueryFilter<E>;
	order?: IApiControllerPropertiesRouteGetListQueryOrder<E>;
	pagination?: IApiControllerPropertiesRouteGetListQueryPagination<M>;
}

interface IApiControllerPropertiesRouteGetListQueryPagination<M extends EApiControllerGetListQueryPaginationMode = EApiControllerGetListQueryPaginationMode.PAGE> {
	mode: M;
}

interface IApiControllerPropertiesRouteGetListQueryFilter<E> {
	fields: TApiControllerGetListQueryFilterFields<E>;
	unlistedFields: EApiControllerGetListQueryUnlistedFields;
}

interface IApiControllerPropertiesRouteGetListQueryOrder<E> {
	defaultOrder?: ReadonlyArray<IApiControllerPropertiesRouteGetListQueryOrderEntry<E>>;
	fields: TApiControllerGetListQueryOrderFields<E>;
	tieBreakers?: ReadonlyArray<IApiControllerPropertiesRouteGetListQueryOrderEntry<E>>;
	unlistedFields: EApiControllerGetListQueryUnlistedFields;
}

interface IApiControllerPropertiesRouteGetListQueryOrderEntry<E> {
	direction: EFilterOrderDirection;
	field: TApiControllerReadDirectScalarField<E>;
}
```

`INHERIT` overlays metadata-enabled fields; `REJECT` creates an allowlist. Filter fields support direct scalars and one-hop to-one scalar paths, while client order fields support direct scalars only. The same immutable plan drives dynamic DTO generation, strict runtime parsing, TypeORM compilation, and OpenAPI. A manual QUERY DTO cannot be combined with these sections; manual RESPONSE DTOs remain compatible.

The `M` generic defaults to `PAGE` on the query target, pagination property, base request target, and its validators. Omitted pagination or explicit `PAGE` uses required `limit`/`page` and `IApiGetListResponseResult`. Select `EApiControllerGetListQueryPaginationMode.CURSOR` for required `limit`, optional mutually exclusive `after`/`before`, and `IApiGetListCursorResponseResult`. CURSOR mode requires an explicit order, exactly one primary column as only the final explicit tie-breaker, and described non-null direct-scalar metadata for every possible order field. Its v1 runtime supports only the exact PostgreSQL storage matrix documented in [Pagination](/docs/nestjs-crud-automator/guides/pagination); PAGE is unchanged.

`defaultOrder` and `tieBreakers` are server-owned ordered arrays. Their fields are validated against all described direct scalar entity columns, not only the client `fields` allowlist, so a UUID primary key can stabilize ordering without becoming a valid `orderBy` value. Duplicate fields within either array, invalid directions, unknown/non-scalar fields, and conflicting directions for the same field across defaults and tie-breakers fail at bootstrap.

When the client omits `orderBy`/`orderDirection`, Automator applies `defaultOrder` followed by `tieBreakers`. When the client supplies the pair, that one client order replaces all defaults and the tie-breakers are appended. Duplicate fields are removed in first-entry order, so the client entry wins when it names a tie-breaker field. Both pagination modes use this compound TypeORM order.

### IApiControllerPropertiesRouteBaseRelationsRequestLoad\<E\>

Request relation hydration configuration.

```typescript
interface IApiControllerPropertiesRouteBaseRelationsRequestLoad<E> {
	include: FindOptionsRelations<E>;
	locks?: Partial<Record<keyof FindOptionsRelations<E>, NonNullable<FindOneOptions<E>["lock"]>>>;
	relationLoadStrategy?: FindOneOptions<E>["relationLoadStrategy"];
	services?: Partial<Record<keyof FindOptionsRelations<E>, string>>;
}
```

`locks` is a direct-relation TypeORM lock passthrough. Runtime accepts `pessimistic_read` and `pessimistic_write`, requires an active Automator transaction, and acquires locks in `include` declaration order. Locked loads set `loadEagerRelations: false` to prevent implicit joins from widening the lock. A locked relation with explicit nested includes requires `relationLoadStrategy: "query"`; nested loads use the same manager without receiving an automatic lock. Lock keys must name enabled direct `include` entries.

### IApiControllerPropertiesRouteAuthentication

Authentication configuration for routes.

```typescript
interface IApiControllerPropertiesRouteAuthentication {
	guard: Type<IAuthGuard>;
	securityRequirements?: Array<IApiRouteSecurityRequirement>;
	type: EApiAuthenticationType | string;
}
```

Use `securityRequirements` for route-level Swagger security. Top-level `bearerStrategies` and `securityStrategies` are not part of the current authentication config.

### IApiRouteSecurityRequirement

One OpenAPI route security requirement group.

```typescript
interface IApiRouteSecurityRequirement {
	bearerStrategies?: Array<string>;
	cookieStrategies?: Array<string>;
	securityStrategies?: Array<string>;
}
```

Each `securityRequirements` item is one OpenAPI AND group. Multiple items are OR alternatives. Global scheme declarations remain application-owned.

### IApiControllerPropertiesRouteBaseResponse\<E, R\>

Generated route response configuration.

```typescript
interface IApiControllerPropertiesRouteBaseResponse<E, R extends EApiRouteType> {
	[EApiControllerResponseTarget.RESPONSE]?: R extends EApiRouteType.DELETE ? never : IApiControllerPropertiesRouteBaseResponseTarget<E>;
	headers?: HeadersObject;
	serialization?: IApiRouteResponseSerializationProperties;
}
```

`headers` is Swagger/OpenAPI metadata for the success response. Runtime response body transformers remain under `[EApiControllerResponseTarget.RESPONSE]`.

### IApiSubscriberFunctionExecutionContext\<E, Result, Input\>

Execution context for function subscribers.

```typescript
interface IApiSubscriberFunctionExecutionContext<E extends IApiBaseEntity, Result = unknown, Input = unknown> {
	action?: string;
	readonly ENTITY: E;
	readonly DATA: Input;
	readonly FUNCTION_TYPE: EApiFunctionType;
	result: Result;
}
```

Use `IApiSubscriberFunctionExecutionContextData<E>` to access optional `eventManager`, `repository`, and operation metadata. For transaction-expectation-aware narrowing, use `TApiSubscriberFunctionExecutionContextData<E, TTransactionExpectation>`; exact `REQUIRED` and `MANDATORY` expectations make `eventManager` required, while `SUPPORTS`, `NONE`, mixed unions, widened expectations, and the default keep it optional:

```typescript
interface IApiSubscriberFunctionExecutionContextData<E extends IApiBaseEntity> {
	eventManager?: EntityManager;
	repository: Repository<E>;
	criteria?: TApiFunctionDeleteCriteria<E> | TApiFunctionUpdateCriteria<E>;
	properties?: TApiFunctionCreateProperties<E> | TApiFunctionGetProperties<E> | TApiFunctionGetListProperties<E> | TApiFunctionGetManyProperties<E>;
	getProperties?: TApiFunctionGetProperties<E>;
	getListProperties?: TApiFunctionGetListProperties<E>;
	getManyProperties?: TApiFunctionGetManyProperties<E>;
}

type TApiSubscriberFunctionExecutionContextData<E extends IApiBaseEntity, TTransactionExpectation extends EApiFunctionSubscriberTransactionExpectation = EApiFunctionSubscriberTransactionExpectation.SUPPORTS> = IApiSubscriberFunctionExecutionContextData<E> & ([TTransactionExpectation] extends [EApiFunctionSubscriberTransactionExpectation.MANDATORY | EApiFunctionSubscriberTransactionExpectation.REQUIRED] ? { eventManager: EntityManager } : { eventManager?: EntityManager });

interface IApiSubscriberFunctionExecutionContextUpdateData<E extends IApiBaseEntity> extends IApiSubscriberFunctionExecutionContextData<E> {
	readonly currentEntity: Readonly<E>;
}
```

`TApiSubscriberFunctionBeforeUpdateContext` uses `IApiSubscriberFunctionExecutionContextUpdateData`. Only the top-level `currentEntity` object is detached and frozen; nested values retain aliases to the internal loaded entity, so mutating them can affect persistence. `result` remains the patch. The repository is bound to the active transaction manager when one exists.

### IApiSubscriberFunctionTransactionContext

Readonly context passed to post-transaction and transaction-error lifecycle hooks.

```typescript
interface IApiSubscriberFunctionTransactionContext {
	readonly DATA: Readonly<{
		events: ReadonlyArray<TApiFunctionTransactionEvent>;
		matchedEvents: ReadonlyArray<TApiFunctionTransactionEvent>;
		transaction: Readonly<IApiFunctionTransaction>;
	}>;
}
```

`transaction` contains the id and immutable `FUNCTION`, `ROUTE`, or `SCOPE` owner. `events` is the complete ordered trace; `matchedEvents` contains only events that selected the current subscriber. Events contain operation metadata only, never arguments, bodies, entities, or results. Post-commit and post-rollback hooks return `Promise<void>` and cannot replace results.

## Authorization Module Interfaces

### IApiAuthorizationModuleOptions

Authorization sources and resolver cache behavior configured by `ApiAuthorizationModule.forRoot(...)` or its async equivalent.

```typescript
interface IApiAuthorizationModuleOptions {
	cache?: TApiAuthorizationCacheOptions;
	hookPermissionSources?: ReadonlyArray<IApiHookPermissionSource>;
	iam?: IApiAuthorizationIamModuleOptions;
	principalResolver?: IApiAuthorizationPrincipalResolver;
}
```

`TApiAuthorizationCacheOptions` is a union of the source-first and bounded-memory contracts:

```typescript
interface IApiAuthorizationCacheSourceFirstOptions {
	mode?: EApiAuthorizationCacheMode.SOURCE_FIRST;
}

interface IApiAuthorizationCacheMemoryOptions {
	maxEntries: number;
	mode: EApiAuthorizationCacheMode.MEMORY;
	ttlMs: number;
}

type TApiAuthorizationCacheOptions = IApiAuthorizationCacheMemoryOptions | IApiAuthorizationCacheSourceFirstOptions;
```

Omitting `cache` or `cache.mode` selects source-first behavior. `MEMORY` must declare positive safe-integer `maxEntries` and `ttlMs`; bootstrap rejects invalid values.

The pagination generic defaults to PAGE. A validator attached to a CURSOR query target receives `TApiControllerGetListQuery<E, EApiControllerGetListQueryPaginationMode.CURSOR>` instead.
