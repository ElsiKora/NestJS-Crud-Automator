# `@ApiFunctionSubscriber`

Registers a class as a function-level subscriber for a specific entity. Subscribers receive hooks whenever observable services execute CRUD functions (`before`, `after`, and error hooks for create/update/delete/get/getList/getMany) and may observe the confirmed outer transaction result through post-commit or post-rollback hooks.

## Signature

```typescript
@ApiFunctionSubscriber<E extends IApiBaseEntity>({
	entity,
	functions?,
	priority?,
	transaction?,
}: IApiFunctionSubscriberProperties<E>)
```

## Options

| Option                    | Description                                                                                                                            |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `entity`                  | Entity the subscriber listens to. The subscriber is ignored for other entities.                                                        |
| `functions`               | Optional filters for function type or custom action. Use this when one subscriber should only observe selected hooks.                  |
| `priority`                | Higher numbers execute first. Defaults to `0`. Use this to enforce deterministic ordering between multiple subscribers.                |
| `transaction.expectation` | Optional subscriber-declared transaction expectation. `REQUIRED` and `MANDATORY` require `context.DATA.eventManager` before hooks run. |

## Usage steps

1. Mark the target service with `@ApiServiceObservable()` so hooks are emitted.
2. Extend `ApiFunctionSubscriberBase<E>` and override desired lifecycle methods (`onBeforeCreate`, `onAfterUpdate`, `onAfterErrorDelete`, `onAfterCommit`, etc.).
3. Decorate the subscriber class with `@ApiFunctionSubscriber`.
4. Register the subscriber class as a Nest provider.

## Example

```typescript
@Injectable()
@ApiFunctionSubscriber<PostEntity>({
	entity: PostEntity,
	functions: [{ type: EApiFunctionType.CREATE }],
	priority: 50,
})
export class PostSlugSubscriber extends ApiFunctionSubscriberBase<PostEntity> {
	async onBeforeCreate(context: TApiSubscriberFunctionBeforeCreateContext<PostEntity>) {
		context.result.slug = this.slugify(context.result.title);
		return context.result;
	}
}
```

Subscribers without `transaction` metadata keep the default optional `eventManager` behavior. The option is not inferred from `@ApiService`, `@ApiFunctionCustom`, or `@ApiFunctionStep` transaction settings; declare it on the subscriber when the hook itself requires a manager, and pass the same expectation to the class/context generic for TypeScript narrowing. The class/context generic is type-only and does not enable runtime enforcement without matching decorator metadata.

## Post-transaction lifecycle

`onAfterCommit` and `onAfterRollback` run once per matching subscriber after the outer `FUNCTION`, `ROUTE`, or named `SCOPE` owner confirms the database result. Their readonly `IApiSubscriberFunctionTransactionContext` exposes `DATA.transaction`, the complete ordered `DATA.events` trace, and `DATA.matchedEvents` selected for this subscriber.

```typescript
async onAfterCommit(
	context: IApiSubscriberFunctionTransactionContext,
): Promise<void> {
	await this.metrics.recordCommittedOperations(
		context.DATA.matchedEvents.length,
	);
}
```

Transaction events contain operation metadata but never arguments, bodies, entities, or results. Keep any outbox payload in application-owned state. These hooks cannot replace an operation result and do not run for nontransactional `SUPPORTS`, `NONE`, or an unknown COMMIT outcome. Error lifecycle methods are `onBeforeErrorCommit`, `onAfterErrorCommit`, `onBeforeErrorRollback`, and `onAfterErrorRollback`.
