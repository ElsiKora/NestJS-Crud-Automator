# `@ApiService`

Extends a provider with CRUD-ready methods (`create`, `update`, `delete`, `get`, `getList`, `getMany`) that mirror the DTO contracts exposed by the generated controllers. Each method routes through `@ApiFunction` so subscribers and validators behave consistently across the stack.

## Signature

```typescript
@ApiService<E extends IApiBaseEntity>({ entity, functions }: TApiServiceProperties<E>)
```

| Property                           | Type                          | Description                                                                 |
| ---------------------------------- | ----------------------------- | --------------------------------------------------------------------------- |
| `entity`                           | `new () => E`                 | Entity constructor for generated CRUD functions.                            |
| `functions[type].transaction.mode` | `EApiFunctionTransactionMode` | Optional transaction mode for a generated function. Defaults to `SUPPORTS`. |

## Requirements

- The decorated class must expose a `repository: Repository<E>` property (the decorator does not inject it automatically).
- Each generated method accepts the DTO created by the controller factory. Transaction scope is resolved internally through `ApiFunctionContextStorage`.
- Methods are defined only if the class does not already provide an implementation. For `get`, `getList`, `update`, and `delete`, however, a generated controller route accepts only the exact same-entity function produced by `@ApiService` or the matching built-in `@ApiFunction*` decorator. An undecorated selective override remains callable directly but is rejected before the Automator-managed route transaction or repository I/O. `getMany` receives the same internal capability marker but has no current generated-route runtime consumer.

This capability boundary is a 4.0 breaking change. To customize a reserved generated-route operation, remove the override and use subscribers, apply the matching built-in decorator knowing that it owns the resulting CRUD implementation, or expose domain-specific behavior through `@ApiFunctionCustom`/a custom route. CREATE remains special, but generated CREATE preflights the protected `get` required for its post-create read. See [Migrating to 4.0](/docs/nestjs-crud-automator/guides/migrating-to-4-0).

## Generated methods

| Method    | Parameters        | Description                                                                             |
| --------- | ----------------- | --------------------------------------------------------------------------------------- |
| `create`  | `(dto)`           | Persists a new entity and triggers subscriber hooks.                                    |
| `update`  | `(criteria, dto)` | Applies updates with full DTO validation and subscriber lifecycle.                      |
| `delete`  | `(criteria)`      | Removes records and notifies subscribers.                                               |
| `get`     | `(properties)`    | Loads a single entity, throwing typed HTTP errors on failure.                           |
| `getMany` | `(properties)`    | Loads multiple records by identifiers or criteria, returning `[]` when nothing matches. |
| `getList` | `(properties)`    | Returns paginated collections with relations populated as requested.                    |

## Example

```typescript
import { Injectable } from "@nestjs/common";
import { InjectRepository } from "@nestjs/typeorm";
import { Repository } from "typeorm";
import { ApiService, ApiServiceBase, EApiFunctionTransactionMode, EApiFunctionType } from "@elsikora/nestjs-crud-automator";
import { UserEntity } from "./user.entity";

@Injectable()
@ApiService<UserEntity>({
	entity: UserEntity,
	functions: {
		[EApiFunctionType.CREATE]: {
			transaction: { mode: EApiFunctionTransactionMode.REQUIRED },
		},
	},
})
export class UserService extends ApiServiceBase<UserEntity> {
	constructor(
		@InjectRepository(UserEntity)
		public repository: Repository<UserEntity>,
	) {
		super();
	}
}
```

The `functions` map accepts generated function types (`CREATE`, `UPDATE`, `DELETE`, `GET`, `GET_LIST`, `GET_MANY`). Omitted entries keep the default `SUPPORTS` transaction mode. It does not configure `CUSTOM`; use `@ApiFunctionCustom` for custom service commands.
