# Function Decorators

CRUD and custom function decorators wrap repository operations inside services, applying DTO validation, subscriber hooks, transaction boundaries, and standardized error handling for CRUD and custom service actions. `@ApiFunctionStep` is the lightweight exception: it only wraps an internal helper with transaction context and does not run DTO validation, subscribers, action routing, Swagger, or authorization metadata.

## Transaction modes

All built-in function decorators, `@ApiFunctionCustom`, and `@ApiFunctionStep` support `transaction.mode`. Step transaction modes only control transaction context for the helper body; they do not add subscriber, action, route, Swagger, or authorization metadata.

```typescript
@ApiFunction<PostEntity>({
	entity: PostEntity,
	type: EApiFunctionType.CREATE,
	transaction: { mode: EApiFunctionTransactionMode.REQUIRED },
})
async createPost(properties: TApiFunctionCreateProperties<PostEntity>) {
	return {} as PostEntity;
}
```

- `SUPPORTS` is the default. It joins an active `ApiFunction` transaction when one exists and otherwise runs without opening one.
- `REQUIRED` joins an active transaction or opens a new TypeORM transaction for the full decorated function lifecycle.
- `MANDATORY` requires an active transaction and fails before the operation when none exists.
- `NONE` requires no active transaction and fails before the operation when one exists.

Transaction managers are no longer public method arguments. Decorated methods keep clean signatures; subscribers receive the active manager on `context.DATA.eventManager`, and custom functions can use `this.getApiFunctionContext()` from `ApiServiceBase` to access `context.operations` and transactional repositories.

Generated controller routes preflight exact function capability for GET, GET_LIST, GET_MANY, UPDATE, and DELETE. Generated CREATE also preflights its protected post-create GET, and UPDATE preflights a protected reload GET when configured. The bound method must come from the matching built-in decorator for the same entity; arbitrary same-named overrides, accessors, and instance shadows are rejected before the Automator-managed route transaction or repository I/O. Direct service calls are not capability-gated. This is the intentional 4.0 migration boundary documented in [Migrating to 4.0](/docs/nestjs-crud-automator/guides/migrating-to-4-0).

Use `@ApiFunctionStep` for private/protected/public helper methods that need ApiFunction transaction semantics and context. A step is not a custom action: it does not create function subscriber hooks, route metadata, Swagger metadata, or authorization action identity. Inside a step, use `this.getApiFunctionStepContext()` for the active `eventManager`, entity `repository`, and `getRepository()`.

## Usage guidelines

1. Ensure the decorated service exposes a `repository` property compatible with TypeORM repositories.
2. Choose the specific decorator when you want direct control, or use `@ApiFunction` with `type` to route automatically.
3. Use `transaction.mode` and nested decorated calls to share transaction scope. Do not pass `EntityManager` as a public method argument.
