# `@ApiFunctionCreate`

Decorates a service method so it creates a new entity instance, executes before/after function subscribers, and propagates typed HTTP errors. It uses the repository on `this` or the ambient transaction context selected by `transaction.mode`.

## Signature

```typescript
@ApiFunctionCreate<E extends IApiBaseEntity>(
	properties: IApiFunctionProperties<E>
): (target, propertyKey, descriptor) => PropertyDescriptor
```

Decorated methods receive the shape `create(dto: TApiFunctionCreateProperties<E>): Promise<E>`. Transaction managers are resolved internally and exposed to subscribers through `context.DATA.eventManager`.

## Behavior

- Instantiates the entity to collect metadata and subscriber context.
- Executes `onBeforeCreate` subscribers; if a handler returns a DTO, it replaces the incoming body.
- Persists the entity using `repository.save` or the active transaction manager repository, and only inserts: a save that would update, remove, soft remove or recover a row that already exists, or would not insert the row it was given, answers `409` with `{ENTITY}_DUPLICATE_KEY` and `details: { type: "UNIQUE_VIOLATION" }` before TypeORM writes. A related object that holds only its key, or the values its row already has, still links that row. To do this, the decorator adds an internal TypeORM subscriber to the `DataSource` of the repository; it acts only on the save of the create function, so other saves, also in the same transaction or on the same connection, are not refused. A TypeORM subscriber or entity listener of your application that changes an existing related object during that save is outside the rule: TypeORM writes that change as an UPDATE without a before event, and the row changes (see [Creating with Relations](/docs/nestjs-crud-automator/guides/relations#creating-with-relations)).
- Executes `onAfterCreate` subscribers with the persisted entity.
- When a generated CREATE route calls it with the route's body, reports to that route the key TypeORM saved for the inserted row, before `onAfterCreate` runs. The route reads its response through GET by that key, so neither the result of `onAfterCreate` nor a change it makes to `context.result` reaches that response.
- On errors, runs `onBeforeErrorCreate` or `onAfterErrorCreate` subscribers and rethrows `HttpException` instances or wraps unknown errors in `InternalServerErrorException`.

## Example

```typescript
export class PostService {
	constructor(public repository: Repository<PostEntity>) {}

	@ApiFunctionCreate<PostEntity>({
		entity: PostEntity,
		transaction: { mode: EApiFunctionTransactionMode.REQUIRED },
	})
	async createPost(properties: TApiFunctionCreateProperties<PostEntity>) {
		// Implementation replaced by decorator
		return {} as PostEntity;
	}
}
```
