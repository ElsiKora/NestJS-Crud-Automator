# `@ApiControllerSecurable`

Decorator without options that enables the authorization pipeline for a controller. When omitted, `ApiAuthorizationGuard` short-circuits and no hooks or IAM evaluation runs.

## Signature

```typescript
@ApiControllerSecurable()
```

## Behavior

- Sets `CONTROLLER_API_DECORATOR_CONSTANT.SECURABLE_METADATA_KEY` to `true`.
- Does not choose `hooks` vs `iam`.
- Does not declare `policyNamespace`, `resourceDefinition`, sources, or fallback behavior.
- Must be paired with `@ApiController({ authorization: ... })` on any secured controller.
- Requires custom `@ApiMethod(...)` and `@ApiRouteCustom(...)` handlers on the controller and its base classes to declare `resource.action` and a `resource.entity` equal to the controller entity.
- Is validated at bootstrap: missing `authorization` on a securable controller and a custom route that breaks the rule above are configuration errors.
- Fails startup in an application that does not import `ApiAuthorizationModule`, on a bare `@Controller` too.
- Attaches `ApiAuthorizationHandlerGuard` to the class, which denies per request a handler that does not go through authorization.
- Refuses at bootstrap any served handler that skips authorization, such as a plain `@Get`, a `@MessagePattern` handler or a handler bound in a constructor. See [Every Served Route Goes Through Authorization](/docs/nestjs-crud-automator/guides/authorization#every-served-route-goes-through-authorization).

## Example

```typescript
@ApiControllerSecurable()
@ApiController<UserEntity>({
	authorization: {
		defaultMode: EApiAuthorizationMode.HOOKS,
	},
	entity: UserEntity,
	path: "users",
	routes: {},
})
export class UserController {}
```

## Notes

- Keep this decorator even in IAM mode.
- Use route-level `security.authorization.mode` inside `@ApiController(...)` when a specific route must differ from the controller default.
- Each route still runs in exactly one authorization mode.
- Auto-generated CRUD routes receive `metadata.route.type`; bespoke `@ApiMethod(...)` routes must provide `metadata.resource.action` explicitly, and run in `authorization.defaultMode` without `metadata.security.authorization.mode`.
