# `@ApiController`

Generates CRUD endpoints, DTOs, Swagger metadata, guards, and request/response pipelines for a given entity. The decorator delegates all heavy lifting to `ApiControllerFactory`, so the controller remains a thin shell that receives prebuilt methods and DTO schemas.

## Signature

```typescript
@ApiController<E extends IApiBaseEntity>(options: IApiControllerProperties<E>)
```

## Options

| Option   | Type                                                                  | Description                                                                                              |
| -------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `entity` | `IApiBaseEntity`                                                      | Entity class used to inspect columns, relations, and repository metadata.                                |
| `name`   | `string`                                                              | Optional human-friendly resource label surfaced in Swagger summaries. Defaults to the entity name.       |
| `path`   | `string`                                                              | Overrides the route prefix if the controller path differs from the entity plural name.                   |
| `routes` | `Partial<Record<EApiRouteType, TApiControllerPropertiesRoute<E, R>>>` | Per-route configuration covering security, DTO sources, request/response metadata, and generation flags. |

## Route configuration

Each route entry can be described in two ways:

- **Auto DTO mode (`autoDto`)** – Add validators to generated DTOs. Field exposure, requiredness, nullable state, guards, filters, and response visibility belong to entity `@ApiPropertyDescribe({ properties: ... })` metadata.
- **Manual DTO mode (`dto`)** – Supply custom DTO classes when manual control is preferred. The decorator still wires up Swagger and validation.

Routes also accept:

- `security.authentication` – bearer/security schemes and custom guards. `type` is required and may be an `EApiAuthenticationType` value or a project-specific string.
- `security.authorization` – authorization mode and optional per-route overrides.
- `request` / `response` – target-scoped pipe and serializer overrides for each CRUD action.
- `generation.decorators` – additional method or property decorators applied after the factory finishes.
- `generation.isEnabled: false` – disables a route. Omitting a route key does not disable it; the factory generates omitted routes with default configuration.
- `generation.shouldWriteToController: false` – keeps the generated method and DTO metadata but skips applying Nest route decorators, so you can expose the method manually.

## Example

```typescript
@ApiController<UserEntity>({
	entity: UserEntity,
	name: "Users",
	path: "users",
	routes: {
		[EApiRouteType.CREATE]: {
			security: {
				authentication: {
					type: EApiAuthenticationType.USER,
					guard: JwtAuthGuard,
					bearerStrategies: ["jwt"],
				},
			},
		},
		[EApiRouteType.GET_LIST]: {
			autoDto: {
				[EApiDtoType.QUERY]: {
					validators: [
						{
							constraintClass: HasAtLeastOnePropertyValidator,
							options: ["username", "email"],
						},
					],
				},
			},
		},
		[EApiRouteType.DELETE]: {
			generation: { isEnabled: false },
		},
	},
})
export class UserController {}
```

## Integration tips

- Combine with `@ApiControllerObservable` to emit route subscriber hooks.
- Add `@ApiControllerSecurable` when authorization policies should execute before each route.
- Align `routes` with the DTO metadata defined on the entity (`@ApiPropertyDescribe`) for consistent validation.
