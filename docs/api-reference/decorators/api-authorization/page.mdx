# Authorization Decorators

Authorization decorators register hooks-mode policy classes and expose guard-evaluated decisions to custom route parameters. Policies allow entity-specific RBAC, multi-tenant filters, and custom assertions, while decision injection keeps raw HTTP requests out of controllers.

## Available decorators

| Decorator                   | Purpose                                                                        | Reference                                                                                                                                                                                              |
| --------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@ApiAuthorizationDecision` | Injects the authorization decision already attached by the Automator guard.    | [/docs/nestjs-crud-automator/api-reference/decorators/api-authorization/api-authorization-decision](/docs/nestjs-crud-automator/api-reference/decorators/api-authorization/api-authorization-decision) |
| `@ApiAuthorizationPolicy`   | Registers a policy class with optional priority, ID, and description metadata. | [/docs/nestjs-crud-automator/api-reference/decorators/api-authorization/api-authorization-policy](/docs/nestjs-crud-automator/api-reference/decorators/api-authorization/api-authorization-policy)     |

## Typical workflow

1. Implement a policy by extending `ApiAuthorizationPolicyBase`.
2. Decorate the class with `@ApiAuthorizationPolicy`, providing the entity and optional metadata.
3. Import `ApiAuthorizationModule` so the policy registry discovers and executes policies for each secured controller, using `forRoot(...)` or `forRootAsync(...)` depending on whether your resolver and permission sources are plain values or Nest providers.
4. Use `@ApiAuthorizationDecision()` only when a custom handler needs the decision produced by that existing authorization pipeline.
