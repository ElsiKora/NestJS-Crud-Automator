# `@ApiPropertyDescribe`

Central metadata decorator for entity properties. The metadata drives auto-generated DTOs, validation rules, Swagger schemas, filters, and route-specific exposure metadata.

## Signature

```typescript
@ApiPropertyDescribe(properties: TApiPropertyDescribeProperties)
```

## Key configuration

| Option               | Description                                                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`               | Required `EApiPropertyDescribeType` (STRING, NUMBER, BOOLEAN, DATE, ENUM, OBJECT, UUID, RELATION). Governs downstream validators and Swagger schema.                                                       |
| `description`        | Human-readable field description appended to DTOs and Swagger docs.                                                                                                                                        |
| `exampleValue`       | Example displayed in Swagger for describe metadata that supports it. Current entity describe types include it for string and number metadata; manual property decorators expose their own example options. |
| `isAutoDtoEnabled`   | Optional property-wide auto-generation switch. Omitted or `true` keeps normal generation; `false` keeps metadata but hides the property from every generated DTO and its generated Swagger/query surfaces. |
| `isNullable`         | Marks the property as nullable in generated DTO and Swagger metadata.                                                                                                                                      |
| `properties`         | Per-route DTO controls keyed by `EApiRouteType`, then `EApiDtoType` (`BODY`, `PARAMETERS`, `QUERY`, `RESPONSE`).                                                                                           |
| Type-specific fields | Each type exposes additional options (e.g., `minLength`, `format`, `enum`, `identifier`, `minimum`, `maximum`).                                                                                            |

The decorator stores values in `MetadataStorage`, allowing factory pipelines to retrieve them even when DTOs are generated lazily.

## Property-wide auto DTO control

Use `isAutoDtoEnabled: false` for a persisted or otherwise described property that must remain server-side:

```typescript
@Column({ default: false, type: "boolean" })
@ApiPropertyDescribe({
	description: "Internal eligibility flag",
	isAutoDtoEnabled: false,
	type: EApiPropertyDescribeType.BOOLEAN,
})
internalEligibility!: boolean;
```

The property remains in `MetadataStorage`, keeps its TypeORM mapping, and can be represented by a manual DTO. Automator omits it from generated BODY, PARAMETERS, QUERY, and RESPONSE DTOs, generated Swagger relation components, and metadata-driven or typed client filter/order fields. Route- or DTO-level `isEnabled: true`, generated GET identity, and `read.scope.parameters` cannot re-enable it.

An explicit `@ApiPropertyCopy` may deliberately copy the hidden source property into a manual DTO. That bypasses only this global auto-generation boundary; the source metadata's remaining route/DTO, guard, and validation rules still apply. PAGE server-only `defaultOrder` and `tieBreakers` may use a hidden described scalar, while CURSOR rejects it because cursor ordering requires generated response exposure.

For built-in string formats, `GetDefaultStringFormatProperties(format)` returns the package defaults for `description`, `exampleValue`, `minLength`, `maxLength`, and `pattern`. Spread those defaults when you want examples to stay aligned with the validator for formats such as email, URL, UUID, slug, or API key.

## Relation metadata

`EApiPropertyDescribeType.RELATION` should be used together with a TypeORM relation decorator such as `@ManyToOne(() => CurrencyEntity)`. The generator reads TypeORM relation metadata to identify the target entity.

For response DTOs, relation references are rendered as a small object with an `id` field. The nested identifier description is relation-aware:

```typescript
class DepositEntity {
	@ManyToOne(() => CurrencyEntity)
	@ApiPropertyDescribe({
		description: "currency",
		type: EApiPropertyDescribeType.RELATION,
	})
	currency!: CurrencyEntity;
}
```

This produces Swagger descriptions like:

```typescript
currency.description === "DepositEntity currency";
currency.id.description === "DepositEntity currency identifier";
```

For request DTOs, generated relation fields keep the existing UUID reference schema. Route relation loading can still be configured to read another `reference.key` at runtime, but that does not change generated DTO metadata.

## Example

```typescript
@Column()
@ApiPropertyDescribe({
	type: EApiPropertyDescribeType.STRING,
	format: EApiPropertyStringType.EMAIL,
	...GetDefaultStringFormatProperties(EApiPropertyStringType.EMAIL),
	properties: {
		[EApiRouteType.CREATE]: {
			[EApiDtoType.BODY]: { isRequired: true },
			[EApiDtoType.RESPONSE]: { isExpose: true, isResponse: true },
		},
		[EApiRouteType.GET_LIST]: {
			[EApiDtoType.QUERY]: { isEnabled: true, useAsOrderByFilter: true },
			[EApiDtoType.RESPONSE]: { isExpose: true, isResponse: true },
		},
	},
})
email!: string;
```

`isExpose` is only valid when `isResponse: true`; request DTOs use `isEnabled`, `isRequired`, and `isNullable` instead. Guard classes on metadata select generated DTO variants; they are not per-request role checks.

## Best practices

- Apply `@ApiPropertyDescribe` to every persistent column so DTOs remain in sync with the entity model.
- Use `CREATED_AT`, `RECEIVED_AT`, and `UPDATED_AT` only for server-owned infrastructure timestamps. Generated write DTO exclusion follows these identifiers rather than property names; use `DATE` for writable business dates.
- Pair it with the property-level decorators (`@ApiPropertyString`, `@ApiPropertyNumber`, etc.) for manual DTOs or overrides.
- Keep string and number `exampleValue` in sync with `pattern` or range rules to avoid validation errors during bootstrapping.
