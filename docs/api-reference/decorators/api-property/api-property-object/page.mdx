# `@ApiPropertyObject`

Describes nested object fields in DTOs. Works with single DTO types, arrays, polymorphic discriminators, or dynamically generated DTOs. Handles both Swagger documentation and `class-validator`/`class-transformer` setup.

## Signature

```typescript
@ApiPropertyObject(properties: TApiPropertyObjectProperties)
```

## Key options

| Option                                             | Description                                                                                                                                                                  |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`                                             | Either a single DTO class, an array of DTOs (for polymorphic `oneOf`), or a dynamically generated DTO registry.                                                              |
| `discriminator`                                    | Optional `{ propertyName, mapping, shouldKeepDiscriminatorProperty }` enabling OpenAPI discriminators and runtime validation. Required when supplying multiple types.        |
| `shouldValidateNested`                             | Adds `ValidateNested` and `Type` decorators so nested objects are validated/serialized. Mandatory for request-side arrays.                                                   |
| `isArray`, `minItems`, `maxItems`, `isUniqueItems` | Enables arrays with validation. A request array must declare all three bounds; a response array (`isResponse: true`) may leave them out, and the schema then publishes none. |
| `additionalProperties`                             | OpenAPI `boolean`, `SchemaObject`, or `ReferenceObject`; literal `true` has request runtime behavior described below.                                                        |

## Behavior

- Calls `RegisterAutoDtoChild` so generated DTOs are discoverable inside auto contexts.
- Emits `@ApiProperty` with `type`, `oneOf`, or `discriminator` metadata. Allows arrays and `additionalProperties`.
- On typed nested request DTOs, literal `additionalProperties: true` accepts and strips undeclared keys before validation. `SchemaObject` and `ReferenceObject` values remain OpenAPI-only.
- Adds `Type`, `ValidateNested`, presence guards, `IsObject`, `IsArray`, `ArrayMinSize`, `ArrayMaxSize`, and `ArrayNotEmpty` as needed.
- A request array that leaves out `minItems`, `maxItems` or `isUniqueItems`, which the types forbid but JavaScript or `any` allows, fails at decoration with `ApiPropertyObject error: Request array property '<Dto>.<name>' must declare ...`, naming each missing bound. On any array, a `minItems` or `maxItems` that is not a non-negative integer, such as `NaN` from `Number(process.env.X)`, an `isUniqueItems` that is not a boolean, or an `isArray` that is not a boolean fails at decoration too.
- Supports polymorphic validation via `MustMatchOneOfSchemasValidator`.
- Adds `ApiResponseProperty`, `Expose`, or `Exclude` for response DTOs.
- When a manual DTO is nested inside an auto-generated DTO, creates context-specific wrapper schemas so request and response metadata do not collide.
- Leaves `type: Object` as a free-form object and does not wrap it as a contextual DTO; its free-form behavior is unaffected by `additionalProperties` request stripping.
- When `discriminator` is used, every variant DTO must declare the discriminator property with the usual property decorators, such as `ApiPropertyEnum` or `ApiProperty`.

`@ApiPropertyObject` discriminators apply to nested object properties inside a DTO. For a flat custom route body union or flat polymorphic custom route response, use root-level `ApiRouteCustom.dto.body` and `ApiRouteCustom.response` discriminators instead.

## Example

```typescript
class AddressDto {
	/* ... */
}
class BillingAddressDto extends AddressDto {
	@ApiProperty()
	type!: string;
}
class ShippingAddressDto extends AddressDto {
	@ApiProperty()
	type!: string;
}

class OrderDto {
	@ApiPropertyObject({
		entity: OrderEntity,
		description: "Address payload",
		type: [BillingAddressDto, ShippingAddressDto],
		discriminator: {
			propertyName: "type",
			mapping: {
				billing: BillingAddressDto,
				shipping: ShippingAddressDto,
			},
			shouldKeepDiscriminatorProperty: true,
		},
		shouldValidateNested: true,
	})
	address!: BillingAddressDto | ShippingAddressDto;
}
```

## Nested manual DTOs in auto DTOs

Manual DTOs decorated with `@ApiPropertyObject` and the other `@ApiProperty*` decorators can be reused inside auto-generated body and response DTOs. When the same manual DTO appears in multiple generated contexts, the library materializes path-specific wrapper classes for Swagger, validation, and serialization metadata.

For example, a `PolicyDocumentDto` nested at `document` can produce separate schemas such as `PolicyCreateBodyDocumentDTO` and `PolicyGetResponseDocumentDTO` for a `PolicyController`. Nested child DTOs receive path-aware names as well, which keeps body and response schemas independent while preserving the original manual DTO contract.

Neutral manual DTO fields do not need to be marked with `isResponse: true` just to serialize in generated response DTOs. `isResponse: true` remains reserved for explicit response-only fields and still emits `ApiResponseProperty`.

## Migration Notes

### 5.0.0

- A request array without `minItems`, `maxItems` or `isUniqueItems` fails at decoration. Before, it decorated and its validators then rejected every value. Declare all three bounds, or mark a response-only property `isResponse: true`.
- A `minItems` or `maxItems` that is not a non-negative integer, or an `isUniqueItems` that is not a boolean, fails at decoration on request and response arrays, and so does an `isArray` that is not a boolean. Before, such a bound decorated and could reject every request value, such an `isUniqueItems` only reached the OpenAPI schema, and such an `isArray` skipped the bound checks. Pass valid values; a number read from the environment needs a default.
- `TApiPropertyObjectProperties` includes `TApiPropertyBaseResponseArrayProperties`, a response array whose bounds are optional. Code that reads the options and narrows on `isArray === true` gets `minItems`, `maxItems` and `isUniqueItems` as possibly `undefined`; also check `isResponse !== true` to read the required bounds of a request array.
