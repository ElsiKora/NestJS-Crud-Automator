# `@ApiPropertyObject`

Describes nested object fields in DTOs. Works with single DTO types, arrays, polymorphic discriminators, or dynamically generated DTOs. Handles both Swagger documentation and `class-validator`/`class-transformer` setup.

## Signature

```typescript
@ApiPropertyObject(properties: TApiPropertyObjectProperties)
```

## Key options

| Option                                             | Description                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`                                             | Either a single DTO class, an array of DTOs (for polymorphic `oneOf`), or a dynamically generated DTO registry.                                                                                                                                                                                                                     |
| `discriminator`                                    | Optional `{ propertyName, mapping, shouldKeepDiscriminatorProperty }` enabling OpenAPI discriminators and runtime validation. Required when supplying multiple types.                                                                                                                                                               |
| `shouldValidateNested`                             | Adds `ValidateNested` against the declared class. Mandatory for request arrays of a class. Refused on a [free-form value](#free-form-objects).                                                                                                                                                                                      |
| `isArray`, `minItems`, `maxItems`, `isUniqueItems` | Enables arrays with validation. `isUniqueItems: true` rejects items equal by value on a request array; see [Unique Items](/docs/nestjs-crud-automator/guides/validation#unique-items). A request array must declare all three bounds; a response array (`isResponse: true`) may leave them out, and the schema then publishes none. |
| `additionalProperties`                             | OpenAPI `boolean`, `SchemaObject`, or `ReferenceObject`; literal `true` has request runtime behavior described below.                                                                                                                                                                                                               |

## Behavior

- Calls `RegisterAutoDtoChild` so generated DTOs are discoverable inside auto contexts.
- Emits `@ApiProperty` with `type`, `oneOf`, or `discriminator` metadata. Allows arrays and `additionalProperties`.
- On typed nested request DTOs, literal `additionalProperties: true` accepts and strips undeclared keys before validation. `SchemaObject` and `ReferenceObject` values remain OpenAPI-only.
- Adds `Type`, `ValidateNested`, presence guards, `IsObject`, `IsArray`, `ArrayMinSize`, `ArrayMaxSize`, and `ArrayNotEmpty` as needed.
- A request array that leaves out `minItems`, `maxItems` or `isUniqueItems`, which the types forbid but JavaScript or `any` allows, fails at decoration with `ApiPropertyObject error: Request array property '<Dto>.<name>' must declare ...`, naming each missing bound. On any array, a `minItems` or `maxItems` that is not a non-negative integer, such as `NaN` from `Number(process.env.X)`, an `isUniqueItems` that is not a boolean, or an `isArray` that is not a boolean fails at decoration too.
- Supports polymorphic validation via `MustMatchOneOfSchemasValidator`.
- Registers every class of an array `type` and every dynamically generated variant as an extra model of the DTO that holds the property, so each `oneOf` reference resolves to a component of the OpenAPI document. A Swagger mapped type (`PickType`, `OmitType`, `PartialType`, `IntersectionType`) copies the property and not the extra models, so a mapped class that keeps such a property declares `@ApiExtraModels(...)` with the variant classes.
- Adds `ApiResponseProperty`, `Expose`, or `Exclude` for response DTOs.
- When a manual DTO is nested inside an auto-generated DTO, creates context-specific wrapper schemas so request and response metadata do not collide.
- Leaves `type: Object` as a [free-form object](#free-form-objects) and does not wrap it as a contextual DTO; its free-form behavior is unaffected by `additionalProperties` request stripping.
- When `discriminator` is used, every variant DTO must declare the discriminator property with the usual property decorators, such as `ApiPropertyEnum` or `ApiProperty`.
- Leaving `shouldKeepDiscriminatorProperty` out means keep, on a request and a response alike. See [Keeping the discriminator](#keeping-the-discriminator).

`@ApiPropertyObject` discriminators apply to nested object properties inside a DTO. For a flat custom route body union or flat polymorphic custom route response, use root-level `ApiRouteCustom.dto.body` and `ApiRouteCustom.response` discriminators instead.

## Example

```typescript
class AddressDto {
	/* ... */
}
class BillingAddressDto extends AddressDto {
	@ApiProperty()
	type!: string;
}
class ShippingAddressDto extends AddressDto {
	@ApiProperty()
	type!: string;
}

class OrderDto {
	@ApiPropertyObject({
		entity: OrderEntity,
		description: "Address payload",
		type: [BillingAddressDto, ShippingAddressDto],
		discriminator: {
			propertyName: "type",
			mapping: {
				billing: BillingAddressDto,
				shipping: ShippingAddressDto,
			},
			shouldKeepDiscriminatorProperty: true,
		},
		shouldValidateNested: true,
	})
	address!: BillingAddressDto | ShippingAddressDto;
}
```

## Free-form objects

A property with `type: Object`, or with an explicit `type: undefined`, declares no class for its value. Leaving the `type` key out does not compile. On a request the value keeps its keys at any depth, apart from the ones a `ValidationPipe` always removes:

- It gets no `ValidateNested`. A host `ValidationPipe` with `whitelist: true` keeps every key, and `forbidNonWhitelisted: true` rejects none of them, including a nested key. The pipe still applies to the keys beside the property, so a junk key next to `meta` in a declared item is stripped or rejected as usual.
- Any Nest `ValidationPipe` removes `__proto__`, `prototype` and `constructor` at any depth, whatever the decorator, and on Fastify the body parser answers `400` for `__proto__` before the pipe runs. Other keys pass through the pipe, `toString` and `valueOf` included.
- It takes no `shouldValidateNested`, on a single property or an array. `true` does not compile, and from JavaScript or `any` it fails at decoration naming the class and property, because there is no class to validate against.
- The value must be an object. A single property answers `400` with `single must be an object`, and an array answers `400` with `each value in payloads must be an object` for an item that is a number, a string, `null` or an array.
- `isUniqueItems: true` applies as on every request array: `[{ "id": 1 }, { "id": 1 }]` answers `400` with `payloads must not contain duplicate items`. Items compare on all their keys, by value at any depth and whatever their key order, so `{ "a": 1, "b": 2 }` and `{ "b": 2, "a": 1 }` are equal. Such an array also answers `400` for an item that nests past 64 levels. See [Unique Items](/docs/nestjs-crud-automator/guides/validation#unique-items).
- Nothing else inside the value is validated, so check it in the handler, or declare a class and pass it as `type` when its shape is known.

`Object` has no place in a list of classes either. `type: [Object]` does not compile, and from JavaScript or `any` it fails at decoration naming the class and property, because every request would fail. Use `type: Object`.

A response value comes back as it stands, also through a `ClassSerializerInterceptor`, with one exception: under `@SerializeOptions({ strategy: "excludeAll" })` the interceptor empties it at every level, so `{ "id": 1 }` comes back as `{}`. Under that strategy class-transformer rebuilds each plain object from its exposed properties, and a plain object has none. A `@Transform` cannot prevent it, since class-transformer runs its default transformation on the result. Declare a class for the value, or leave `excludeAll` off that route.

The OpenAPI schema publishes an open object: `{ "type": "object" }` for a single property and `{ "type": "array", "items": { "type": "object" }, "minItems": 0, "maxItems": 5, "uniqueItems": true }` for an array, with no `properties`. `additionalProperties` appears only when the option is set.

A raw `class-validator` `@ValidateNested()` without `@Type` has no such handling, so a plain object under it is still emptied by `whitelist: true` and rejected by `forbidNonWhitelisted: true`. Use `@ApiPropertyObject({ type: Object })` for a free-form value, or add `@Type` with a class for a declared one.

## Keeping the discriminator

`shouldKeepDiscriminatorProperty` follows one rule: only `false` removes the property. Leaving it out is the same as `true`, here and on a root-level [`@ApiRouteCustom` discriminator](/docs/nestjs-crud-automator/api-reference/decorators/api-method/api-route-custom#root-level-discriminated-dtos).

- On a request property, `false` fails at decoration with `ApiPropertyObject error: Request property '<Dto>.<name>' cannot set 'discriminator.shouldKeepDiscriminatorProperty' to false`. The value is transformed before it is validated, so a removed discriminator could never pass `MustMatchOneOfSchemasValidator` or the variant's own field. A property counts as a request property unless it has `isResponse: true`, which a generated response DTO sets on its own, so a neutral manual DTO needs `isResponse: true` to set `false`. Entity metadata that sets `false` fails at import as soon as a generated write body applies it, and write routes are on unless a controller disables them. A property that is only read disables each of those bodies with `properties[route][BODY].isEnabled: false`. Setting `isResponse: true` there instead decorates, and then every write answers `400`.
- On a response property, `false` removes the property from the response of generated and custom routes. The variant's field stays in the OpenAPI schema, so make it optional there. `class-transformer` also deletes the property from the object the handler returned, and `instanceToPlain`, which a host `ClassSerializerInterceptor` calls, writes it back into the response.

## Nested manual DTOs in auto DTOs

Manual DTOs decorated with `@ApiPropertyObject` and the other `@ApiProperty*` decorators can be reused inside auto-generated body and response DTOs. When the same manual DTO appears in multiple generated contexts, the library materializes path-specific wrapper classes for Swagger, validation, and serialization metadata.

For example, a `PolicyDocumentDto` nested at `document` can produce separate schemas such as `PolicyCreateBodyDocumentDTO` and `PolicyGetResponseDocumentDTO` for a `PolicyController`. Nested child DTOs receive path-aware names as well, which keeps body and response schemas independent while preserving the original manual DTO contract.

Neutral manual DTO fields do not need to be marked with `isResponse: true` just to serialize in generated response DTOs. `isResponse: true` remains reserved for explicit response-only fields and still emits `ApiResponseProperty`.

## Migration Notes

### 5.0.0

- A request array without `minItems`, `maxItems` or `isUniqueItems` fails at decoration. Before, it decorated, a missing `minItems` or `maxItems` then rejected every value, and a missing `isUniqueItems` only left `uniqueItems` out of the schema. Declare all three bounds, or mark a response-only property `isResponse: true`.
- A `minItems` or `maxItems` that is not a non-negative integer, or an `isUniqueItems` that is not a boolean, fails at decoration on request and response arrays, and so does an `isArray` that is not a boolean. Before, such a bound decorated and could reject every request value, such an `isUniqueItems` only reached the OpenAPI schema, and such an `isArray` skipped the bound checks. Pass valid values; a number read from the environment needs a default.
- A free-form request value (`type: Object` or `type: undefined`) keeps its keys, apart from the ones a `ValidationPipe` always removes. Before, `shouldValidateNested: true`, which every request array needs, attached `ValidateNested` to it: under a `ValidationPipe` with `whitelist: true`, `[{ "id": 1 }, { "id": 2 }]` reached the handler as `[{}, {}]`, and with `forbidNonWhitelisted: true` each key answered `400`. Code that relied on the emptied value must drop those keys itself. A free-form array item that is not an object now answers `400` with `each value in <name> must be an object`, which replaces the `nested property` message for a number, a string or `null`, and also covers a nested array such as `[[{ "id": 1 }]]`, which passed before.
- `shouldValidateNested: true` on a free-form property does not compile and fails at decoration. Remove it: a free-form array no longer needs it. `type: [Object]`, which compiled and answered `500` on every request, fails the same way; use `type: Object`.
- `shouldKeepDiscriminatorProperty: false` on a request property fails at decoration, naming the class and property. Before, it decorated and rejected every body that carried it with `<name> has invalid discriminator value for field '<field>'`. Remove the option; to drop the value before it reaches the service, do it in a request transformer or in the handler. On entity metadata that also serves GET, removing it brings the discriminator back into the response; to keep GET as it was, leave `false` and set `properties[route][BODY].isEnabled: false` on each write route. A read-only property with `false` now fails at import unless its write bodies are disabled.
- A discriminator with `shouldKeepDiscriminatorProperty` left out keeps the property. Before, class-transformer removed it, so such a request property rejected every body that carried it, and such a response property left the discriminator out of the response. A response that must keep leaving it out sets `shouldKeepDiscriminatorProperty: false` and `isResponse: true`.
- `TApiPropertyObjectProperties` includes `TApiPropertyBaseResponseArrayProperties`, a response array whose bounds are optional. Code that reads the options and narrows on `isArray === true` gets `minItems`, `maxItems` and `isUniqueItems` as possibly `undefined`; also check `isResponse !== true` to read the required bounds of a request array.
