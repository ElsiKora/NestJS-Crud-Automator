# Property Decorators

Property decorators describe DTO fields, attach Swagger metadata, and generate class-validator/class-transformer rules consistent with the entity definition.

## Available decorators

| Decorator              | Purpose                                                                        | Reference                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@ApiPropertyDescribe` | Central metadata source used by auto DTO generation.                           | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-describe](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-describe) |
| `@ApiPropertyBoolean`  | Applies boolean validation/serialization rules.                                | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-boolean](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-boolean)   |
| `@ApiPropertyNumber`   | Handles numeric formats, ranges, and array validation.                         | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-number](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-number)     |
| `@ApiPropertyString`   | Covers dozens of string formats, pattern enforcement, and serialization hints. | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-string](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-string)     |
| `@ApiPropertyDate`     | Controls timestamp identifiers, serialization, and timezone handling.          | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-date](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-date)         |
| `@ApiPropertyEnum`     | Maps enum values to Swagger and validation metadata.                           | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-enum](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-enum)         |
| `@ApiPropertyObject`   | Describes nested object payloads with typed sub-properties.                    | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-object](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-object)     |
| `@ApiPropertyUUID`     | Adds UUID validation for identifiers and relation references.                  | [/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-uuid](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-uuid)         |

## Recommended workflow

1. Start with `@ApiPropertyDescribe` on entities so DTO generation stays centralized.
2. Apply the property-specific decorators to manual DTOs when fine-grained control is needed.
3. Use `@ApiPropertyCopy` to mirror existing metadata onto custom DTOs or nested payloads while preserving auto-context behavior.

## Required, nullable, and response-only semantics

Manual property decorators now use explicit presence guards instead of a blanket `IsOptional` behavior:

- `isRequired: true` rejects missing `undefined` values.
- `isNullable: true` allows `null` without making missing `undefined` valid unless `isRequired` is also `false`.
- `isRequired: false` allows missing `undefined`.
- `isResponse: true` marks a response-only field and skips request validators such as `IsString`, `IsNumber`, `IsUUID`, `IsEnum`, `IsObject`, and nested validators.

```typescript
export class CreatePostDTO {
	@ApiPropertyString({
		entity: CreatePostDTO,
		description: "Required title",
		format: EApiPropertyStringType.STRING,
		minLength: 1,
		maxLength: 120,
		pattern: "/^[\\s\\S]{1,120}$/",
		exampleValue: "Launch notes",
		isRequired: true,
	})
	title!: string;

	@ApiPropertyString({
		entity: CreatePostDTO,
		description: "Optional subtitle",
		format: EApiPropertyStringType.STRING,
		minLength: 0,
		maxLength: 160,
		pattern: "/^[\\s\\S]{0,160}$/",
		exampleValue: "A short summary",
		isRequired: false,
	})
	subtitle?: string;

	@ApiPropertyString({
		entity: CreatePostDTO,
		description: "Required but nullable external reference",
		format: EApiPropertyStringType.STRING,
		minLength: 1,
		maxLength: 64,
		pattern: "/^[a-zA-Z0-9_-]+$/",
		exampleValue: "external-123",
		isNullable: true,
		isRequired: true,
	})
	externalReference!: null | string;
}
```

## Array options

Every `@ApiProperty*` decorator checks its array options when it decorates, and an error names the decorator, the DTO class and the property:

- A request array must declare `minItems`, `maxItems` and `isUniqueItems`. The types require them, and JavaScript or `any` can still leave one out; a missing `minItems` or `maxItems` would reject every value. A response array (`isResponse: true`) may leave them out, and its schema then publishes none.
- `minItems` and `maxItems` must be non-negative integers, with `minItems` not above `maxItems`. `NaN` from `Number(process.env.X)` and `Number.POSITIVE_INFINITY` fail here.
- `isArray` and `isUniqueItems` must be booleans.

## Migration Notes

### 5.0.0

- A fractional `multipleOf` on `@ApiPropertyNumber` is now an exact decimal check under the same `isDivisibleBy` constraint. Before 5.0.0, class-validator read the divisor with `parseInt`, so `0.01` rejected every value and `2.5` checked multiples of `2`.
- Before 5.0.0, the boolean, date, enum, number, string and UUID decorators rejected at decoration only a negative bound, `minItems` above `maxItems`, and `isUniqueItems` with `maxItems` of 1 or less. A request array without `minItems` or `maxItems` decorated and every request then failed with `must contain at least undefined elements` or `must contain no more than undefined elements`, one without `isUniqueItems` only left `uniqueItems` out of the schema, a `NaN` bound rejected every value, and an array with a non-boolean `isArray` skipped the checks. Each of these now fails at decoration. Declare valid values, and give a number read from the environment a default.
- `maxItems: Number.POSITIVE_INFINITY` and a fractional bound compiled and worked before, and now fail at decoration. Declare a finite integer.
- The options type of every `@ApiProperty*` decorator includes `TApiPropertyBaseResponseArrayProperties`, a response array whose bounds are optional, and `@ApiPropertyBoolean` takes the new `TApiPropertyBooleanProperties`. Code that reads the options and narrows on `isArray === true` gets `minItems`, `maxItems` and `isUniqueItems` as possibly `undefined`; also check `isResponse !== true` to read the required bounds of a request array.
