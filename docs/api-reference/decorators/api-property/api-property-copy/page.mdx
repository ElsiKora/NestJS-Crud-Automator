# `@ApiPropertyCopy`

Copies all generated decorators (Swagger metadata, class-validator rules, transformers, DTO hooks) from an entity property onto a manual DTO field. Eliminates duplication when custom DTOs should mirror entity metadata.

## Signature

```typescript
ApiPropertyCopy<E>({
	entity,
	propertyName,
	method?,
	dtoType?,
	metadata?,
	guard?,
	shouldAutoResolveContext?,
}: TApiPropertyCopyProperties<E>): PropertyDecorator
```

## Options

| Option                     | Description                                                                                                                                                            |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entity`                   | Entity class or factory. Factories allow lazy resolution to avoid circular imports.                                                                                    |
| `propertyName`             | Property name on the entity to mirror.                                                                                                                                 |
| `method` / `dtoType`       | Specify which CRUD route + DTO (e.g., GET + RESPONSE) to pull decorators from. Required unless `shouldAutoResolveContext` is true.                                     |
| `metadata`                 | Partial overrides merged with the original `@ApiPropertyDescribe` metadata before decorator generation. Useful for tweaking descriptions or DTO exposure.              |
| `guard`                    | Guard class used when generating DTO-specific decorators (mirrors the guard registered during auto DTO generation).                                                    |
| `shouldAutoResolveContext` | When true, defers execution until the auto DTO pipeline attaches method/dto metadata (e.g., inside generated controller DTOs). Retries through the auto-context queue. |

## Behavior

- Resolves the entity (sync or async) and ensures `propertyName` metadata exists, throwing descriptive errors if not.
- Determines the correct DTO context either from `method`/`dtoType` or the auto context queue.
- Calls the DTO generator to produce the same decorators originally attached to the entity property and re-applies them to the DTO field.
- May explicitly copy a source property declared with `ApiPropertyDescribe({ isAutoDtoEnabled: false })`. This is an intentional manual-DTO opt-in that bypasses only the global auto-generation boundary; all other source route/DTO, guard, validator, transformer, and Swagger rules still apply.
- Supports guard-aware decorator generation so field-level guards remain in sync.
- Relation response copies generate a relation object whose nested `id` description is relation-aware, e.g. `DepositEntity currency identifier` instead of `DepositEntity identifier`.
- A relation response copy reads the entity, not a route, so it stays the `{ id }` object, required and non-null, whatever `relations.response` a route configures. On a route whose reference is `SCALAR`, on another key, or nullable on the wire, describe the property in the manual DTO instead.
- Request relation copies keep the existing UUID reference behavior.
- A copied polymorphic property registers its variants as extra models of the DTO that holds the copy, as [`@ApiPropertyObject`](/docs/nestjs-crud-automator/api-reference/decorators/api-property/api-property-object) does, so its `oneOf` references resolve without a generated route for the entity.
- A nested DTO that the copy generates is named after the DTO that holds the property: `<Host><Property>DTO` for a relation and `<Host><Property><Variant>DTO` for a dynamic object variant, where `<Host>` is the DTO class name without a trailing `DTO` in any case. Two DTOs that copy one relation get two names, so both can appear in one document. See [Generated Schema Names](/docs/nestjs-crud-automator/core-concepts/dtos#generated-schema-names).
- Records the source column on the DTO property. A securable `@ApiRouteCustom` route needs this for each path parameter its IAM `resourcePath` names, and startup fails for a placeholder the PARAMETERS DTO does not copy this way. `ApiAuthorizationGuard` runs the route's PARAMETERS DTO before authorization, so a path parameter copied this way is checked by the source column's rule, named in the `resourcePath` or not, and IAM conditions see its canonical text. Any other rule in that DTO decides its own value the same way. Copy the property in the PARAMETERS DTO itself: a mapped type such as `PickType` keeps the rule but not the record of the source column. See [Validation](/docs/nestjs-crud-automator/guides/validation#generated-route-path-parameters).

## Example

```typescript
class DepositResponseDto {
	@ApiPropertyCopy({
		entity: () => DepositEntity,
		propertyName: "amount",
		method: EApiRouteType.GET,
		dtoType: EApiDtoType.RESPONSE,
	})
	amount!: number;

	@ApiPropertyCopy({
		entity: () => DepositEntity,
		propertyName: "status",
		shouldAutoResolveContext: true,
	})
	status!: EDepositStatus;
}
```

## Relation example

```typescript
class DepositResponseDto {
	@ApiPropertyCopy({
		entity: () => DepositEntity,
		propertyName: "currency",
		method: EApiRouteType.GET,
		dtoType: EApiDtoType.RESPONSE,
	})
	currency!: CurrencyEntity;
}
```

If `DepositEntity.currency` is described as a relation, the copied response schema uses:

```typescript
currency.description === "DepositEntity currency";
currency.id.description === "DepositEntity currency identifier";
```

The relation object is the component `DepositResponseCurrencyDTO`, named after `DepositResponseDto` without its trailing `Dto`.
