# Execution Context

Execution contexts provide access to data and metadata during subscriber hook execution. Different contexts are available for route and function subscribers, each with specific properties.

## Helper Types (Recommended)

For simplified usage, helper types are provided that require only the Entity generic parameter:

```typescript
import {
  TApiSubscriberFunctionBeforeCreateContext,
  TApiSubscriberFunctionAfterCreateContext,
  TApiFunctionCreateProperties,
} from "@elsikora/nestjs-crud-automator";

// Simple - only one generic parameter needed
async onBeforeCreate(
  context: TApiSubscriberFunctionBeforeCreateContext<PostEntity>
): Promise<TApiFunctionCreateProperties<PostEntity>> {
  // Full type safety and autocomplete for DATA
  const manager = context.DATA.eventManager;
  const repository = context.DATA.repository;

  return context.result;
}
```

Before function helpers default to the operation payload type, and can accept a second constrained `Result` generic when a subscriber needs a stricter payload. Define the payload type yourself to match the service input shape; the generic only narrows TypeScript's `context.result` type and does not change validation, transformation, or runtime behavior.

```typescript
type PostCreateInput = {
	title: string;
	author: { id: string };
};

async onBeforeCreate(
  context: TApiSubscriberFunctionBeforeCreateContext<PostEntity, PostCreateInput>
): Promise<PostCreateInput> {
  context.result.title; // string
  context.result.author.id; // string

  return context.result;
}
```

Function helpers also accept a transaction expectation generic. Exact `REQUIRED` and `MANDATORY` expectations narrow `context.DATA.eventManager` to `EntityManager`; `SUPPORTS`, `NONE`, mixed unions, widened expectations, and the default keep it optional.

## Base Execution Context

All execution contexts extend the base interface:

```typescript
interface IApiSubscriberExecutionContext<E, Result, Input> {
	/**
	 * The entity instance the operation is being performed on
	 */
	readonly ENTITY: E;

	/**
	 * Immutable container for metadata
	 * (e.g., transaction manager, HTTP headers, route info)
	 */
	readonly DATA: Input;

	/**
	 * Mutable data payload that subscribers can modify
	 */
	result: Result;
}
```

## Route Execution Context

Used in route (controller-level) subscribers:

```typescript
interface IApiSubscriberRouteExecutionContext<E, Result, Input> {
	readonly ENTITY: E;
	readonly DATA: Input; // Use IApiSubscriberRouteExecutionContextData<E, R> or IApiSubscriberRouteExecutionContextDataExtended<E, R>
	readonly ROUTE_TYPE: EApiRouteType;
	result: Result;
}
```

### Route Context DATA Interfaces

**Base DATA (for before hooks):**

```typescript
interface IApiSubscriberRouteExecutionContextData<E extends IApiBaseEntity, R = TApiAuthorizationRuleTransformPayload<E>> {
	readonly entityMetadata: IApiEntity<E>;
	readonly method: EApiRouteType;
	readonly methodName: string;
	readonly properties: IApiControllerProperties<E>;
	readonly authorizationDecision?: IApiAuthorizationDecision<E, R>;
}
```

**Extended DATA (for after/error hooks):**

```typescript
interface IApiSubscriberRouteExecutionContextDataExtended<E extends IApiBaseEntity, R = TApiAuthorizationRuleTransformPayload<E>, M extends EApiControllerGetListQueryPaginationMode = EApiControllerGetListQueryPaginationMode.PAGE> extends IApiSubscriberRouteExecutionContextData<E, R> {
	readonly authenticationRequest?: IApiAuthenticationRequest;
	readonly headers: Record<string, string>;
	readonly ip: string;
	readonly body?: DeepPartial<E>;
	readonly parameters?: Partial<E>;
	readonly query?: TApiControllerGetListQuery<E, M>;
}
```

PAGE remains the default generic. A CURSOR route subscriber selects `M = EApiControllerGetListQueryPaginationMode.CURSOR` to receive the mutually exclusive `after`/`before` query and `TApiControllerGetListResponse<E, M>` flat envelope.

### Accessing Route Context Data

**Recommended approach with helper type:**

```typescript
import { TApiSubscriberRouteBeforeCreateContext } from "@elsikora/nestjs-crud-automator";

async onBeforeCreate(
  context: TApiSubscriberRouteBeforeCreateContext<PostEntity>
): Promise<TApiSubscriberRouteBeforeCreateContext<PostEntity>["result"]> {
  // Entity being operated on
  const entity = context.ENTITY;

  // Route information (fully typed)
  const routeType = context.ROUTE_TYPE;
  const method = context.DATA.method;
  const methodName = context.DATA.methodName;

  // Entity metadata
  const entityMetadata = context.DATA.entityMetadata;
  const primaryKey = entityMetadata.primaryKey;

  // Mutable result
  const { body } = context.result;
  body.slug = this.generateSlug(body.title);

  return context.result;
}
```

**For after hooks with extended DATA:**

```typescript
import { TApiSubscriberRouteAfterCreateContext } from "@elsikora/nestjs-crud-automator";

async onAfterCreate(
  context: TApiSubscriberRouteAfterCreateContext<PostEntity>
): Promise<PostEntity> {
  // Authenticated user
  const user = context.DATA.authenticationRequest?.user;
  const userId = user?.id;

  // Request headers
  const contentType = context.DATA.headers["content-type"];
  const userAgent = context.DATA.headers["user-agent"];
  const correlationId = context.DATA.headers["x-correlation-id"];

  // Client IP
  const clientIp = context.DATA.ip;

  return context.result;
}
```

## Function Execution Context

Used in function (service-level) subscribers:

```typescript
interface IApiSubscriberFunctionExecutionContext<E, Result, Input> {
	readonly ENTITY: E;
	readonly DATA: Input; // Use IApiSubscriberFunctionExecutionContextData<E> for typed access
	readonly FUNCTION_TYPE: EApiFunctionType;
	result: Result;
}
```

### Function Context DATA Interface

```typescript
interface IApiSubscriberFunctionExecutionContextData<E extends IApiBaseEntity> {
	readonly eventManager?: EntityManager;
	readonly repository: Repository<E>;
	readonly criteria?: TApiFunctionDeleteCriteria<E> | TApiFunctionUpdateCriteria<E>;
	readonly properties?: TApiFunctionCreateProperties<E> | TApiFunctionGetProperties<E> | TApiFunctionGetListProperties<E> | TApiFunctionGetManyProperties<E>;
	readonly getProperties?: TApiFunctionGetProperties<E>;
	readonly getListProperties?: TApiFunctionGetListProperties<E>;
	readonly getManyProperties?: TApiFunctionGetManyProperties<E>;
	readonly principal?: Readonly<IApiAuthorizationPrincipal>;
}

type TApiSubscriberFunctionExecutionContextData<E extends IApiBaseEntity, TTransactionExpectation extends EApiFunctionSubscriberTransactionExpectation = EApiFunctionSubscriberTransactionExpectation.SUPPORTS> = IApiSubscriberFunctionExecutionContextData<E> & ([TTransactionExpectation] extends [EApiFunctionSubscriberTransactionExpectation.MANDATORY | EApiFunctionSubscriberTransactionExpectation.REQUIRED] ? { eventManager: EntityManager } : { eventManager?: EntityManager });

interface IApiSubscriberFunctionExecutionContextWriteData<E extends IApiBaseEntity> extends IApiSubscriberFunctionExecutionContextData<E> {
	addCondition(where: Array<FindOptionsWhere<E>> | FindOptionsWhere<E>): void;
}

interface IApiSubscriberFunctionExecutionContextUpdateData<E extends IApiBaseEntity> extends IApiSubscriberFunctionExecutionContextWriteData<E> {
	readonly currentEntity: Readonly<E>;
}
```

`TApiSubscriberFunctionBeforeUpdateContext` uses the update-specific DATA interface. One decorated GET loads `currentEntity` before UPDATE before-hooks. Only its top-level object is detached and frozen; nested values retain aliases to the internal loaded entity, so mutating them can affect persistence. `context.result` remains the update patch, and `repository` is manager-bound whenever the update joins or owns a transaction.

### Request Principal

`context.DATA.principal` is the principal the authorization guard resolved for the route request the function runs in: a deep-frozen copy, the same object for every function of that request. Generated routes and `@ApiRouteCustom` routes with authorization set it; it is `undefined` on a direct service call, on a route without authorization, and in work that starts outside a route request. It is in the DATA of every function context (create, get, getList, getMany, update, delete, and `@ApiFunctionCustom`), in BEFORE, AFTER, and error hooks alike.

The principal travels with the request through `AsyncLocalStorage`, so every function the request runs sees it: a function another function or a handler calls (an update's internal GET, a service call inside a custom route handler), and a function called from a callback the request registers, such as a transaction's after-commit hook. A queue consumer or job runner sees none only when it starts outside a request, even for work a request enqueued. Async work that starts during a request inherits that request's principal for its whole life: a `setInterval` or `setTimeout` callback, an event emitter listener registered in the request, a consumer or pool started lazily by the first request. Start long-lived workers at bootstrap (`onModuleInit`, `onApplicationBootstrap`), not on first use inside a request, so their functions do not act as the user of the request that happened to start them.

```typescript
async onBeforeCreate(context: TApiSubscriberFunctionBeforeCreateContext<PostEntity>): Promise<TApiFunctionCreateProperties<PostEntity>> {
	return { ...context.result, authorId: context.DATA.principal?.id };
}
```

### Write Conditions

`TApiSubscriberFunctionBeforeUpdateContext` and `TApiSubscriberFunctionBeforeDeleteContext` add `context.DATA.addCondition(where)`, so a BEFORE subscriber can make the write depend on the row's current state:

```typescript
async onBeforeUpdate(context: TApiSubscriberFunctionBeforeUpdateContext<OrderEntity, TApiFunctionUpdateProperties<OrderEntity>, EApiFunctionSubscriberTransactionExpectation.REQUIRED>): Promise<undefined> {
	context.DATA.addCondition({ status: "draft" });
	context.DATA.addCondition({ store: { ownerId: context.DATA.principal?.id } });

	return undefined;
}
```

- Every condition is ANDed into the write scope: the criteria and the authorization scope, under `SAVE` and `PATCH` and on delete. A condition only narrows the write; it never widens or replaces the scope. Conditions only accumulate; an array is an OR of branches inside that one condition.
- A row a condition excludes answers what a row outside the scope answers: `404 {ENTITY}_NOT_FOUND`, through the AFTER_ERROR subscribers, with the row unchanged. Never `403`.
- A condition may read relations (`{ store: { ownerId } }`), also under `PATCH`.
- The condition is checked in the write's transaction, on the row the write changes: `PATCH` adds it to its `UPDATE ... WHERE` (with a locking key read first when the WHERE reads another table); `SAVE` update and delete add one locking read of the row by its key, the scope, and the conditions right before the write. That read runs only when a subscriber added a condition; without one, the function issues exactly the queries it issues without this feature. The lock holds the written row itself, so its own columns cannot change between the check and the write; related rows a scope or condition reads are checked at the lock point but not locked on PostgreSQL and CockroachDB (`FOR UPDATE OF` the entity), so a concurrent change to them after the check is not seen there. MySQL's `FOR UPDATE` locks the related rows it reads too. These checks need a driver with row locks or a single connection: on a driver TypeORM refuses `pessimistic_write` for (Spanner), a PATCH relation scope and `addCondition` fail with TypeORM's `LockNotSupportedOnGivenDriverError`.
- `addCondition` needs a transaction: on a function that runs without one (`SUPPORTS` with no outer transaction, `NONE`), it throws `Function "<Service>.<method>" needs a transaction to add a write condition: configure its transaction mode as REQUIRED`. Configure the function with `REQUIRED` (or call it inside a transaction).
- A condition never makes the criteria address a row: a delete whose criteria and scope are empty (`service.delete({})`, or an `onBeforeDelete` returning `{}`) is refused with a condition too, and removes nothing. The locking read keeps the read's soft-delete visibility: a row the read saw live must still not be soft-deleted, so another writer's soft delete after the read is a miss.
- `addCondition` works only while the BEFORE subscribers run; a call after the chain (from a stored reference) throws.
- A condition must be a non-empty WHERE that TypeORM would not drop or widen (an empty object or an `undefined` value throws), checked when it is added.

### Accessing Function Context Data

**Recommended approach with helper type:**

```typescript
import { TApiSubscriberFunctionBeforeCreateContext } from "@elsikora/nestjs-crud-automator";

async onBeforeCreate(
  context: TApiSubscriberFunctionBeforeCreateContext<PostEntity>
): Promise<TApiFunctionCreateProperties<PostEntity>> {
  // Entity being created
  const entity = context.ENTITY;

  // Fully typed DATA access
  const manager = context.DATA.eventManager;
  const repository = context.DATA.repository;

  if (manager) {
    // Use transactional operations
    await manager.save(RelatedEntity, { ... });
  }

  // Mutable result
  context.result.slug = this.generateSlug(context.result.title);

  return context.result;
}
```

**Alternative approach with explicit generic:**

```typescript
import { IApiSubscriberFunctionExecutionContextData } from "@elsikora/nestjs-crud-automator";

async onBeforeCreate(
  context: IApiSubscriberFunctionExecutionContext<
    PostEntity,
    TApiFunctionCreateProperties<PostEntity>,
    IApiSubscriberFunctionExecutionContextData<PostEntity>
  >
): Promise<TApiFunctionCreateProperties<PostEntity>> {
  const manager = context.DATA.eventManager;
  // ...
}
```

## Error Execution Contexts

### Route Error Context

```typescript
interface IApiSubscriberRouteErrorExecutionContext<E extends IApiBaseEntity, Input = unknown> {
	readonly DATA: Input;
	readonly ENTITY: E;
	readonly ROUTE_TYPE: EApiRouteType;
}
```

Use `IApiSubscriberRouteExecutionContextData<E, R>` for before-error hooks (route metadata + optional `authorizationDecision`) and `IApiSubscriberRouteExecutionContextDataExtended<E, R>` for after-error hooks when you need authentication data or request context.

### Function Error Context

```typescript
interface IApiSubscriberFunctionErrorExecutionContext<E extends IApiBaseEntity, Input = unknown> {
	readonly DATA: Input;
	readonly ENTITY: E;
	readonly FUNCTION_TYPE: EApiFunctionType;
}
```

Use `IApiSubscriberFunctionExecutionContextData<E>` to access `eventManager` and `repository`.

### Using Error Contexts

```typescript
async onAfterErrorCreate(
  context: IApiSubscriberRouteErrorExecutionContext<
    PostEntity,
    IApiSubscriberRouteExecutionContextDataExtended<PostEntity, unknown>
  >,
  error: Error
): Promise<void> {
  console.error(`Post creation failed: ${FormatErrorEvidenceForLog(error)}`);

  await this.notificationService.notifyAdmins({
    type: "post_creation_error",
    errorEvidence: FormatErrorEvidenceForLog(error),
  });
}
```

## Modifying Results

Subscribers can modify the mutable `result` field:

### Before Hooks

```typescript
async onBeforeCreate(
  context: TApiSubscriberRouteBeforeCreateContext<PostEntity>
): Promise<TApiSubscriberRouteBeforeCreateContext<PostEntity>["result"]> {
  // Modify body before saving
  context.result.body.slug = this.generateSlug(context.result.body.title);
  context.result.body.status = "draft";

  return context.result;
}
```

### After Hooks

```typescript
async onAfterGet(
  context: TApiSubscriberFunctionAfterGetContext<PostEntity>
): Promise<PostEntity> {
  // Enrich result after fetching
  context.result.readingTime = this.calculateReadingTime(context.result.content);
  context.result.isBookmarked = await this.checkIfBookmarked(context.result.id);

  return context.result;
}
```

## Type Parameters

Execution contexts are generic and accept type parameters:

```typescript
// E: Entity type
// Result: Result type (varies by operation)
// Input: Input data type (metadata)

IApiSubscriberExecutionContext<E, Result, Input>;
```

### Common Result Types

```typescript
// Function create before hook
TApiFunctionCreateProperties<E> = DeepPartial<E>;

// Function update before hook
TApiFunctionUpdateProperties<E> = DeepPartial<E>;

// Route create/update before hooks
TApiControllerRequestProperties<E, M extends EApiControllerGetListQueryPaginationMode = EApiControllerGetListQueryPaginationMode.PAGE> = {
	body?: DeepPartial<E>;
	parameters?: Partial<E>;
	query?: TApiControllerGetListQuery<E, M>;
};

// Get operation (function + route after)
E; // The entity itself

// Get list operation (function + route after)
TApiControllerGetListResponse<E, M>; // PAGE by default; flat CURSOR response when M = CURSOR

// Get many operation (function + route after)
Array<E>;

// Delete before hook (function)
TApiFunctionDeleteCriteria<E>;

// Delete after hook (function)
E;
```

Route before hooks receive request payloads (`body`, `parameters`, `query`) rather than entities, so their `result` shape is based on the incoming DTO. After/error hooks also receive the last request payload on `context.DATA` (when available).

## Practical Examples

### Enriching Response from Context

```typescript
async onAfterCreate(
  context: TApiSubscriberRouteAfterCreateContext<PostEntity>
): Promise<PostEntity> {
  const post = context.result;
  const user = context.DATA.authenticationRequest?.user;

  // Add request metadata to the response
  post.authorId = user?.id;
  post.authorIp = context.DATA.ip;
  post.createdVia = context.DATA.headers["user-agent"];

  return post;
}
```

### Conditional Logic Based on Context

```typescript
async onAfterGet(
  context: TApiSubscriberRouteAfterGetContext<PostEntity>
): Promise<PostEntity> {
  const post = context.result;
  const user = context.DATA.authenticationRequest?.user;

  // Hide sensitive data based on user role
  if (user?.role !== "admin") {
    post.internalNotes = null;
    post.authorEmail = null;
  }

  return post;
}
```

### Using Event Manager (Transactions)

By default, `context.DATA.eventManager` is optional. A function subscriber that cannot run without a manager should declare the expectation on both the decorator metadata and the class/context generic:

```typescript
@ApiFunctionSubscriber({
	entity: PostEntity,
	transaction: { expectation: EApiFunctionSubscriberTransactionExpectation.REQUIRED },
})
export class PostAuditSubscriber extends ApiFunctionSubscriberBase<PostEntity, TApiFunctionCreateProperties<PostEntity>, EApiFunctionSubscriberTransactionExpectation.REQUIRED> {
	async onBeforeCreate(context: TApiSubscriberFunctionBeforeCreateContext<PostEntity, TApiFunctionCreateProperties<PostEntity>, EApiFunctionSubscriberTransactionExpectation.REQUIRED>): Promise<TApiFunctionCreateProperties<PostEntity>> {
		await context.DATA.eventManager.save(AuditEntity, {
			title: context.result.title,
		});

		return context.result;
	}
}
```

The runtime check is subscriber-declared through `transaction.expectation`. It is not inferred from `@ApiService`, `@ApiFunctionCustom`, or `@ApiFunctionStep` transaction config.

```typescript
async onBeforeCreate(
  context: TApiSubscriberFunctionBeforeCreateContext<PostEntity>
): Promise<TApiFunctionCreateProperties<PostEntity>> {
  const manager = context.DATA.eventManager;

  if (manager) {
    // Create related entities within same transaction
    const tags = await manager.save(TagEntity, [
      { name: "tech" },
      { name: "programming" },
    ]);

    context.result.tags = tags;
  }

  return context.result;
}
```

### Error Context with Cleanup

```typescript
async onAfterErrorCreate(
  context: IApiSubscriberFunctionErrorExecutionContext<
    PostEntity,
    IApiSubscriberFunctionExecutionContextData<PostEntity>
  >,
  error: Error
): Promise<void> {
  // Clean up temporary resources
  if (context.ENTITY.tempFileIds) {
    await this.fileService.deleteTempFiles(context.ENTITY.tempFileIds);
  }

	this.logger.error(`Failed to create post: ${FormatErrorEvidenceForLog(error)}`);
}
```

Error hooks may use context for recovery decisions, but must not serialize that context into logs. Log only explicitly admitted dimensions and `FormatErrorEvidenceForLog(error)`.
