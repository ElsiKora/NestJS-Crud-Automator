# Pagination

All generated GET_LIST endpoints in NestJS CRUD Automator use a page/limit contract. Both values are required integers from 1 through 100, and the standard response includes page and total-count metadata.

## Basic Pagination

Paginate results using query parameters:

```
GET /users?limit=10&page=1
```

This returns the first 10 users.

## Pagination Parameters

### `limit`

Required number of items per page (minimum 1, maximum 100):

```
GET /users?limit=20&page=1
```

### `page`

Required page number (1-based indexing, maximum 100):

```
GET /users?limit=20&page=2
```

## Response Structure

Paginated responses include metadata:

```typescript
{
  count: number,       // Number of items on the current page
  currentPage: number, // Current page number
  items: UserEntity[], // Array of results
  totalCount: number,  // Total count of all matching items
  totalPages: number   // Total number of pages
}
```

Example response:

```json
{
	"count": 2,
	"currentPage": 1,
	"items": [
		{
			"id": "uuid-1",
			"username": "john_doe",
			"email": "john@example.com"
		},
		{
			"id": "uuid-2",
			"username": "jane_doe",
			"email": "jane@example.com"
		}
	],
	"totalCount": 50,
	"totalPages": 5
}
```

## Combining with Filters and Sorting

Pagination works seamlessly with filtering and sorting:

```
GET /users?limit=20&page=2&username[operator]=cont&username[value]=john&orderBy=createdAt&orderDirection=desc
```

This returns page 2 of users with "john" in username, sorted by creation date descending, 20 items per page.

For stable consecutive pages over an unchanged dataset, configure a deterministic server order with a unique final tie-breaker:

```typescript filename="user.controller.ts" copy
@ApiController<UserEntity>({
	entity: UserEntity,
	routes: {
		[EApiRouteType.GET_LIST]: {
			request: {
				[EApiControllerRequestTarget.QUERY]: {
					order: {
						defaultOrder: [{ direction: EFilterOrderDirection.DESC, field: "createdAt" }],
						fields: {
							createdAt: { isEnabled: true },
						},
						tieBreakers: [{ direction: EFilterOrderDirection.ASC, field: "id" }],
						unlistedFields: EApiControllerGetListQueryUnlistedFields.REJECT,
					},
				},
			},
		},
	},
})
export class UserController {
	constructor(public service: UserService) {}
}
```

If the request omits `orderBy` and `orderDirection`, runtime applies `createdAt DESC, id ASC`. If the client supplies that pair, it replaces `defaultOrder`; `id ASC` is still appended. Duplicate order fields are removed with the earlier entry winning. Server-owned order entries are validated against all described direct scalar fields, so a UUID `id` can remain a hidden tie-breaker instead of appearing in the client order enum.

## Programmatic Usage

Use pagination in service calls:

```typescript filename="user.controller.ts" copy
import { Injectable } from "@nestjs/common";
import { UserService } from "./user.service";
import { IApiGetListResponseResult } from "@elsikora/nestjs-crud-automator";
import { UserEntity } from "./user.entity";

@Injectable()
export class UserReportService {
	constructor(private readonly userService: UserService) {}

	async getAllUsers(): Promise<UserEntity[]> {
		const allUsers: UserEntity[] = [];
		let page = 1;
		const limit = 100;
		let hasMore = true;

		while (hasMore) {
			const result: IApiGetListResponseResult<UserEntity> = await this.userService.getList({
				where: {},
				take: limit,
				skip: (page - 1) * limit,
			});

			allUsers.push(...result.items);
			hasMore = result.currentPage < result.totalPages;
			page++;
		}

		return allUsers;
	}
}
```

## Pagination Limits

Generated GET_LIST routes parse `limit` and `page`, then pass `take = limit` and `skip = limit * (page - 1)` to the service. There is no route-level pagination-default configuration in the current public contract. Clients must send both values. Use a custom route/service contract only when an application genuinely needs a different pagination model.

## Infinite Scroll

Implement infinite scroll patterns:

```typescript filename="frontend-example.ts" copy
class UserListComponent {
	users: UserEntity[] = [];
	page = 1;
	limit = 20;
	loading = false;
	hasMore = true;

	async loadMore(): Promise<void> {
		if (this.loading || !this.hasMore) return;

		this.loading = true;
		try {
			const response = await fetch(`/users?limit=${this.limit}&page=${this.page}`);
			const data = await response.json();

			this.users.push(...data.items);
			this.hasMore = data.currentPage < data.totalPages;
			this.page++;
		} finally {
			this.loading = false;
		}
	}
}
```

## Performance Considerations

### Offset Pagination

The generated route uses TypeORM offset pagination. It supports jumping to a page and keeps the standard count envelope, but large offsets can become expensive. A unique final order tie-breaker prevents rows with equal primary sort values from changing relative position for an unchanged dataset; it cannot freeze a dataset while concurrent inserts or updates occur.

### Counting Performance

Total counts can be expensive on large tables. Consider:

1. **Caching counts**:

```typescript
@Injectable()
export class UserService extends ApiServiceBase<UserEntity> {
	private countCache: { value: number; timestamp: number } | null = null;
	private readonly CACHE_TTL = 60000; // 1 minute

	async getList(properties) {
		const now = Date.now();
		if (!this.countCache || now - this.countCache.timestamp > this.CACHE_TTL) {
			const total = await this.repository.count();
			this.countCache = { value: total, timestamp: now };
		}

		// Use cached count
		const items = await this.repository.find({
			relations: properties.relations,
			skip: properties.skip,
			take: properties.take,
		});

		return {
			count: items.length,
			currentPage: properties.skip && properties.take ? Math.floor(properties.skip / properties.take) + 1 : 1,
			items,
			totalCount: this.countCache.value,
			totalPages: Math.ceil(this.countCache.value / (properties.take ?? 1)),
		};
	}
}
```

2. **Approximate counts** for very large tables:

```typescript
// PostgreSQL approximate count
const result = await this.repository.query(`
  SELECT reltuples::bigint AS estimate
  FROM pg_class
  WHERE relname = 'users'
`);
const approximateTotal = result[0].estimate;
```

### Index Optimization

Ensure pagination queries are fast with proper indexes:

```typescript
@Entity("users")
@Index(["createdAt", "id"]) // Matches defaultOrder + tieBreakers
export class UserEntity {
	@PrimaryGeneratedColumn("uuid")
	id: string;

	@Column({ type: "timestamp", default: () => "CURRENT_TIMESTAMP" })
	createdAt: Date;
}
```

## Empty Results

Handle empty result sets gracefully:

```typescript
{
  "count": 0,
  "currentPage": 0,
  "items": [],
  "totalCount": 0,
  "totalPages": 0
}
```
