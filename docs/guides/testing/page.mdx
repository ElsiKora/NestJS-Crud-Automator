# Testing

A controller with an enabled generated route checks its service repository at application bootstrap, so a test of such a controller needs a real TypeORM repository. Build it from a DataSource and stub the repository methods the test controls.

## Repository Of An In-Memory DataSource

Create a `better-sqlite3` DataSource in memory, take the entity repository from it, and stub single methods with `vi.spyOn` (or `jest.spyOn`). Provide that repository under the token `@InjectRepository` reads. The sample keeps the entity, the service, and the controller in one file so that it runs as it is; import yours instead:

```typescript filename="user.controller.spec.ts" copy
import "reflect-metadata";

import type { INestApplication } from "@nestjs/common";
import type { Repository } from "typeorm";

import { Injectable } from "@nestjs/common";
import { FastifyAdapter } from "@nestjs/platform-fastify";
import { Test } from "@nestjs/testing";
import { getRepositoryToken, InjectRepository } from "@nestjs/typeorm";
import { Column, DataSource, Entity, PrimaryGeneratedColumn } from "typeorm";
import { afterAll, beforeAll, expect, it, vi } from "vitest";

import { ApiAuthorizationModule, ApiController, ApiPropertyDescribe, ApiService, ApiServiceBase, EApiPropertyDescribeType, EApiPropertyStringType, EApiRouteType } from "@elsikora/nestjs-crud-automator";

@Entity("users")
class UserEntity {
	@ApiPropertyDescribe({ description: "id", type: EApiPropertyDescribeType.UUID })
	@PrimaryGeneratedColumn("uuid")
	public id!: string;

	@ApiPropertyDescribe({ description: "username", exampleValue: "john_doe", format: EApiPropertyStringType.STRING, maxLength: 50, minLength: 1, pattern: "/^.+$/", type: EApiPropertyDescribeType.STRING })
	@Column({ type: "varchar" })
	public username!: string;
}

@Injectable()
@ApiService<UserEntity>({ entity: UserEntity })
class UserService extends ApiServiceBase<UserEntity> {
	public constructor(
		@InjectRepository(UserEntity)
		public repository: Repository<UserEntity>,
	) {
		super();
	}
}

@ApiController<UserEntity>({ entity: UserEntity, path: "users", routes: { [EApiRouteType.GET]: {} } })
class UserController {
	public constructor(public service: UserService) {}
}

const USER_ID: string = "aaaaaaaa-0000-4000-8000-000000000001";

let app: INestApplication;
let dataSource: DataSource;
let repository: Repository<UserEntity>;

beforeAll(async () => {
	dataSource = await new DataSource({ database: ":memory:", entities: [UserEntity], synchronize: true, type: "better-sqlite3" }).initialize();
	repository = dataSource.getRepository(UserEntity);
	vi.spyOn(repository, "findOne").mockResolvedValue({ id: USER_ID, username: "john_doe" });

	const moduleReference = await Test.createTestingModule({
		controllers: [UserController],
		imports: [ApiAuthorizationModule.forRoot()],
		providers: [UserService, { provide: getRepositoryToken(UserEntity), useValue: repository }],
	}).compile();

	app = moduleReference.createNestApplication(new FastifyAdapter());
	await app.init();
});

afterAll(async () => {
	await app?.close();
	await dataSource?.destroy();
});

it("serves a generated route from the stubbed repository", async () => {
	const response = await app
		.getHttpAdapter()
		.getInstance()
		.inject({ method: "GET", url: `/users/${USER_ID}` });

	expect(response.statusCode).toBe(200);
	expect(response.json()).toEqual({ id: USER_ID, username: "john_doe" });
	expect(repository.findOne).toHaveBeenCalledOnce();
});
```

- `synchronize: true` creates the tables, so a method the test does not stub still runs a real query.
- `ApiAuthorizationModule.forRoot()` provides the guard every generated route uses.
- A generated CREATE counts the row it stored through its own transaction, past the stubs, and answers 500 unless exactly one row matches the key. Let `save` store the row in the in-memory database, or insert the row a stubbed `save` answers with before the request and leave its key out of the request body: a create only inserts, so a body that names the key of a stored row answers 409.
- The sample needs `better-sqlite3`, `@nestjs/testing`, `@nestjs/platform-fastify`, and `vitest` as development dependencies, next to the packages the application already uses. Nest resolves the constructor parameters from decorator metadata, so run Vitest with a transform that emits it, such as `unplugin-swc`.

### Column Types SQLite Rejects

`better-sqlite3` accepts only the column types of SQLite. An entity that declares any other type, such as `type: "timestamp"` or `type: "timestamptz"`, fails `dataSource.initialize()` with `DataTypeNotSupportedError` before the test starts. Test such an entity on a DataSource of its own database type, with [metadata and no connection](#postgresql-typed-entities-without-a-connection) or the way [CURSOR Controllers](#cursor-controllers) does, or declare a type both databases accept, such as `varchar`. Keep `app?.close()` and `dataSource?.destroy()` optional in `afterAll`, so that a failed `initialize()` reports its own error instead of a second one about `close`.

## CURSOR Controllers

A CURSOR GET_LIST route runs only on PostgreSQL, and the bootstrap check reads the driver of the active DataSource, so SQLite does not start such a controller. Test it on a PostgreSQL DataSource and stub `find`, which the route reads its window through. Production code stays as it is; do not switch the route to PAGE for a test. The sample connects to a real PostgreSQL, so unstubbed methods run real queries; [without a connection](#postgresql-typed-entities-without-a-connection) the check passes too:

```typescript filename="user.cursor-controller.spec.ts" copy
import "reflect-metadata";

import type { INestApplication } from "@nestjs/common";
import type { StartedPostgreSqlContainer } from "@testcontainers/postgresql";
import type { Repository } from "typeorm";

import { Injectable } from "@nestjs/common";
import { FastifyAdapter } from "@nestjs/platform-fastify";
import { Test } from "@nestjs/testing";
import { getRepositoryToken, InjectRepository } from "@nestjs/typeorm";
import { PostgreSqlContainer } from "@testcontainers/postgresql";
import { Column, DataSource, Entity, PrimaryGeneratedColumn } from "typeorm";
import { afterAll, beforeAll, expect, it, vi } from "vitest";

import { ApiAuthorizationModule, ApiController, ApiPropertyDescribe, ApiService, ApiServiceBase, EApiControllerGetListQueryPaginationMode, EApiControllerGetListQueryUnlistedFields, EApiControllerRequestTarget, EApiPropertyDescribeType, EApiPropertyStringType, EApiRouteType, EFilterOrderDirection } from "@elsikora/nestjs-crud-automator";

@Entity("users")
class UserEntity {
	@ApiPropertyDescribe({ description: "id", type: EApiPropertyDescribeType.UUID })
	@PrimaryGeneratedColumn("uuid")
	public id!: string;

	@ApiPropertyDescribe({ description: "username", exampleValue: "john_doe", format: EApiPropertyStringType.STRING, maxLength: 50, minLength: 1, pattern: "/^.+$/", type: EApiPropertyDescribeType.STRING })
	@Column({ type: "varchar" })
	public username!: string;
}

@Injectable()
@ApiService<UserEntity>({ entity: UserEntity })
class UserService extends ApiServiceBase<UserEntity> {
	public constructor(
		@InjectRepository(UserEntity)
		public repository: Repository<UserEntity>,
	) {
		super();
	}
}

@ApiController<UserEntity>({
	entity: UserEntity,
	path: "users",
	routes: {
		[EApiRouteType.GET_LIST]: {
			request: {
				[EApiControllerRequestTarget.QUERY]: {
					order: { fields: {}, tieBreakers: [{ direction: EFilterOrderDirection.ASC, field: "id" }], unlistedFields: EApiControllerGetListQueryUnlistedFields.REJECT },
					pagination: { mode: EApiControllerGetListQueryPaginationMode.CURSOR },
				},
			},
		},
	},
})
class UserController {
	public constructor(public service: UserService) {}
}

const USER_ID: string = "aaaaaaaa-0000-4000-8000-000000000001";

let app: INestApplication;
let container: StartedPostgreSqlContainer;
let dataSource: DataSource;
let repository: Repository<UserEntity>;

beforeAll(async () => {
	container = await new PostgreSqlContainer("postgres:17-alpine").start();
	dataSource = await new DataSource({ entities: [UserEntity], synchronize: true, type: "postgres", url: container.getConnectionUri() }).initialize();
	repository = dataSource.getRepository(UserEntity);
	vi.spyOn(repository, "find").mockResolvedValue([{ id: USER_ID, username: "john_doe" }]);

	const moduleReference = await Test.createTestingModule({
		controllers: [UserController],
		imports: [ApiAuthorizationModule.forRoot()],
		providers: [UserService, { provide: getRepositoryToken(UserEntity), useValue: repository }],
	}).compile();

	app = moduleReference.createNestApplication(new FastifyAdapter());
	await app.init();
}, 120_000);

afterAll(async () => {
	await app?.close();
	await dataSource?.destroy();
	await container?.stop();
}, 120_000);

it("serves a CURSOR route from the stubbed repository", async () => {
	const response = await app.getHttpAdapter().getInstance().inject({ method: "GET", url: "/users?limit=10" });

	expect(response.statusCode).toBe(200);
	expect(response.json()).toEqual({ items: [{ id: USER_ID, username: "john_doe" }], nextCursor: null, previousCursor: null });
	expect(repository.find).toHaveBeenCalledOnce();
});
```

- The sample also needs `pg` and `@testcontainers/postgresql` as development dependencies, and Docker. A PostgreSQL you already run for tests works too: pass its connection string as `url` and drop the container.
- The route validates the driver and the storage of its order fields, so the DataSource must use the entity's real column types.

## PostgreSQL-Typed Entities Without A Connection

The bootstrap checks and the CURSOR check read TypeORM metadata and the loaded driver and send no query, so a PostgreSQL DataSource whose metadata is built passes them without a connection. `buildMetadatas()` is a protected method of TypeORM's `DataSource`, so call it from a subclass, and build the repository from the manager of that DataSource:

```typescript filename="user.metadata-only.spec.ts" copy
import "reflect-metadata";

import type { INestApplication } from "@nestjs/common";

import { Injectable } from "@nestjs/common";
import { FastifyAdapter } from "@nestjs/platform-fastify";
import { Test } from "@nestjs/testing";
import { getRepositoryToken, InjectRepository } from "@nestjs/typeorm";
import { Column, DataSource, Entity, PrimaryGeneratedColumn, Repository } from "typeorm";
import { afterAll, beforeAll, expect, it, vi } from "vitest";

import { ApiAuthorizationModule, ApiController, ApiPropertyDescribe, ApiService, ApiServiceBase, EApiControllerGetListQueryPaginationMode, EApiControllerGetListQueryUnlistedFields, EApiControllerRequestTarget, EApiPropertyDateIdentifier, EApiPropertyDateType, EApiPropertyDescribeType, EApiRouteType, EFilterOrderDirection } from "@elsikora/nestjs-crud-automator";

class MetadataDataSource extends DataSource {
	public async buildWithoutConnection(): Promise<void> {
		await this.buildMetadatas();
	}
}

@Entity("users")
class UserEntity {
	@ApiPropertyDescribe({ description: "id", type: EApiPropertyDescribeType.UUID })
	@PrimaryGeneratedColumn("uuid")
	public id!: string;

	@ApiPropertyDescribe({ format: EApiPropertyDateType.DATE_TIME, identifier: EApiPropertyDateIdentifier.CREATED_AT, type: EApiPropertyDescribeType.DATE })
	@Column({ type: "timestamptz" })
	public createdAt!: Date;
}

@Injectable()
@ApiService<UserEntity>({ entity: UserEntity })
class UserService extends ApiServiceBase<UserEntity> {
	public constructor(
		@InjectRepository(UserEntity)
		public repository: Repository<UserEntity>,
	) {
		super();
	}
}

@ApiController<UserEntity>({
	entity: UserEntity,
	path: "users",
	routes: {
		[EApiRouteType.GET_LIST]: {
			request: {
				[EApiControllerRequestTarget.QUERY]: {
					order: { fields: {}, tieBreakers: [{ direction: EFilterOrderDirection.ASC, field: "id" }], unlistedFields: EApiControllerGetListQueryUnlistedFields.REJECT },
					pagination: { mode: EApiControllerGetListQueryPaginationMode.CURSOR },
				},
			},
		},
	},
})
class UserController {
	public constructor(public service: UserService) {}
}

const USER: UserEntity = { createdAt: new Date("2026-01-01T00:00:00.000Z"), id: "aaaaaaaa-0000-4000-8000-000000000001" };

let app: INestApplication;
let dataSource: MetadataDataSource;
let repository: Repository<UserEntity>;

beforeAll(async () => {
	dataSource = new MetadataDataSource({ entities: [UserEntity], type: "postgres" });
	await dataSource.buildWithoutConnection();
	repository = new Repository(UserEntity, dataSource.manager);
	vi.spyOn(repository, "find").mockResolvedValue([USER]);

	const moduleReference = await Test.createTestingModule({
		controllers: [UserController],
		imports: [ApiAuthorizationModule.forRoot()],
		providers: [UserService, { provide: getRepositoryToken(UserEntity), useValue: repository }],
	}).compile();

	app = moduleReference.createNestApplication(new FastifyAdapter());
	await app.init();
});

afterAll(async () => {
	await app?.close();
});

it("starts and serves a CURSOR route without a database connection", async () => {
	const response = await app.getHttpAdapter().getInstance().inject({ method: "GET", url: "/users?limit=10" });

	expect(dataSource.isInitialized).toBe(false);
	expect(response.statusCode).toBe(200);
	expect(response.json()).toEqual({ items: [{ createdAt: "2026-01-01T00:00:00.000Z", id: USER.id }], nextCursor: null, previousCursor: null });
	expect(repository.find).toHaveBeenCalledOnce();
});
```

- The sample needs `pg` as a development dependency, because the driver loads it, and no database.
- Stub every repository method the test reaches. An unstubbed method has no connection to run on and fails.
- `dataSource.isInitialized` stays `false`, so skip `dataSource.destroy()`.

An object with the metadata and the manager of that DataSource is a repository too, so a test can pass only the methods it stubs:

```typescript
{ provide: getRepositoryToken(UserEntity), useValue: { find: vi.fn(), manager: dataSource.manager, metadata: dataSource.getMetadata(UserEntity) } }
```

## What Does Not Work

The items below apply to a controller with an enabled generated route. A controller whose generated routes are all disabled reads nothing through its repository, so it starts without one.

- A plain object without TypeORM metadata and a manager as the repository, such as `{ provide: getRepositoryToken(UserEntity), useValue: { findOne: vi.fn() } }`, fails at bootstrap, because the date and time filter checks and the relation load checks could not run.
- A mocked service with no repository, such as `{ provide: UserService, useValue: { get: vi.fn() } }`, fails at bootstrap too. Generated routes also accept only the methods `@ApiService` installs.
- A service double with a TypeORM repository whose `create`, `get`, `update` or `delete` is not the function `@ApiService` or the matching built-in `@ApiFunction*` decorator defines, such as `{ provide: UserService, useValue: { get: vi.fn(), repository } }`, fails at bootstrap for every enabled route that calls that function: `POST` calls `create` and `get`, `PUT` and `PATCH` call `update` and `get`, `GET` calls `get`, `DELETE` calls `delete`. Keep the `@ApiService` service and stub the repository.
- A repository of a DataSource that is not initialized yet fails at bootstrap with the cause. With `manualInitialization`, call `dataSource.initialize()` before `app.init()`.

The bootstrap error names the controller, the entity, and the missing part:

```text
[NestJS-Crud-Automator] Controller "UserController" of entity "UserEntity": service.repository is not a usable TypeORM repository because its metadata is not TypeORM entity metadata. In tests, use a repository of an in-memory DataSource and stub its methods: https://elsikora.com/docs/nestjs-crud-automator/guides/testing
```

The check reads TypeORM's own type markers instead of `instanceof`, so a repository built by a second installed copy of TypeORM, as a pnpm workspace or monorepo can resolve, passes, and it reads the properties instead of testing for them, so a Proxy-wrapped repository passes too.

## Request-Scoped Controllers

Nest does not run `onApplicationBootstrap` on a request-scoped controller, which includes a controller that depends on a request-scoped service, so none of the bootstrap checks run for it and the application starts. A GET_LIST route of such a controller makes the repository and CURSOR database checks when a request arrives: the request answers `500`, and the application log holds the same error that names the controller, the route, and the cause. Its other generated routes are not checked.

## Migration Notes

Before 5.0.0, a controller started with any `service.repository`, so a plain-object repository mock was enough for a controller test. From 5.0.0 a singleton `@ApiController` with an enabled generated route fails at application bootstrap unless `service.repository` is a TypeORM repository, whichever of the decorated class and the class the decorator returns is registered. A controller whose generated routes are all disabled is not refused. Replace a repository or service mock with the [repository of an in-memory DataSource](#repository-of-an-in-memory-datasource); for an entity with PostgreSQL column types or a CURSOR route, use a [PostgreSQL DataSource without a connection](#postgresql-typed-entities-without-a-connection) or [with one](#cursor-controllers).
